# 哈希表原地扩容设计

## 目标

修改 `expand()`，使哈希表对象本身的地址保持不变。扩容时只替换
`h->data` 和 `h->size`，迁移已有链表节点，并释放旧桶数组。

## 设计

`expand()` 返回 `bool`：

- 参数或容量无效、容量翻倍溢出、桶数组分配失败时返回 `false`，原表保持不变。
- 分配并初始化两倍大小的新桶数组。
- 遍历 `old_size` 个旧桶，将每个原节点摘下，按新容量重新计算下标，再链接到新桶。
- 节点和字符串不重新分配，`h->cnt` 保持不变。
- 全部迁移完成后释放旧桶数组，更新 `h->data` 和 `h->size`，返回 `true`。

`insert()` 在达到扩容阈值时调用 `expand(h)`；扩容失败则返回 `false`，
成功后继续插入新节点。

## 内存所有权

扩容期间，新桶数组仅拥有重新链接后的原节点。旧桶数组只包含哨兵节点，
因此迁移完成后直接释放旧数组，不调用 `clear_hash_table()`，避免释放已经迁移的节点。

## 验证

测试覆盖：

1. 第一次扩容后，哈希表对象地址不变、桶数组地址改变、容量翻倍。
2. `cnt` 在扩容迁移期间不变，触发插入后只增加一次。
3. 扩容前的所有元素和触发扩容的新元素均可查找。
4. 连续两次扩容后仍满足上述条件。
5. 清理哈希表后程序正常退出。

修改范围仅限扩容所需的 `expand()` 与 `insert()` 调用逻辑；不处理其他既有问题。
