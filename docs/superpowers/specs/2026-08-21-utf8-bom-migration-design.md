# 项目文本文件 UTF-8 BOM 统一设计

## 目标

将 `D:\code\data structure and algorithm` 中由项目维护的文本文件统一保存为 UTF-8 with BOM，并配置 VS Code 今后默认使用 UTF-8 BOM 打开和保存文件。转换必须保留现有中文、英文、换行符和其他文本内容。

## 范围

- 转换项目根目录下除 `.git/` 与 `.build/` 以外的全部文本文件。
- 当前盘点得到 294 个文本候选文件；设计文档和后续新增的编码配置文件也纳入最终转换清单。
- 包含 C、C++、Python、Markdown、JSON、YAML、`.gitignore` 以及其他能够严格解码的项目文本文件。
- 不转换 `.git/` 内部数据、`.build/` 构建产物、可执行文件、目标文件、图片或其他二进制文件。

## 转换方法

转换分为预检和写入两个阶段：

1. 枚举范围内的全部文件，拒绝包含 NUL 字节的二进制候选文件。
2. 根据原始字节严格解码：已有 UTF-8 BOM 文件按 UTF-8 解码；合法 UTF-8 或纯 ASCII 文件按 UTF-8 解码；其余文件按 Windows CP936 严格解码。
3. 若任一文件无法严格解码，则在写入任何文件前停止并报告该文件，避免部分转换。
4. 在 `D:\codex` 创建带时间戳的转换前 ZIP 备份，备份范围与转换范围一致。
5. 将预检得到的 Unicode 文本写回为 UTF-8 with BOM，不改变解码后的字符序列和原有换行符。

## 持久化配置

在项目根目录创建 `.editorconfig`，仅设置根配置和 `charset = utf-8-bom`，不改变缩进、换行风格或其他格式。

更新 `.vscode/settings.json`：

- 设置 `"files.encoding": "utf8bom"`，使 VS Code 默认按 UTF-8 BOM 保存文件。
- 设置 `"files.autoGuessEncoding": false`，避免已经统一后的文件再次被猜测为其他编码。
- 保留现有编译器、终端和编辑器设置。

## 安全性与验证

转换前记录每个文本文件解码后的字符内容摘要，并记录 `.build/` 中现有文件的哈希。转换后执行以下检查：

1. 范围内所有文本文件均以字节 `EF BB BF` 开头。
2. 所有文本文件均可由严格 UTF-8 解码器读取。
3. 每个旧文件去除 BOM 后的 Unicode 字符内容与转换前完全一致。
4. 中文文件不包含新增的替换字符 `U+FFFD`，并抽查原 CP936 文件与原 UTF-8 文件的中文。
5. `.build/` 文件数量和哈希保持不变。
6. `.vscode/settings.json` 仍可按 JSON with Comments 配置读取，并包含新的编码设置。

如果任一验证失败，停止后续操作，保留转换前 ZIP 备份并报告具体文件，不声称迁移完成。

## 预期结果

迁移完成后，项目维护的文本文件只有 UTF-8 with BOM 一种编码。VS Code 新建、打开和保存文件时沿用同一编码，不再因旧 CP936 文件与 UTF-8 读取方式混用而出现中文乱码。
