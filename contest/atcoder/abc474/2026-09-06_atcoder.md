## A、B：枚举与固定分组

A 从 1、2、3 中输出一个不等于输入值的数，直接枚举即可。

[B 的退场规则](https://atcoder.jp/contests/abc474/tasks/abc474_b)是按座位编号每十人一组，组间顺序固定，组内顺序任意。当前实现每次取出退场序列中连续的十个数，排序后与对应编号段比较；最后一组不足十人，就把右端点截到 `n-1`。分组大小固定，整个检查的时间是 $O(n)$。

## C Remove and Append：只保留最后一次被移到末尾的时间

题目反复执行“删除指定值，再把它追加到末尾”。如果直接在列表中查找和删除，每次都可能移动大量元素，最坏会到 $O(NQ)$。

回看当前实现，我把最终序列分成两部分：从未操作过的数留在前面，保留原有相对顺序；被操作过的数排在后面，按各自最后一次操作的时间从早到晚排列。

某个数早先被移到哪里，只要后来又被移到末尾，那次旧操作就不再决定它的最终位置。源码因此倒序扫描操作序列：

```python
seen = [False] * (n + 1)
tail = []

# 找到每个数的最后一次操作，得到从晚到早的顺序
for x in reversed(ops):
    if not seen[x]:
        seen[x] = True
        tail.append(x)

# 没被操作过的数，保留原来的相对顺序
ans = [x for x in arr if not seen[x]]

# 被操作过的数，按最后操作时间从早到晚放到末尾
ans.extend(reversed(tail))
```

倒着第一次遇到一个值，就是它在正序中的最后一次操作。`tail` 记录的是从晚到早的顺序，输出前再反转。过滤原数组时使用的是同一份 `seen`，所以前后两部分不会重复，也不会漏数。

例如原排列是 `2 4 3 1`，操作依次为 `3、2`：没有动过的 `4、1` 保留在前面，后面接上按最后操作时间排列的 `3、2`，得到 `4 1 3 2`。

时间复杂度为 $O(N+Q)$，当前实现保存了操作列表，空间也是 $O(N+Q)$。这里值得记住的是：题目只问最终顺序时，可以先检查较早的操作是否会被后来的同类操作覆盖。

## D Outweigh：先找正差值，再证明它能压过其他项

需要构造正整数权重，使两个人的总重量满足严格大小关系。把两边移到一起，就是：

$$
\sum_{i=1}^{N}(A_i-B_i)W_i>0。
$$

如果所有 $A_i-B_i\le0$，无论怎样选择正权重都不可能得到正数。只要存在一个正差值，就可以让其他权重为 1，再把这个位置的权重放大。

当前源码中的 `maximum` 是两组数量的最大值，构造部分如下：

```python
index = -1
ans = [1]*n
for i in range(n):
    if(arr1[i] <= arr2[i]):
        continue
    index = i

if(index == -1):
    print("No")
else:
    print("Yes")
    ans[index] = maximum*n*100
    print(*ans)
```

我在整理时把这个“大权重”具体检查了一遍。记 $M=\max(A_i,B_i)$，选中的正差值至少为 1，它贡献至少 $100nM$；其余项的负贡献绝对值总和小于 $nM$，因此一定能保证总差值为正。

题目中 $n\le10^5$、$M\le10^9$，构造的最大权重不超过 $10^{16}$，也在 $10^{18}$ 的限制内。扫描与输出都是 $O(n)$，当前数组存储为 $O(n)$ 空间。

这段代码里的 100 留出了很大余量。复盘时更需要保留的是它为什么够大、为什么又没有超过上界，之后遇到类似构造就可以重新算出所需范围。

## E One-Time Coupon：一次原价购买让券的缺口减少 2

每种商品至少买一次。原价购买第 $i$ 种商品花 $A_i$，获得一张券；用券购买花 $B_i$，消耗一张券。允许重复购买，所以还可以重复原价购买便宜商品来拿券。

当前实现先记下三个量：

- `base = sum(B_i)`：假设每种商品都按用券价格购买的费用基准。
- `diff[i] = A_i - B_i`：把某种商品的一次购买从用券改成原价，需要多花的钱。
- `cost = min(A_i)`：额外原价购买一次商品、获得一张券的最低成本。

如果有 $k$ 种商品选择原价购买，这些购买会产生 $k$ 张券，剩下 $n-k$ 种商品需要用券，因此还缺：

$$
\max(0,(n-k)-k)=\max(0,n-2k)
$$

张券。这里的 $2k$ 很容易少算一半：一种商品改成原价后，既少用了一张券，又多获得了一张券。

固定 $k$ 后，产生和消耗多少张券已经确定。费用上的区别只剩选哪些商品原价购买，因此选择差价最小的 $k$ 种，排序后用前缀和维护：

```python
    diff.sort()
    # k = 0：额外买 n 张券，每种商品都用券购买
    ans = base + n * cost
    prefix = 0

    for k in range(1, n + 1):
        # 选择差价最小的 k 种商品原价购买
        prefix += diff[k - 1]
        # 还需要额外获取的优惠券数量
        missing = max(0, n - 2 * k)
        total = base + prefix + missing * cost
        ans = min(ans, total)
    return ans
```

额外获取优惠券，就是重复原价购买价格为 `cost` 的商品。公式中仍然给每种商品保留了一次指定的购买，多买同一种商品是允许的。实施时先完成所有原价购买，再进行用券购买，就能保证最初没有券也不会卡住。

反过来看任意一种购买方案，可以为每种商品选出一次代表它已被买到的购买。设其中有 $k$ 次原价购买，那么另外 $n-k$ 次要用券；除这 $k$ 次以外，至少还要有 $\max(0,n-2k)$ 次原价购买补足券数。每次额外原价购买至少花 `cost`，而被选中的 $k$ 种商品的差价和也不会小于排序后的前 $k$ 项。这样，枚举式既能构造出实际方案，也能给出相应的费用下界。

用源码附带的第一个样例核对：`base=19`，最低原价是 2，排序后的差价为 `1、1、3、5、5`。取 $k=2$ 时，额外差价为 2，还缺一张券，总费用为 $19+2+2=23$。

差价排序需要 $O(n\log n)$，之后的枚举为 $O(n)$，空间为 $O(n)$。我想把这题的推导记成“先固定原价购买的种类数，再算券的收支”：数量固定以后，选差价最小的那几种才有明确依据。
