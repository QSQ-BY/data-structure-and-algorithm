# 2026-07-30_cf：第一次参加 Codeforces

## 第一次参加 Codeforces Round 1109（Div. 3）

今天也算正式向算法竞赛迈出了第一步。我挑了难度不算高的 Codeforces Round 1109（Div. 3）进行 virtual participation，第一次完整感受限时读题、实现、提交和调试的节奏。

规定时间内，我只完成了 A、B 两题。C 的思路从一开始就走偏了：我试图模拟若干次交换，却没有把“哪些位置可以互相到达”看成连通性问题。可能也和当前进度有关，我还没有系统学到连通块与并查集。赛后看完题解，才知道这题最终可以落到 `gcd(x,y)` 划分的位置同余类上。我随后把判断改成了：

```cpp
string f(const vector<int>& arr, int x, int y){
    int g = gcd(x, y);
    for (int i = 0; i < (int)arr.size(); i++){
        if (arr[i] % g != (i + 1) % g)
            return "NO";
    }
    return "YES";
}
```

值 `arr[i]` 最终要回到第 `arr[i]` 个位置，只要当前位置 `i+1` 和目标位置模 `g` 不同，它就不可能通过距离为 `x` 或 `y` 的交换到达。代码并不长，真正缺的是比赛中把操作抽象成连通块的那一步。

D 在比赛末尾只来得及扫一眼，赛后再看时，排序翻转端点、把数组切成若干段，再让每一段独立选择正负的思路很快就明白了。以我现在掌握的排序和前缀和，它并没有超出我的能力范围；现场没做到它，主要还是因为 A、B 消耗了太多时间。

这点让我有些挫败。A、B 的思路都出来得很快，但代码实现时不够利落，频繁回头检查小问题，还保留了先存下全部测试数据、再统一处理之类不够适合比赛的写法。单看每一个问题都不严重，放进计时环境里却不断切碎时间，最后根本没有给后面的题留下完整的思考窗口。

第一次比赛只做出两题，和学了这么久数据结构与算法形成的心理预期有些落差。不过回头看，这次至少让我分清了两件事：会实现已经学过的数据结构，不等于能在陌生题面里迅速找到模型；赛后能够看懂 C、D，也不等于比赛现场已经具备发现它们的速度。

以后我准备每周至少参加一次 Codeforces，正式比赛或 virtual 都可以。每次比赛的过程也会继续用键盘记录下来，单独放进已经建好的 `codeforces` 目录。下一场先不急着追求题数，我更想把 A、B 的实现压缩得干净一些，给第三题第四题留下真正完整的时间。
