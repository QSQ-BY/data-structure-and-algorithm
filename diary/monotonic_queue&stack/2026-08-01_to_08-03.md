# 2026-08-01 至 08-03：从最近元素到窗口最值

8 月 1 日开始学习单调栈和单调队列，昨天浅浅休息了一天，今天继续把重心放在相关练习上，一共做了五道题。两天的内容连起来看，反而更容易抓住这两个结构各自维护的东西：单调栈找的是距离当前元素最近的、更大或更小的元素；单调队列维护的则是一个滑动窗口里的最大值或最小值。

它们和之前学过的堆有些相似，都是为了从一组数据中快速拿到某种特殊值。不过单调栈和单调队列更依赖元素原本的线性顺序。想清楚题目究竟在问“最近的大小关系”，还是“一个固定范围内的最值”，基本就能判断该往哪个方向走。

## 单调栈：新元素入栈时，旧元素的答案也随之确定

单调栈的底层实现并不复杂。每次加入新元素时，把它和栈顶比较；只要栈顶破坏了需要维护的单调性，就不断弹出。弹出并不只是删除，很多时候也意味着这个旧元素终于遇到了离它最近、满足大小关系的新元素。

我在基础实现里用 `l` 和 `r` 两个数组，分别记录每个元素左侧和右侧最近的较小元素。下面这段从左向右扫描，负责确定右侧关系：

```cpp
stack<int> s;
vector<int> l(arr.size()+1);//每个元素左侧最近的比它小的元素
vector<int> r(arr.size()+1);//每个元素右侧最近的比它小的元素

for(int i=0;i<arr.size();i++){
    while(!s.empty() and arr[s.top()] > arr[i]){
        r[s.top()] = i;
        s.pop();
    }
    s.push(i);
}
```

栈中保存的是下标，而不是元素本身。新来的 `arr[i]` 如果更小，就会依次成为若干栈顶元素右侧第一个更小的数；再从右向左做一次同样的扫描，就能填好 `l`。每个下标最多入栈、出栈一次，所以整次处理是 `O(n)`，并不是看上去的双重循环 `O(n²)`。

现在我更愿意把单调栈理解成一个“尚未找到答案的下标集合”。栈里的元素还在等待，而一个合适的新元素出现时，就会一次解决掉其中的一部分。

## 单调队列：除了维护单调性，还要管窗口边界

单调队列同样会在尾部比较新元素并不断弹出，但它比单调栈多了一件事：队头可能已经离开当前窗口，需要根据窗口大小及时出队。

以维护滑动窗口最小值为例，队尾负责维持单调性，队头负责处理窗口边界。因为队列中的下标对应值始终单调递增，`q.front()` 就是当前窗口的最小值；如果要维护最大值，只要把比较方向反过来。

这也是单调栈和单调队列最直接的区别。单调栈只关心新元素与栈顶的大小关系，不需要处理队头；单调队列既要从尾部维护大小关系，也要从头部淘汰已经过期的下标。两者都不难写，真正容易混乱的是每一步操作对应的含义。

## 从窗口最值走到限制长度的最大子序列和

今天做的最大子序列和让我看到，单调队列并不只会直接维护原数组的最值。题目要求找到一段长度不超过 `m` 的连续子序列，使它的和最大。把区间和写成前缀和之差后，问题就变成：对于当前右端点 `i`，在合法范围内寻找最小的 `prefix[j]`。

```cpp
deque<int> q;
q.push_back(0);
int ans = INT_MIN;
for(int i=1;i<n+1;i++){
    while(!q.empty() and i-q.front() > m) q.pop_front();
    ans = max(ans,prefix[i] - prefix[q.front()]);
    while(!q.empty() and prefix[q.back()] > prefix[i]) q.pop_back();
    q.push_back(i);
}
```

这里维护的窗口不再是原数组的元素，而是一组合法的前缀和下标。队头始终对应窗口中的最小前缀和，用当前前缀和减去它，就能得到以 `i` 为右端点的最大合法区间和。窗口范围与单调性必须同时成立，少处理其中任何一个，得到的区间都可能超出长度限制。

这道题把我对单调队列的理解又往前推了一步：先别急着问“原数组的最大值在哪里”，而要先判断公式中究竟是哪一部分需要在一个变化的范围内取最值。只要这个范围会随着遍历一起滑动，就有可能交给单调队列维护。

## 五道练习，把窗口从定长推到变长

今天的五道题里，前四道都和单调队列有关。第一题是最标准的定长滑动窗口，同时维护每个窗口的最大值和最小值；第二题就是上面的限制长度最大子序列和，用单调队列维护合法范围内的最小前缀和；第三题则把普通队列和单调队列放在一起，既保留正常的先进先出顺序，又让 `get_max()` 能在均摊 `O(1)` 时间里拿到最大值。

第四题更特殊。它要求连续子数组中的最大值与最小值之差不能超过 `limit`，所以我需要同时维护两个单调队列：`min_q` 保存窗口最小值，`max_q` 保存窗口最大值。它也不再给出一个固定窗口长度，而是让右端点不断向右移动；一旦最大值与最小值之差越界，左端点就跟着收缩，直到窗口重新合法。

```cpp
deque<int> min_q;//维护滑动窗口内的最小值
deque<int> max_q;//维护滑动窗口内的最大值
int l = 0;
// ...
for(int r = 1;r<nums.size();r++){
    // ... 更新两个单调队列
    while(nums[max_q.front()] - nums[min_q.front()] > limit){
        if(min_q.front() == l) min_q.pop_front();
        if(max_q.front() == l) max_q.pop_front();
        l++;
    }
    ans = max(ans,r-l+1);
}
```

这里没有一个预先写死的 `k`。右端点负责把新元素纳入考虑，两个队头随时给出当前区间的最大值和最小值，左端点只在区间不合法时前进。这个过程让我意识到，滑动窗口并不等于“固定长度窗口”；只要左右边界沿同一方向移动，并且中间状态能够被快速维护，窗口就可以随着条件变化。

最后一题是最大面积矩形，也是今天唯一一道单调栈题。我觉得它真正难的地方并不在单调栈，而在于怎样把面积问题抽象成“最近的更小元素”。任何一个候选矩形的高度都会受到某根柱子的限制。把第 `i` 根柱子的高度作为矩形高度，向左右延伸到第一根比它矮的柱子，能够得到的宽度就是 `r[i] - l[i] - 1`，面积则是 `height[i] * (r[i] - l[i] - 1)`。

想清楚这一层以后，前面练过的 `l`、`r` 数组正好可以直接接上。单调栈只负责一次性找出每根柱子左右最近的更小值，遍历所有柱子计算面积，再取最大值。原本看起来像一道几何题，最后落回了熟悉的大小关系；真正费力的是完成这次转化，模型一旦确定，代码也就水到渠成了。

## 今天留下的几个判断

这两天学下来，我想先记住三类判断：最近的大于或小于关系可以考虑单调栈；连续区间里反复变化的最值可以考虑单调队列；大量按值查询的问题，则要先想哈希表能不能直接建立映射。窗口可以定长，也可以根据约束伸缩；哈希表里保存的内容也不只有“是否存在”，还可能是出现次数或原始位置。
