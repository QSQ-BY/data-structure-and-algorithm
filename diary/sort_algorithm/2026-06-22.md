## 无监督插入排序

后面跟着老师优化了插入排序。普通插入排序里，内层循环要同时判断两件事：

```cpp
while(j > l and arr[j] < arr[j - 1]){
    swap(&arr[j], &arr[j - 1]);
    j--;
}
```

`j > l` 是边界，`arr[j] < arr[j - 1]` 才是排序逻辑。无监督插入排序的想法，是先把整个区间里的最小值放到最左边，让它充当哨兵。这样后面元素往前移动时，一定会在最小值那里停住，内层循环就可以去掉 `j > l` 这一层判断：

```cpp
while(arr[j] < arr[j - 1]){
    swap(&arr[j], &arr[j - 1]);
    j--;
}
```

这个优化挺小，但它把一个很重要的思路摆出来了：有时候算法优化不是换一个大框架，而是先调整数据状态，让循环条件变简单。最小值被放到最前面以后，边界不再靠条件语句保护，而是靠数据本身保护。

不过我也不能把这个优化想得太神。现在的写法仍然用相邻交换来搬元素，真正耗时的部分没有消失。它减少的是一次判断，不是把插入排序从平方级变成更低复杂度，也没有减少反复交换的操作。这个区别要分清楚。之前我已经注意到，选择排序虽然比较多，但交换少；插入排序如果一直用 `swap` 往前挪，内存写入会比较重。无监督版本让内层循环更干净，但它还没有解决“相邻交换成本高”这个问题。

## 从堆走到排序

重写完生日礼物这道题以后，堆与优先队列这一章就算正式结束了。回头看这一章，前面是手写堆、建堆、堆排序和哈夫曼编码，后面一路写到数据流、合并链表、序列 m 小和、超市利润和生日礼物。最开始我把堆理解成“能快速取最小值或最大值的结构”，现在会多想一层：它经常是在维护一个会不断变化的候选集合。

生日礼物正好是这一章的最后一道硬题。它把 `set`、贪心、删除标记和模拟链表揉在一起，难度不只是容器用法，而是状态同步。用它收尾，有点累，但也合适。

接下来就全身心投入排序算法。排序看起来比生日礼物朴素得多，可它里面的问题一点也不少：稳定性、原地性、比较次数、交换次数、最好和最坏情况，以及不同数据分布下的实际表现。今天从插入排序的优化开始，算是把注意力从“动态维护候选”挪到了“怎样让一段区间逐步有序”。下一步，我想继续把基础排序一个个写扎实，不只记模板，也要把每一轮循环结束后数组处在什么状态说清楚。
