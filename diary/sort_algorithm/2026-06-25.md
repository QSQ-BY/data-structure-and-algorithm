# 2026-06-25：快速排序，把基准值放回正确位置

今天学习了快速排序。

前几天写的选择排序、插入排序、希尔排序和冒泡排序，都是让数组一点点接近有序。快速排序的思路不太一样：先选出一个基准值，通过一次分区把它放到最终位置，再用同样的方法处理左右两边。

## 分区过程

这次写的是左右指针配合“挖坑填数”的版本。函数处理的仍然是左闭右开的区间 `[l, r)`，先把最左边的元素保存为 `base_number`。基准值被单独保存以后，`left_index` 所在的位置就可以看成一个空位。

接下来从右边开始找比基准值小的元素，把它放进左边的空位；左边向前移动后，空位转移到了右边。然后再从左边找比基准值大的元素，填进右边的空位。两个指针这样交替靠近，直到在同一个位置相遇，最后再把基准值放进去。

```cpp
while(left_index != right_index){
    while(left_index < right_index && base_number <= arr[right_index]){
        right_index--;
    }
    if(left_index < right_index){
        arr[left_index] = arr[right_index];
        left_index++;
    }

    while(left_index < right_index && base_number >= arr[left_index]){
        left_index++;
    }
    if(left_index < right_index){
        arr[right_index] = arr[left_index];
        right_index--;
    }
}
arr[left_index] = base_number;
```

这里从右边先找不是随便规定的。因为最开始保存的是左端点的基准值，第一个空位就在左边，所以要先从右侧找到一个更小的数来填。之后空位在左右两边来回转移，分区过程才不会覆盖还没处理的数据。

一次分区结束后，基准值左边的元素都不大于它，右边的元素都不小于它。此时基准值已经落在排序完成后的最终位置，不需要再参与递归。因此后面的区间分别是 `[l, left_index)` 和 `[left_index + 1, r)`：

```cpp
quick_sort(arr, l, left_index);
quick_sort(arr, left_index + 1, r);
```

快速排序的代码不长，真正容易绕的是每次赋值以后“空位在哪里”，以及递归时该不该把基准值算进去。把这两件事想清楚以后，整个过程就顺了很多。

## 测试和下一步

代码保留了 5,000 个和 1,000,000 个随机数两组测试。在当前环境重新编译运行后，两组数据都通过了有序性检查，百万规模的随机数据耗时约 115 ms。这个数字只代表这次运行环境，不过和前几种平方级排序相比，规模上的差距已经很直观。

目前的版本固定选择区间第一个元素作为基准值。写完基础版本以后，我也能看出它留下的问题：如果基准值总是落在很偏的位置，左右区间会严重不均衡，快速排序就可能退化。

明天打算继续学习快速排序的四种优化方法。我想先盯住一个问题：每种优化到底是在改进基准值的选择、分区过程，还是递归带来的额外开销。先把这个对应关系理清楚，再记具体写法，应该会比直接背四份代码更牢。
