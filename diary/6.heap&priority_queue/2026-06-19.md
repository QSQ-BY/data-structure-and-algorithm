昨天我把序列 m 小和重新写了一遍。那道题的核心已经从“照着写一个 `set`”慢慢变成了“每一轮只保留当前最小的前 `m` 个候选”。今天接着往后走，难度一下又抬上去了：HZOJ 第 289 题，生日礼物。

## 生日礼物：先把题目从“选区间”变成“删代价”

这道题要求在一个序列里最多选 `M` 个连续部分，让总和最大。题面看起来是在选区间，但真正难的地方不是“怎么找一个最大子段和”，而是“最多可以选多个连续部分”。一个连续部分内部可以跨过负数，只要跨过去以后能把两边更大的正数收益连起来；一个正数段也不一定必须留下，如果它很小，删掉它可能比保留一次选择次数更划算。

我一开始看这题时，最容易下意识想到的做法是：正数就要，负数就不要。这个想法只对一半。正数段当然提供收益，但如果所有正数段都单独选，选择次数可能超过 `M`；负数段虽然会扣分，却可能把两个正数段接成一个连续部分，让原来需要两次选择的东西变成一次选择。也就是说，这题不是简单地挑正数，而是在正数段数量和总收益之间做交换。

所以第一步不是急着上 `set`，而是先把原数组压缩成正负交替的段。

```cpp
if(__arr[i]>=0){
    while(i<n and __arr[i]>=0){
        number+=__arr[i];
        i++;
    }
    arr.push_back(number);
}else if(__arr[i] < 0){
    while(i<n and __arr[i]<0){
        number+=__arr[i];
        i++;
    }
    arr.push_back(number);
}
```

这一步做完以后，原来的每一个元素就不再重要了。真正重要的是一段连续正数总共能带来多少收益，一段连续负数要付出多少连接代价。比如原序列里一长串正数，既然中间没有负数隔开，就没有必要拆成很多个点来看；它天然属于同一个连续部分。

后面还有一个 `clean`，把 0 去掉，并且把同号的相邻段重新合并。我觉得这一步很像在整理题目的状态空间：先把会干扰判断的零清掉，再保证压缩后的数组尽量保持正负交替。这样后面的 `cnt` 才有明确含义：当前有多少个正数段。

## 先全选正数段，再一步步减少选择次数

压缩之后，思路就清楚了一点。假设我不受 `M` 限制，那最优答案一定是把所有正数段都选上。代码里的 `pos_sum` 就是这个初始答案：

```cpp
if(array[i] > 0){
    pos_sum += array[i];
}
```

同时，`cnt` 记录正数段个数。如果 `cnt == 0`，说明整个序列没有正收益，答案就是 0；如果 `cnt <= m`，说明选择次数够用，直接把所有正数段加起来就行。真正复杂的情况只剩下一个：`cnt > m`。

这个时候就不能全选了，必须把正数段数量从 `cnt` 降到 `m`。每降一次，都会损失一些收益。题目的关键就变成了：每次用最小的代价，让正数段数量减少一。

这里有两种减少方式。

第一种是删掉一个正数段。比如某个正数段只有 `2`，我放弃它，答案少 `2`，正数段数量也少一。第二种是跨过一个负数段，把左右两个正数段合并。比如 `5, -1, 6`，如果我愿意承受 `-1` 这个代价，就可以把两个正数段合成一个连续部分，正数段数量也少一，答案只少 `1`。

这样一看，为什么要找绝对值最小的段就比较自然了：  
如果当前最小绝对值的是正数段，删掉它损失最小；如果当前最小绝对值的是夹在两边中间的负数段，跨过它付出的代价最小。每做一次这样的操作，选择次数就少一，而且尽量少损失答案。

今天这道题让我卡住的地方就在这里。它不像普通堆题那样，堆顶就是答案的一部分；这里的堆顶更像“下一次修改结构的最低代价”。拿到这个代价以后，还要更新相邻段，原来的局面就变了。

## `set` 管代价，模拟链表管相邻关系

代码里用的是：

```cpp
set<PII> s;
```

`first` 存当前段的绝对值，`second` 存它在数组里的位置。这样 `s.begin()` 就能拿到当前绝对值最小的段。只用绝对值还不够，因为会有多个段的绝对值一样，第二维下标可以把它们区分开。

但光有 `set` 还不够。因为每次选中一段以后，可能要把它和左右两段合并。合并之后，左右两个旧段已经不存在了，中间这个位置变成一个新段。数组本身不好真的删除元素，所以代码用了 `l` 和 `r` 模拟双向链表：

```cpp
l[i] = i-1;
r[i] = i+1;
```

对当前位置 `index` 来说：

```cpp
int left = l[index];
int right = r[index];
```

这两句拿到的是当前还活着的左右邻居，而不是原数组里机械的 `index - 1` 和 `index + 1`。这个区别很重要。因为前面可能已经删过一些段了，原来的相邻关系早就不可信了，只有链表里的 `l`、`r` 还表示当前结构。

合并时，代码把左右两段的值加到 `array[index]` 上：

```cpp
if(left > 0){
    array[index] += array[left];
}
if(right <= n){
    array[index] += array[right];
}
```

这一步一开始很容易看晕。它不是在“修改原数组”，而是在把三个相邻段压成一个新段。比如 `5, -1, 6` 选中了 `-1`，新的段就是 `5 + (-1) + 6 = 10`。这个新段仍然放在 `index` 位置，再重新插回 `set`。

如果选中的是正数段，也会做类似的结构更新。删掉这个正数段以后，它左右两边如果存在，通常是负数段，合并起来代表新的连接代价。这个地方比想象中绕，因为正数和负数两种情况在代码里用了同一套“把左右并进当前节点”的框架，只是含义不同。

## 删除标记：不是所有在 `set` 里的点都还活着

这题实现上最容易出错的地方，是 `set` 和链表状态并不是天然同步的。

当一个节点被合并掉以后，代码没有立刻从 `set` 里精准删掉它的所有旧记录，而是用 `st` 做删除标记：

```cpp
vector<int> st(array.size()+5);
```

每次从 `set` 取候选前，先跳过已经失效的点：

```cpp
while(st[s.begin()->second] == 1) s.erase(s.begin());
```

这个写法有点像“懒删除”。旧节点可能还躺在 `set` 里，但只要它被标记成删除，真正轮到它被取出来时再扔掉就行。这样不用在合并时到处找旧记录，逻辑会简单一些。

合并左右节点时，还要把它们从链表里摘掉：

```cpp
r[l[left]] = r[left];
l[r[left]] = l[left];
```

右边节点也是同理。这里我最需要盯住的是：`st` 负责告诉 `set` 哪些点已经失效，`l`、`r` 负责维护当前还活着的相邻关系。它们不是一回事。如果只打删除标记，不改链表，下一次找左右邻居会错；如果只改链表，不打删除标记，`set` 里失效节点又可能被拿出来。

这也是今天代码实现上最重的地方。前几天写堆的时候，很多题只是插入、取最小、删除最小；这道题每取一次最小，还要把整条结构重新接起来。它考的不是容器语法，而是多个状态之间有没有同步。

## 我今天真正绕住的点

这道题我觉得难，是因为它有两层转换。

第一层是题意转换：从“最多选 `M` 个连续部分”，转成“先全选正数段，再用最小代价把正数段数量降到 `M`”。这一步不想明白，就会一直在原数组上找区间，思路很散。

第二层是代码转换：从“选一个最小代价”，转成“在 `set` 里取最小绝对值，在链表里找到它的左右邻居，合并后插回新段，同时标记旧节点失效”。这一步不想明白，代码就会变成一堆数组下标，`l`、`r`、`st`、`array[index]` 看起来都像是在乱改。

现在回头看，生日礼物和序列 m 小和有一点相似：它们都不是单纯求一个静态最值，而是在维护候选集合。序列 m 小和维护的是“当前最小的前 `m` 个部分和”；生日礼物维护的是“下一次减少选择次数时最便宜的结构修改”。差别在于，生日礼物每次修改以后，邻接关系会跟着变化，所以它还多了一层模拟链表。

这个题今天算是把我按住了。算法思想本身已经不轻，落到实现时又要同时盯住 `cnt`、`pos_sum`、`set`、删除标记和左右指针。写完以后，我没有那种“这题终于轻松拿下”的感觉，更多是觉得自己刚刚把一团很硬的东西啃开了一个口子。后面如果要真正把它变成熟练题，还得再单独回来看一遍，尤其是“取最小代价之后，链表到底怎么接回去”这一段。

写完生日礼物以后，今天最后的时间又往下一章推了一点，开始排序算法。先写的是选择排序。和生日礼物放在同一天看，选择排序简直显得眉清目秀：每一轮从待排序区间里找出最小值，把它换到最前面，待排序区间往后缩一格。它当然不高效，复杂度是 `O(n^2)`，但作为排序章节的开头很合适，因为它把“有序区”和“待排序区”这两个概念摆得很直。

后面还会接触很多排序算法。选择排序只是开门，后面还有插入、冒泡、归并、快速排序等等，以及更多和稳定性、复杂度、原地性有关的细节。今天先把门推开一点。期末前能不能把排序算法这一章结束还不好说，但接下来这段时间的目标很明确：每学一个排序，都要把它的区间含义、循环不变量和适用场景说清楚，而不是只背一段模板。
