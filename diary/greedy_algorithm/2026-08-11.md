## 洛谷日练：一道熟悉的二分，一道没能独立做出的 DFS

第一题是 P2440「木材加工」。给定若干根原木，要切出至少 `k` 段等长木料，并让这个长度尽可能大。固定一个长度 `len` 后，只要统计所有 `arr[i] / len` 的和，就能判断它是否可行；长度越大，能切出的段数越少，答案具有很明显的单调性。

这就是很标准的二分答案：写出 `check(len)`，再寻找最大的可行长度。题型和流程都很熟悉，今天做起来没有什么波折，也就不再展开了。

第二题 P2036「Perket」是一道很经典的 DFS。每种食材有选和不选两种状态，要枚举所有非空组合，再比较酸度乘积与苦度总和的差。DFS 一直不是我掌握得很稳的部分，今天最后还是没能靠自己把整道题完整做出来。

不过这次也不是毫无收获。我又练了一遍用二进制掩码表示集合：第 `i` 位为 `1`，表示第 `i` 种食材已经选入；为 `0`，表示没有选。代码从全为 `1` 的状态出发，每次删掉当前集合中的一种食材：

```cpp
void dfs(int t) {
    // 不计算空集；已经计算过的状态不用重复搜索
    if (t == 0 or dp[t] != INT_MAX) return;
    // calculate_result 会同时把结果保存到 dp[t]
    ans = min(ans, calculate_result(t));
    // 尝试删除当前集合中的每一种食材
    for (int temp = t; temp != 0; temp -= (temp & -temp)) {
        int bit = temp & -temp;
        dfs(t ^ bit);
    }
}
```

`temp & -temp` 取出最低位的 `1`，`t ^ bit` 再把这一位清零。这样从 `(1 << n) - 1` 开始，就能逐步到达所有非空子集。以前我使用掩码时更容易把它看成一个整数，今天对照 DFS 的状态变化后，它更像一张随搜索不断修改的“食材使用表”。题目没有独立做出来，至少掩码、`lowbit` 和集合状态之间的关系又清楚了一些。

## 最大子阵和：先压成一维，再解决熟悉的问题

主线第一题是最大子阵和。直接枚举一个子矩阵需要确定上下左右四条边，做法很直观，但枚举量和求和过程都会变得麻烦。这里的转换是先枚举起始行与终止行，把这两行之间每一列的元素压缩成一个数。此时，二维矩阵的一条横向区域就变成了一维数组，问题也随之变成最大子段和。

```cpp
for(int i=1;i<=n;i++){
    for(int j=i;j<=n;j++){
        int s = 0;
        for(int k=1;k<=n;k++){
            //得到这一个区间内第k列的值
            int a = arr[j][k] - arr[i-1][k];
            if(s>=0) s+=a;
            else s = a;
            ans = max(ans,s);
        }
    }
}
```

读入时已经按列求好了纵向前缀和，因此 `arr[j][k] - arr[i-1][k]` 能直接得到第 `k` 列在第 `i` 行到第 `j` 行之间的总和。随后只需线性扫描这些列：前面的累加和为负，就从当前列重新开始；否则继续累加。枚举行区间需要 `O(n²)`，每个区间扫描 `n` 列，总时间复杂度是 `O(n³)`。

这道题我最大的收获有两层。第一层是把二维问题压成一维问题；第二层是最大子段和本身的写法。和之前比较直观、但写起来复杂的双指针思路相比，这种“负数就舍弃，否则继续积累”的处理短得多，也更贴合子段和真正需要维护的状态。

## 从 `a` 到 `b`：把操作过程倒过来看

下一题给出 `a`、`b` 和 `k`，每次可以把当前数字加一或乘以 `k`，要求从 `a` 变成 `b` 的最少操作次数。题面看上去很简单，真正的解法却很难直接想到。

顺着 `a` 往上走时，每一步都要决定加一还是乘 `k`，分支很难判断；倒过来从 `b` 看，结构就清楚了。`b % k` 是为了到达上一个可整除状态必须补掉的那几次加一，而除以 `k` 则对应正向的一次乘法：

```cpp
while(1){
    if(a*k <= b){
        ans+= 1+ b%k;
        b = b/k;
    }else{
        ans+=b-a;
        break;
    }
}
```

也可以把 `a` 和 `b` 看成 `k` 进制数。乘以 `k` 相当于整体左移一位，加一负责调整低位；反向处理时，就先消掉当前最低位，再除以 `k`。这种抽象让我印象很深，因为它完全改变了观察操作序列的方向。原本像是一步步试选择的题，转成进制以后，每一轮该处理什么几乎被数位结构直接确定了。

## 安置雷达与奶牛挤奶：先把对象改写成区间

最后两道题有些相似，但都不容易从题面直接想到完整策略。

安置雷达的第一步就很难：一个坐标为 `(x,y)` 的小岛，并不是直接拿来参与贪心，而是先映射成海岸线上的一个区间

```text
[x - sqrt(d²-y²), x + sqrt(d²-y²)]
```

只要雷达落在这个区间内，就能覆盖该小岛。问题于是从二维平面上的圆形覆盖，变成了在数轴上选尽量少的点，使每个区间至少包含一个点。之后按区间右端点排序，每次把雷达放在当前最靠左的可选右端点；后续区间如果仍包含这个位置，就继续共用同一部雷达，否则再开一个新位置。无论是前面的几何映射，还是后面按右端点选择的贪心，都不是看一眼题面就能自然想到的。

奶牛挤奶同样要处理许多时间区间。按照开始时间依次安排奶牛，如果已有挤奶机在它开始前空闲，就复用编号最小的那一台；否则新增机器。它和安置雷达不完全是同一道模型，但思路确实有相通的地方：先把原对象看成区间，再围绕端点决定当前选择。即使刚做完雷达题，要独立补全机器复用、编号和原输入顺序之间的关系，还是有难度。
