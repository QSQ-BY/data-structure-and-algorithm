## 完整实现一次哈希表

哈希表这一部分，我跟着概念学完后，又自己完整写了字符串哈希表。字符串先经过哈希函数得到桶下标，发生冲突时使用拉链法，把落在同一个桶里的元素接成链表。插入、查找、输出和清理之外，我还实现了扩容。

扩容时，原来的节点不能继续留在旧位置，因为容量改变后，取模得到的桶下标也会改变。我分配了两倍大小的新桶数组，然后把旧节点逐个摘下来，按照新容量重新计算位置：

```cpp
for(int i=0;i<old_size;i++){
    node* p = old_data[i].next;
    while(p!=nullptr){
        node* next = p->next;
        int index = hash_func(p->s)%new_size;
        p->next = new_data[index].next;
        new_data[index].next = p;
        p = next;
    }
}

free(old_data);
h->data = new_data;
h->size = new_size;
```

这里没有重新复制字符串，也没有更换哈希表对象本身，只是替换了它管理的桶数组。节点迁移结束后再释放旧数组，`cnt` 仍然记录原来的元素数量。连续扩容两次后，之前插入的元素依然可以找到，这让我真正走完了一次哈希表扩容的完整过程。

## 布隆过滤器

老师今天讲了布隆过滤器的理论，但没有带着我们自己实现。它的底层是一段只记录 0 和 1 的空间，一个元素会通过多个哈希函数映射到多个位置。查询时，只要有一个位置为 0，就能确定这个元素没有出现过；如果所有位置都是 1，只能判断它大概率出现过。

我现在能理解布隆过滤器为什么会有误判，也知道增加底层数组长度可以降低误判概率，不过这种理解还停留在纸面上。哈希函数应该选几个、数组开多大、误判率怎么变化，我都没有在程序里实际观察过。后面如果遇到网页去重、黑名单或者大规模数据判重的题目，我想自己把它实现一次。

## 第一题：两数之和

进入练习阶段后做的第一题是“两数之和”。哈希表方法是一边遍历数组，一边查找当前元素需要的补数：

```cpp
unordered_map<int,int> h;
vector<int> ret(2);
for(int i=0;i<nums.size();i++){
    if(h.find(target-nums[i])!=h.end()){
        ret[0] = h[target-nums[i]];
        ret[1] = i;
        break;
    }
    else{
        h[nums[i]] = i;
    }
}
```

先查补数，再把当前元素和下标存进表中，可以避免同一个位置被使用两次。这个方法平均只需要遍历一遍数组，时间复杂度是 `O(n)`，但需要额外的 `O(n)` 空间。

二分查找的方法要绕一些。我先排序下标数组，让 `nums[index[i]]` 有序，同时保留元素在原数组中的位置。枚举一个元素后，只在它后面的区间里二分查找补数：

```cpp
while(l<=r){
    int mid = l + (r-l)/2;
    if(nums[index[mid]] == goal) {
        ret = index[mid];
        break;
    }
    if(nums[index[mid]] < goal) l = mid+1;
    else r = mid-1;
}
```

这里使用的是闭区间 `[l,r]`，所以 `l==r` 时最后一个位置也要检查。排序需要 `O(n log n)`，之后每个元素再做一次 `O(log n)` 的查找，总时间复杂度仍然是 `O(n log n)`。它没有哈希表快，但正好让我把刚学完的二分查找放进一道实际题目里。

这两种方法里，我目前更不熟悉的是 C++ 的 `unordered_map`。今天只用到了 `find`、下标访问和键值存储，对它的常用接口、遍历方式、冲突处理以及性能特点还没有形成完整认识。接下来做查找题之前，我准备先把 `unordered_map` 系统过一遍；同时留意有没有真正适合布隆过滤器的题目，把今天没有落地的部分补上。
