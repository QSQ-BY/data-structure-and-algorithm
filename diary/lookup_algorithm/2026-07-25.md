# 2026-07-25：从数组到函数，重新理解二分查找

今天正式开始学习查找算法，主要写了二分查找和跳跃表。二分查找的代码不长，真正让我震撼的是老师讲到的另一层关系：数组和函数都在完成“输入到输出”的映射。

## 二分查找：每次排除一半范围

数组中的二分查找建立在有序性上。今天代码里的核心循环是：

```cpp
int left = 0;
int right = n-1;
while(left<right){
    int mid = right + (left-right)/2;
    if(target == arr[mid]){
        pos = mid;
        break;
    }
    if(target > arr[mid]){
        left = mid+1;
    }
    if(target < arr[mid]){
        right = mid-1;
    }
}
```

这段代码反复做三件事：

1. 用 `left` 和 `right` 表示当前还需要查找的范围。
2. 取中间位置 `mid`，比较 `target` 与 `arr[mid]`。
3. 根据比较结果移动一个边界，把不可能出现答案的半边直接排除。

因此，长度为 `n` 的区间经过一次比较后大约只剩 `n/2`，再下一次只剩 `n/4`。查找次数随数据量增长得很慢，时间复杂度是 `O(log n)`；循环只使用几个变量，额外空间是 `O(1)`。

## 数组与函数，其实是同一种映射

老师今天把数组和函数放在一起比较，我以前从来没有从这个角度想过：

| 形式 | 输入 | 输出 | 主要消耗 |
| --- | --- | --- | --- |
| 数组 | 下标 `i` | `arr[i]` | 预先存储数据，占用空间 |
| 函数 | 参数 `x` | `f(x)` | 调用时计算，花费时间 |

数组是给定下标就能取出一个值，函数是传入参数就能得到返回值。从映射关系看，两者没有那么遥远。二分查找放在数组里，是已知元素值去找下标；迁移到单调函数里，就是已知返回值 `y`，反过来寻找参数 `x`。

## 用税后收入反求税前收入

今天的税收问题先用 `f(x)` 根据税前收入 `x` 算出税后收入，再给定税后收入 `y`，寻找满足 `f(x)=y` 的 `x`。我写的搜索部分如下：

```cpp
#define EXP 1e-4
double binary_algorithm(int y){

    double left = 0.0;
    double right = 100000000.0;
    double mid = 0.0;
    while(abs(left - right)>=EXP){
        mid = right + (left-right)/2;
        if(y == f(mid)){
            break;
        }
        if(y > f(mid)){
            left = mid+1;
        }
        if(y < f(mid)){
            right = mid-1;
        }
    }
    return mid;
}
```

这里和数组二分一一对应：

- 搜索对象从数组下标变成了税前收入所在的数值区间。
- `arr[mid]` 换成了 `f(mid)`，比较的是中间收入对应的税后结果。
- 因为 `f(x)` 单调递增，`f(mid)` 偏小就向右找，偏大就向左找。
- 循环不再等待左右边界碰到同一个整数，而是用误差 `EXP` 控制搜索精度。

如果初始区间长度是 `R-L`，允许误差是 `EXP`，不断折半需要的次数大约是 `O(log((R-L)/EXP))`。这个例子让我第一次清楚地看到，二分查找并不属于数组，它真正依赖的是“有序”或“单调”。

后面的练习还会继续把二分用到函数上。我需要训练的也不只是循环模板，而是拿到问题后先问两件事：答案有没有明确的取值范围？题目中的关系是否具有单调性？

## 跳跃表：在链表上搭出多层索引

今天学习的另一个结构是跳跃表。它可以看成二维链表：`next` 负责同层向右移动，`up` 和 `down` 负责在同一个键的不同层之间移动。

下面这段节点定义和查找函数最能说明它的结构：

```cpp
typedef struct node{
    int key;
    struct node* next;//横向指针
    struct node* down;//向下的指针
    struct node* up;//向上的指针
    int level;//层数
}node;

// ... 省略节点创建等代码

node* find(skiplist* s,int x){
    if(s==nullptr) return nullptr;
    node* p = s->head;
    while(p!=nullptr and p->key!=x){
        if(p->next!=nullptr and p->next->key <= x) p = p->next;
        else p = p->down;
    }
    return p;
}
```

查找过程可以拆成两种移动：

1. 如果右边节点的值仍然不大于目标值，就沿 `next` 向右走，尽量在高层跨过更多节点。
2. 如果继续向右会越过目标，就沿 `down` 下降一层，在更密集的链表中继续判断。

插入时还要用 `rand_level` 随机决定新节点出现的层数。越高的层节点越少，负责跳过较长的距离；底层保存完整数据。理想情况下，跳跃表的平均查找和插入复杂度都是 `O(log n)`，最坏情况下仍可能退化到 `O(n)`。

跳跃表的想法不算难，代码却很冗长。节点塔、头尾哨兵、横向连接和上下层连接都要分别处理，我今天的大部分时间都花在这些指针上。
