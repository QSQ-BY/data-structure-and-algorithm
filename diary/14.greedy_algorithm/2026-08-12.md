## 洛谷日练：并查集很熟，DFS 开始成形

第一题 P1162「填涂颜色」和课堂上的并查集练习很接近。把每个值为 `0` 的格子看成节点，相邻的 `0` 合并；边界上的 `0` 再统一连接到虚拟节点 `0`。最后，凡是没有和虚拟节点连通的 `0`，都位于闭合圈内部，输出时改成 `2`。

这道题的模型比较熟悉，路径压缩、按大小合并和二维坐标映射也都用过，所以思路很快就定了。今天没有在这里遇到新的概念，更多是维持并查集的手感。

第二题 P9241「飞机降落」依旧用 DFS。每架飞机都有最早开始时刻、最晚开始时刻和降落耗时，单纯按最晚开始时刻排序并不可靠，因为一架截止较早但耗时很长的飞机，未必应该最先降落。`N≤10`，直接枚举降落顺序反而更稳妥。

```cpp
bool dfs(long long  t,long long  current_time){
    if(t == 0){
        return true;
    }
    for(long long  temp = t;temp!=0;temp-=(-temp&temp)){
        long long  bit = -temp&temp;
        long long  next_plane_index = ind[bit];
        long long  next_t = t^bit;
        long long start_time =
            max(current_time, datas[next_plane_index].l);
        long long next_time =
            start_time + datas[next_plane_index].time;
        if(start_time>datas[next_plane_index].r){
            continue;
        }
        if(dfs(next_t,next_time)){
            return true;
        };
    }
    return false;
}
```

这里的 `t` 表示还没有降落的飞机集合，某一位为 `1`，对应的飞机仍可选择。`lowbit` 每次取出一架飞机，`t ^ bit` 把它从下一层状态里删掉。状态掩码不再只是一个压缩后的整数，它直接描述了 DFS 当前还剩哪些选择。

这次最值得记住的是时间与返回值的含义。飞机真正能开始降落的时刻不是简单的 `current_time`，而是 `max(current_time, T_i)`：跑道空闲以后，如果飞机还没到，就必须等到它到达。某一架飞机当前来不及降落，只说明这个选择失败，应该 `continue` 尝试同层的其他飞机；只有所有选择都失败，当前状态才返回 `false`。反过来，只要有一条递归路径完成了全部飞机，就要把 `true` 一层层传回去。

我以前对 DFS 的理解容易停在“递归调用自己”，现在开始能把它拆成状态、选择、转移、剪枝和返回值。接下来还需要继续强化，但掩码回溯的骨架已经不再陌生。

## 奶牛晒太阳：先照顾选择范围窄的奶牛

贪心主线今天有三道题。第一题「奶牛晒太阳」里，每头奶牛能接受一个 SPF 区间，每种防晒霜则有固定 SPF 和数量。处理顺序是把奶牛按可接受区间的右端点从小到大排序，再把防晒霜按 SPF 从小到大排序。轮到一头奶牛时，为它选择范围内最小的可用 SPF。

右端点更小，意味着它更早失去被满足的机会；已经决定先处理它以后，再给它最低可行 SPF，可以把更高的 SPF 留给最低承受值更高的奶牛。今天我也把几个相近方案放在一起比较了：不排序会让结果取决于输入顺序；如果反向处理，则不能简单地把两个数组都倒序，而要改成按左端点降序，并选择最大的可行 SPF。贪心的扫描方向与“节省哪一侧资源”必须配套。

## 公司任务：两个约束维度不能同时用同一种方式处理

「公司任务」与奶牛晒太阳很像，但机器和任务都有时间、难度两个属性。任务按时间从大到小处理，机器也按最大工作时间从大到小排列。扫描到当前任务时，把所有时间足够的机器加入候选集合，再从候选集合中选择难度最低但仍能完成任务的机器。

```cpp
for (long long i = 0; i < M; i++) {
    long long task_time = mission[i].first;
    long long task_level = mission[i].second;

    while (j < N and machine[j].first >= task_time) {
        level[machine[j].second]++;
        j++;
    }

    for (long long k = task_level; k <= 100; k++) {
        if (level[k] > 0) {
            level[k]--;
            cnt++;
            wage += 500LL * task_time + 2LL * task_level;
            break;
        }
    }
}
```

这段代码把两个约束分开处理。时间负责决定哪些机器已经有资格进入候选集合；难度负责从候选集合中挑选具体机器。因为后面的任务所需时间不会更长，候选机器一旦加入，就不必再担心时间能力不够。真正需要节省的是难度，所以不能总拿最强机器，也不能只挑最大工作时间最低的机器。

收益公式 `500x+2y` 还有一层作用。难度范围是 `0～100`，时间增加 `1` 带来的 `500` 收益，大于难度部分最多产生的 `200` 差距，因此按收益降序等价于按时间降序、时间相同时按难度降序。这个结论依赖题目的系数与数据范围，并不是看到两个正系数就能直接照搬。

## 树的涂色：最难的是把节点重新看成块

最后一题「树的涂色」是今天最难的一道，在洛谷上也是紫题。每个节点的代价是完成时刻乘以自身权值，同时又要求父节点必须先于子节点染色。直接在所有可染节点中挑权值最大的一个还不够，因为树上的先后依赖会不断改变后续选择。

真正的做法是把已经绑定顺序的一组节点看成一个整体，维护这个块的总权值、节点数和平均权值。每次找到平均权值最大的非根块，把它合并到当前尚未合并的祖先块中：

```cpp
for(int i=1;i<=n-1;i++){
    int x = find_max();
    int father_x = find_father(x);
    //把x和father[x]进行合并
    ans+=cnt[father_x]*c[x];
    c[father_x] += c[x];
    cnt[father_x] += cnt[x];
    w[father_x] = 1.0*c[father_x]/cnt[father_x];
    vis[x] = 1;
}
```

这里最难的不是合并代码，而是接受问题中的基本单位已经从“单个节点”变成了“必须连续安排的一段节点”。`c` 记录块的总权值，`cnt` 记录块的长度，`w=c/cnt` 决定接下来优先合并哪一块。与前两题相比，这道题的局部选择藏得更深，必须先完成一轮调度模型的转化，贪心规则才会出现，这道题主要还是用来拓展一下算法思维并不会进行完整的自行复现，毕竟与我的水平相差实在太大。
