## P16797 密码提取：把前导零合并成计数权重

[源码](../../Exercise/prefix&difference/P_16797_蓝桥杯_2026_国_B_密码提取.py)

这道题要统计数字串中数值落在指定区间的连续子串，位置不同就算不同方案。最初我枚举左右端点，把子串转换成整数，再逐次回答询问。字符串和询问都能达到一百万，这样枚举子串的规模太大。

突破口在询问的数值上界：所有区间都不超过 100000。一个以非零数字开头、数值不超过上界的子串，最多只有六位。真正不能直接限制的是前导零，例如 `5`、`05`、`005` 都应该计入数值 5。

我把一个非零开头的子串，以及它前面可以附带的连续零，一起统计。如果非零起点前紧接着有 `zeros` 个零，固定终点后，可以带上零个、一个，直到全部前导零，一共 `zeros + 1` 个起点。源码中这一段保留了这个关系：

```python
    zeros = 0
    for left in range(n):
        if number[left] == "0":
            zeros += 1
            # 以当前零结尾的全零子串共有 zeros 个。
            cnt[0] += zeros
            continue

        # 当前非零数字前的连续零，可以选取 0 到 zeros 个。
        weight = zeros+1
        zeros = 0
        cur = 0
        for right in range(left,min(n,left+6)):
            cur = cur*10+int(number[right])
            if cur > limit:
                break
            cnt[cur] += weight
```

`cnt[v]` 保存数值恰好为 `v` 的子串数量。遇到零时，`zeros` 是以当前位置结束的连续零长度，也正好是新增的全零子串数量。例如连续三个零，依次增加 1、2、3，累计得到 6 个数值为零的子串。

遇到非零数字后，先用 `zeros + 1` 保存起点数量，再把连续零计数清空。后面的终点最多枚举六个；即使数值相同，附带不同数量的前导零也是不同的截取方案。

统计完成后，我对 `cnt` 建立带一个前置零的前缀和。源码中的 `pre[x]` 表示数值严格小于 `x` 的子串数，因此查询 `[l,r]` 用 `pre[r+1] - pre[l]`，`l=0` 也可以直接处理。

例如 `00510` 中，数值 5 对应 `5`、`05`、`005` 三种截取，权重就是 3。前面的零还会继续成为 `51`、`510` 的前导零，所以同一个权重可以用于这个非零起点向后扩展得到的每个合法数值。

预处理时间为 $O(6N+V)$，每次查询 $O(1)$，总时间为 $O(N+M+V)$，其中 $V=100000$。我需要保留的思路是：数值位数有限，而前导零造成的不同起点，可以压缩成一次累加的权重。

## P10489 The Buses：从逐条分配记录改成选择完整线路

[源码](../../Exercise/backtrack_algorithm&search/P_10489_IOI_1994_The_Buses.py)

公交线路在 0 到 59 分钟内等间隔到站，每条至少出现两次，不同线路也可能在同一分钟到站。我的第一种写法按时间顺序处理记录，用迭代加深限制线路数，再决定当前记录接到哪条线路，或者是否新建一条。

这套状态里，一条线路只有一个时刻时，发车间隔还没有确定；有两个时刻后，后续必须出现的时间才全部确定。因此我先在原来的 DFS 上加剪枝：已经错过下一班的分支直接结束；剩余记录不够补全已有线路时结束；已确定线路正在等待当前时刻时优先分配；起点相同的单点线路，在同一层只尝试一条。

这些剪枝减少了分支，但仍要在搜索中逐步拼出线路。后来我继续看 `solution2`，它先枚举完整线路，再搜索这些线路怎样覆盖所有记录。

一条候选线路可以用 `(s,d,length)` 表示：首次到站时间、间隔、这一小时内的到站次数。首次到站必须满足 $s<d$，否则 $s-d$ 仍在这一小时内，就不是首次到站；同时要求 $s+d\le59$，保证至少到站两次。只有整条线路需要的时刻都在原记录中出现过，才保留为候选。

`t[minute]` 保存该分钟尚未使用的记录数量，所以同一时刻的多条记录不会被合并掉。候选按长度降序排列后，搜索的核心如下，省略了函数开头的终止判断和越界判断：

```python
        if total + a[pos][2] * (dep - x) < n:
            return False
        for i in range(pos, cnt):
            s, d, length = a[i]
            if not check(s, d):
                continue
            for j in range(s, 60, d):
                t[j] -= 1
            if dfs(x + 1, i, total + length):
                return True
            for j in range(s, 60, d):
                t[j] += 1
```

这里 `x` 是已经选的线路数，`dep` 是本轮允许的总线路数，`total` 是已覆盖的记录数。由于后续只选择编号不小于 `pos` 的候选，而候选按长度递减，剩下每条线路最多覆盖 `a[pos][2]` 条记录。如果把这个乐观上界加上去仍小于 `n`，就可以结束当前分支。

选择线路前，`check` 检查它需要的每个时刻是否还有记录；选择后逐个扣除，失败时再恢复。递归传入的是 `i`，允许同一候选再次被选择，因为题目允许多条起点、间隔完全相同的线路；同时保持候选编号不下降，避免把同一组线路按不同顺序重复搜索。

我追问过为什么这份写法比逐条分配记录更容易跑快。两者都用了迭代加深，区别在搜索对象：完整线路提前满足了等间隔、小时内不能漏班等约束，一次选择就覆盖多条记录，还能用长度上界剪枝。搜索本身仍然是指数级，实际速度取决于候选和分支数量，不能只凭用了迭代加深就判断是否会超时。

## B4253 几何：曼哈顿距离需要考虑两个方向

[源码](../../Exercise/math/B_4253_科大国创杯小学组_2024_几何.py)

这题分别求最大欧氏距离的平方、最大曼哈顿距离。我最初在曼哈顿距离分支里按 `x+y` 排序，再取首尾差值。检查时用两个点 `(1,3)`、`(3,1)` 就能发现遗漏：它们的 `x+y` 都等于 4，但曼哈顿距离是 4。

对坐标差 $u=x_i-x_j$、$v=y_i-y_j$，有：

$$
|u|+|v|=\max(|u+v|,|u-v|).
$$

所以需要同时考虑 `x+y` 和 `x-y`，答案是：

$$
\max\left(
\max_i(x_i+y_i)-\min_i(x_i+y_i),
\max_i(x_i-y_i)-\min_i(x_i-y_i)
\right).
$$

修改后的代码在读入时维护这两组最大值、最小值。处理完前若干个点后，四个变量分别保存这些点在两个方向上的极值；加入一个新点，只需要更新这四个量。这样就能用 $O(n)$ 时间、$O(1)$ 额外空间计算，不再需要排序或保存全部点。

欧氏距离分支中，$n\le1000$，枚举点对可以保留。这里还确认了一个数值计算问题：用 `dist` 开方后再平方，最后转成整数，会受浮点误差影响。点 `(1,1)`、`(3,4)` 的距离平方应为 13，原来的表达式实际得到了 12。

题目要求的本来就是整数平方和，所以直接计算 `dx*dx + dy*dy`。这也适用于坐标接近 $10^9$ 的情况，Python 整数可以精确保存结果。

修正后，9 组样例及边界测试、1000 组随机暴力对拍均通过。这次需要记住的是两个方向都要纳入曼哈顿距离的极值，以及整数目标尽量直接用整数表达式计算。

## P10580 gcd 与 lcm：把整数序列转成质因子指数序列

[源码](../../Exercise/math/P_10580_蓝桥杯_2024_国_A_gcd_与_lcm.py)

这道题统计长度为 $n$、gcd 为 $x$、lcm 为 $y$ 的序列数量。我最初写的是组合数乘阶乘，但序列允许重复，而且合法序列不一定含有 $x$ 或 $y$。例如 gcd 为 1、lcm 为 6 时，`(2,3)` 就合法，不能把 1 和 6 当成必须出现的两个元素。

我后来先把所有元素除以 $x$。令 $b_i=a_i/x$、$m=y/x$，条件变成：

$$
\gcd(b_1,\ldots,b_n)=1,\qquad
\operatorname{lcm}(b_1,\ldots,b_n)=m.
$$

每个 $b_i$ 都是 $m$ 的约数。把 $m$ 分解为 $\prod_j p_j^{e_j}$ 后，就可以分别考虑每一种质因子的指数。

我又让讲解展开了一次，重点确认 gcd 和 lcm 对应什么约束：gcd 中某个质因子的指数，是所有元素中该指数的最小值；lcm 中则是最大值。因此，对 $m$ 中的一个质因子 $p^e$，各位置的指数都在 $0$ 到 $e$ 之间，并且至少出现一次 0、至少出现一次 $e$。

用容斥统计这一种质因子的贡献：

$$
f(e)=(e+1)^n-2e^n+(e-1)^n.
$$

全部指数序列有 $(e+1)^n$ 种。没有 0、没有 $e$ 的分别有 $e^n$ 种，先各减一次；既没有 0 也没有 $e$ 的 $(e-1)^n$ 种被重复减掉，再补回来。

源码中求出某个质因子的指数后，按这个公式累乘：

```python
        while m % p == 0:
            m //= p
            e += 1

        if e:
            ways = (
                pow(e + 1, n, MOD)
                - 2 * pow(e, n, MOD)
                + pow(e - 1, n, MOD)
            ) % MOD
            ans = ans * ways % MOD
```

不同质因子的指数选择互不限制，可以按位置组合成唯一的整数序列；反过来，整数序列也唯一确定这些指数，所以直接使用乘法原理。`pow(base,n,MOD)` 用快速幂计算贡献，单次询问的时间为 $O(\sqrt{y/x}+k\log n)$，其中 $k$ 是不同质因子的个数。

第二组样例中 $m=144/12=12=2^2\cdot3$，$n=3$，两个贡献分别为：

$$
f(2)=27-16+1=12,\qquad f(1)=8-2=6,
$$

相乘得到 72。这里提供最小指数、最大指数的元素可以不同，不需要某个位置同时承担所有质因子的最小值或最大值。

我最后单独追问了指数为 1 时怎么办。此时每个位置只能选 0 或 1，合法条件就是两者都出现。全部 $2^n$ 个 01 序列里，去掉全 0 和全 1，剩下 $2^n-2$ 种；通用公式也正好化简成这个结果。试除结束后剩余的大于 1 的数是质数，剩余指数为 1，因此代码最后也是乘这一项。

当 $x=y$ 时，$m=1$，没有质因子需要处理，答案初值 1 保留下来，对应所有元素都等于 $x$ 的唯一序列。当前源码已通过 3 组样例，并与 $m=1$ 到 40、$n=2$ 到 4 的全部小规模枚举结果核对，共 120 组。
