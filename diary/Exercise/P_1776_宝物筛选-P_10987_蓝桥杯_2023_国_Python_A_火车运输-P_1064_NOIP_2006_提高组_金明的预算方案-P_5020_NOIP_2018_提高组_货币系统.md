## P1776 宝物筛选：二进制分组与单调队列

我先写了二进制分组，把一种物品的数量拆成若干包，再当成 0/1 物品倒序更新容量。之后又问了单调队列的做法，以及为什么实际运行时二进制分组反而更快。

单调队列按容量除以重量的余数分组。固定余数 `r`，容量写成 `r+k*weight`，转移整理成：

$$
new[r+kw]=kv+max_{tin[max(0,k-cnt),k]}(old[r+tw]-tv).
$$

窗口限制对应最多拿 `cnt` 件，源码维护减掉 `t*value` 后的候选：

```python
for k, j in enumerate(range(r, limit + 1, weight)):
    # 下标小于 k-cnt，意味着要拿超过 cnt 件，不能使用
    while q and q[0][0] < k - cnt:
        q.popleft()
    score = old[j] - k * value
    # 新候选更晚过期，且价值不低，可以淘汰队尾
    while q and q[-1][1] <= score:
        q.pop()
    q.append((k, score))
    # 队首就是当前窗口中的最大值
    dp[j] = q[0][1] + k * value
```

下标太小的候选超过件数上限，从队首删除；新候选更晚过期且得分不低时，可以淘汰队尾。必须从保存好的 `old` 转移，防止当前物品更新后的结果再次混入。

单调队列每种物品扫描容量，总时间为 $O(nV)$；二进制分组约为 $O(V\sum_i\log(cnt_i+1))$。但 Python 中元组、双端队列与维护窗口都有常数开销，具体速度不能只凭渐进复杂度判断。我保留了两种实现来对照。

## P10987 火车运输：同一根木材只能分给一辆车

最初的搜索枚举放 A 车、放 B 车或者不装。我要求先按普通三维 DP 理解，再去掉物品这一维，保留两个容量维度。

```python
for w in weights:
    for j in range(a, -1, -1):
        for k in range(b, -1, -1):
            # 不装：保留 dp[j][k]
            # 装进 A 车
            if j >= w:
                dp[j][k] = max(
                    dp[j][k],
                    dp[j-w][k] + w
                )
            # 装进 B 车
            if k >= w:
                dp[j][k] = max(
                    dp[j][k],
                    dp[j][k-w] + w
                )
```

`dp[j][k]` 表示两辆车的容量分别为 `j`、`k` 时，最多能装多少重量。不装由原值保留，另外两项分别扣除 A 或 B 的容量。

两层容量都倒序，保证读取的是尚未使用当前木材的上一层结果，同一根木材不能既装 A 又装 B。空间压到 $O(ab)$，时间仍然为 $O(nab)$。

## P1064 金明的预算方案：一组方案包含多个附件

附件不能单独买，我先按主件编号归组，再把主件和选中的附件当成一个完整选项。讨论时我担心逐个 `extend` 会漏掉同时买两个附件的情况，展开列表后才看清它是怎样生成子集的。

```python
options = [main[i]]

#拓展出所有选择，选择主+附件1，主+附件2，主+附件1+附件2
for aw, av in attachments[i]:
    extra = [(w + aw, v + av) for w, v in options]
    options.extend(extra)
```

最初只有主件。加入第一个附件后，已有主件、主件加附件一两项；处理附件二时，给这两项分别加一次附件二，所以同时包含两个附件的方案也会出现。

`extra` 先生成再扩展，不会在同一次处理中不断使用刚追加的项。之后容量倒序、组内枚举方案，每个主件组最多选一种。单组至多四种组合，背包部分为 $O(nV)$。

## P5020 货币系统：复用已经得到的可表示金额

面额排序后，当前面额能由更小面额组合出来，就不必保留；不能表示，则要把它加入货币系统。

我要求尽量少改原代码，不要每次从 0 重建可达数组。当前实现保留共享的 `can_get`，并令 `can_get[0]=True`。每次检查下一个目标前，只把上一个尚不可表示的面额加入完全背包更新，金额正序遍历，允许同一面额重复使用。

已经能由旧面额表示的面额，不会扩大可达集合，也可以跳过更新。总时间为 $O(nV)$，空间为 $O(V)$。这里复用的是已处理货币集合对应的计算结果，而不只是重复使用数组内存。
