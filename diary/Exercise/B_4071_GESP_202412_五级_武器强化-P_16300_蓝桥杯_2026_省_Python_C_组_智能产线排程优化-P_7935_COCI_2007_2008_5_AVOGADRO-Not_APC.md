# 武器强化、双产线排程与队列传播

## B4071 武器强化：枚举目标数量，再区分强制和可选材料

[源码](../../Exercise/greedy_algorithm/B_4071_GESP_202412_五级_武器强化.py)

我先枚举武器 1 最终至少要达到的数量 t。要让它严格领先，其他每种武器都只能剩 t-1 份材料，因此第 i 种必须转走 max(0,cnt[i]-t+1) 份。

 每种材料先按修改费用排序，强制转移的部分取最便宜的。如果完成这些转移后武器 1 仍不足 t，再从所有剩余材料中统一挑最便宜的补足。枚举 t 时，强制部分带来的数量也必须算入 have。

 这里的建模把“自己增加”和“对手减少”放在了同一次转移里。当前实现每个 t 都重新收集并排序可选材料，最坏仍有 O(m² log m+nm) 的成本；它是按目标数量枚举的方案，不能因为内部用了贪心就直接记成线性。

## P16300 智能产线排程优化：先排截止时间，再决定订单放哪条线

[源码](../../Exercise/dynamic_programming/P_16300_蓝桥杯_2026_省_Python_C_组_智能产线排程优化.py)

订单的顺序和两条产线的分配同时变化，看起来不好枚举。先按截止时间排序后，对选到同一条线的任务，可以按截止时间顺序加工；再用两维时间容量记录两条线的安排。

 当前代码把初始表全部设为 0，整理时我按时间预算理解这张表，不把不可达的“恰好用时”状态也当成收益 0。每份订单只有跳过、放到 A、放到 B 三种选择：

```python
for p, d, r in tasks:
    for j in range(d, -1, -1):
        for k in range(d, -1, -1):
            # 当前订单放到 A 产线
            if j >= p:
                dp[j][k] = max(dp[j][k], dp[j-p][k] + r)

            # 当前订单放到 B 产线
            if k >= p:
                dp[j][k] = max(dp[j][k], dp[j][k-p] + r)
```

j、k 都倒序，避免同一份订单在本轮被重复选取。当前任务只更新不超过 d 的时间范围，使它放入某条线后的完成时间不晚于自己的截止时间。

 设最大截止时间为 D，时间上界 O(nD²)，空间 O(D²)。二维预算把分配选择保存下来，截止时间排序则让每条线上的加工次序不必再额外枚举。

## AVOGADRO：某个数字缺失后，删除会继续传播

[源码](../../Exercise/simulation/P_7935_COCI_2007_2008_5_AVOGADRO.py)

三行最后要保留相同的数字集合。第一行原本是一个排列，所以某个数字只要在任意一行缺失，所有包含它的列就必须删除。删列又可能使其他数字的出现次数变成零，继续触发删除。

 源码用 cnt 记录各行频次，pos 记录包含某个数字的列，再用队列处理这些必须删除的数字。下面是一次传播的主体：

```python
while q:
    x = q.popleft()
    #遍历所有包含了x的列下标
    for i in pos[x]:
        if(delete[i]):
            continue
        delete[i] = True
        ans += 1
        for r in range(3):
            y = a[r][i]
            cnt[r][y] -= 1
            if(cnt[r][y] == 0 and bad[y] ==False):
                bad[y] = True
                q.append(y)
```

bad 防止同一个数字重复入队，delete 防止一列被多个数字重复删除。队列处理完后，剩下 k 列，第一行有 k 个不同数字；另外两行也必须包含这 k 个数字，而且只有 k 个位置，所以自然各出现一次。

 每个数字最多入队一次，每列最多删除一次，pos 总共只有 3n 项，时间、空间都是 O(n)。不用反复把三行排序后比较，只需处理新出现的缺失。

## Not APC：同时保留未匹配的 A 和等待 C 的 AP

[源码](../../Exercise/simulation/Not_APC.py)

对话里检查过只记一组 APC 的写法，它会漏掉交错的子序列。AAPPCC 就可以删除两组，不能在等待第一个 C 时把后来的 A、P 忽略。

 当前代码用两个队列分别保存尚未匹配的 A，以及已经组成、正在等待 C 的 AP：

```python
for i,ch in enumerate(string):
    if ch == "A":
        qa.append(i)
    elif ch == "P" and qa:
        qap.append((qa.popleft(), i))
    elif ch == "C" and qap:
        a, p = qap.popleft()
        bad[a] = bad[p] = bad[i] = True
        delete.extend((a + 1, p + 1, i + 1))
        ans += 1
```

遇到 P 就尽早形成 AP，遇到 C 就尽早完成一组，后续字符仍能继续匹配。队列中的下标保留原字符串位置，所以删除方案可以直接输出，不需要真的反复删除字符串。

 每个字符只经过常数次处理，总时间和空间为 O(n)。这次要保留的是多组尚未完成的匹配进度，而非只保存眼前的一组。
