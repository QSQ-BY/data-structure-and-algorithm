## P3958 奶酪：并查集只负责连通，几何判断还需要剪枝

[源码](../../Exercise/unionset/P_3958_NOIP_2017_提高组_奶酪.py)

球形空洞相交就属于同一连通块，另设底面、顶面两个虚拟节点，最后判断两者是否连通。

 我先问了如何把 find 写成循环：第一段向上找到根，第二段沿原路径把节点直接接到根。这样不用递归，也保留了路径压缩。后来遇到 TLE，优化重点又落在候选球对上。下面是当前实现里按高度排序后的内层判断，省略后续相交检测：

```python
for q in range(p + 1, n):
    j = order[q]
    xx, yy, zz = items[j]

    if zz - z > diameter:
        break

    root_j = find(j)
    if root_i == root_j:
        continue

    # 任意一个方向距离过大，都不可能相交
    if abs(xx - x) > diameter or abs(yy - y) > diameter:
        continue
```

按 z 排序后，高度差超过 2r 就可直接结束本轮；x、y 任一方向差值超过直径，也无需算欧氏距离。已经处于同一集合的两球不必再合并，上下表面连通后可以提前结束。

 排序和剪枝能减少实际距离计算，但没有消除最坏 O(n²) 的两两候选枚举。并查集用按大小合并和路径压缩降低连接操作的成本，不能据此把整个几何建图也写成近似线性。

## P16804 键盘失灵：补集计数，再只保存递推需要的历史

[源码](../../Exercise/dynamic_programming/P_16804_蓝桥杯_2026_国_Python_A_键盘失灵.py)

我在对话里反复问过递推的含义，也比较过直接开 n 大小数组和循环数组。长度 n=20260606 时，存下每一项会占用大量内存。

 先让 f[i] 表示长度为 i、不含连续 k 个相同字母的串数，最后用 26^n-f[n] 得到会卡死的串数。初值为 f[i]=26^i（i<k），f[k]=26^k-26；之后有 f[i]=26f[i-1]-25f[i-k]。

 原因是先给合法串补一个字母，再减掉新产生的违规串。对长度 i-k 的合法前缀，接上一整段 k 个同字母时，为了使此前仍合法，尾段字母须与前缀最后一个字母不同，有 25 种选择。循环数组版只保留最近 k 项：

```python
prev = (26 * dp[k-1] - 26) % MOD  # f[k]
dp[0] = prev
for i in range(k+1, n+1):
    pos = i % k
    # 覆盖前 dp[pos] 是 f[i-k]，prev 是 f[i-1]。
    prev = (26 * prev - 25 * dp[pos]) % MOD
    dp[pos] = prev
```

覆盖 dp[pos] 前，它保存的恰好是 f[i-k]，prev 保存 f[i-1]，所以读完旧值后就能原位覆盖。总时间仍为 O(n)，辅助空间由 O(n) 降为 O(k)。

 当前文件同时保留两个版本，末尾调用的仍是完整数组版 solution1()。日志记录的是两种实现及其区别，不能把循环数组写成已经成为当前运行入口。

## P12347 栈与乘积：先找零，再只乘真正放大结果的因子

[源码](../../Exercise/simulation/P_12347_蓝桥杯_2025_省_A_第二场_栈与乘积.py)

我问过这题怎么优化，还追问过能否使用线段树。当前方案没有为每次查询遍历全部栈元素，而是额外保存零的位置和大于 1 的因子，值为 1 的元素不参加乘法扫描。

 查询栈顶 y 个数时，先确认数量足够，再看最近的零是否在区间内。下面摘出查询主体：

```python
left = len(stack) - y

if zeros and zeros[-1] >= left:
    print(0)
else:
    ans = 1
    for pos, x in reversed(factors):
        if pos < left:       # 已经超出查询范围
            break
        ans *= x
        if ans >= limit:
            break
    print("OVERFLOW" if ans >= limit else ans)
```

零会使整个乘积为 0，必须先判断，不能在扫描到大因子后就先报溢出。没有零时，每个记录的因子至少为 2，乘上约 32 个就达到 2^32；超过阈值后可以立即停止，范围外的因子也不再扫描。

 入栈、出栈同步维护三组信息，每次更新 O(1)，查询只需 O(32) 次有效乘法。对于当前的后缀查询和固定溢出阈值，这比另建线段树更直接。
