## CF2122C：分别处理两个坐标

[源码](../../Exercise/math/CF_2122_C_Manhattan_Pairs.py)

这题要把平面上的点两两配对，让曼哈顿距离之和最大。我起初按 $x+y$ 排序，再首尾配对；用四个点就能找到反例，因为 $x$ 和 $y$ 的差在这个和里可能互相抵消。后来改成分别按 $x$、$y$ 排序，每一维都把前一半与后一半分开。

两个划分叠在一起，点就落入 `00`、`01`、`10`、`11` 四组。代码最后这样配对：

```python
groups = [[[], []], [[], []]]
for i in range(n):
    groups[x_side[i]][y_side[i]].append(i + 1)

ans = []
for a, b in zip(groups[0][0], groups[1][1]):
    ans.append(f"{a} {b}")
for a, b in zip(groups[0][1], groups[1][0]):
    ans.append(f"{a} {b}")
```

每一维的前后两半人数相同，因此 `00` 与 `11` 人数相同，`01` 与 `10` 也相同。这样配出的每一对都同时跨过两维的分界，两维的距离之和都达到各自的最大值。同一对组内，具体谁和谁配不影响总和；每个点在求和式里的正负号已经由它所在的组确定了。排序时我保留原始编号，后来也把 `lambda` 换成了具名比较函数。两个反例、题目样例和 160 组小规模穷举核对的数据都通过了。

## P1007 独木桥：先从相撞的位置想起

[源码](../../Exercise/greedy_algorithm/P_1007_独木桥.py)

最短撤离时间比较好想：让每个士兵朝离自己最近的桥端走，就不必为了某次相撞额外设计方向。位置为 $p$ 的士兵，向左走需要 $p$ 时间，向右走需要 $L+1-p$ 时间；所有人离桥的时刻由其中最慢的一个决定，所以取 $\max_p\min(p,L+1-p)$。

最长时间我先从相撞想起。把士兵按位置排好，考虑一对最先迎面相撞的相邻士兵：如果固定的点向左，它左边最近的那个点就向右；如果固定的点向右，就看它右边最近、向左走的点。枚举这样的相向组合，再算相遇和折返后的离桥时间，这条路能走通，也比较容易从题意直接想到，只是算起来绕一些。

我把这套相邻点枚举保留在 `test01` 里。下面两项分别计算一对相邻士兵相撞后向右、向左离桥的时间：

```python
positions.sort()
for i in range(n):
    cur = positions[i]
    if(i - 1 >= 0):
        left = positions[i-1]
        maximum_step = max(maximum_step,cur - left + length - cur + 1)
    if(i + 1 < n):
        right = positions[i+1]
        maximum_step = max(maximum_step,right - cur + cur)
```

设相邻两人的起点为 $p<q$。他们在 $(p+q)/2$ 相遇，已经走了 $(q-p)/2$ 时间，转身不耗时。之后向左离桥的一人，总用时是 $q$；向右离桥的一人，总用时是 $L+1-p$。代码里的两个式子正好化成这两个数。先前我用整除去算半段路，遇到相邻两人时会漏掉半格相遇带来的时间；把整段路代入并约掉中点，奇数间距也不用单独处理了。只有一个士兵时，`test01` 另行计算。

再往后看，相撞后两人同时掉头，对“所有人何时离桥”而言，等价于两人直接穿过、交换身份。当前程序调用的是更短的 `test02`：

```python
def test02():
    minimum = max((min(p, length + 1 - p) for p in positions), default=0)
    maximum = max((max(p, length + 1 - p) for p in positions), default=0)
    print(f"{minimum} {maximum}")
test02()
```

这个写法直接取每个人到近端、远端所需时间的最大值，$N=0$ 时也会输出 `0 0`。我的相撞枚举并没有走错，只是最终算出的 $q$ 和 $L+1-p$ 已经把碰撞过程消掉了。先沿着撞点把式子推清楚，再回头看这个简化，我更容易记住它为什么成立。
