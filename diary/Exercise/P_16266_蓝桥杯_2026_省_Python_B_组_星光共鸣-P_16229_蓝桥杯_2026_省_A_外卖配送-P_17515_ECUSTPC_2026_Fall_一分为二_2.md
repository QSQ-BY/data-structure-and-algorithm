## P16266：只统计还没达到门槛的方案

[源码](../../Exercise/dynamic_programming/P_16266_蓝桥杯_2026_省_Python_B_组_星光共鸣.py)

星光共鸣要求统计全 1 子区间数量至少为 K 的 01 串。长度 N 可以到 1000，但 K 不超过 100。我把计数转到补集上：总方案数是 2^N，只计算共鸣次数小于 K 的方案，再减掉它们。

状态 `dp[i][score][run]` 表示已经填好 i 位、总共鸣次数为 score、末尾连续 1 的长度为 run 的方案数。只有 score 还不够：追加一个 1 新增多少个全 1 子区间，取决于结尾连续多少个 1。

下面摘录追加一位的转移，外层枚举和 `ways` 为零时的跳过分支省略：

```python
            # 第 i+1 位填 0
            dp[i + 1][score][0] = (
                dp[i + 1][score][0] + ways
            ) % MOD

            # 第 i+1 位填 1
            new_score = score + run + 1
            if new_score < k:
                dp[i + 1][new_score][run + 1] = (
                    dp[i + 1][new_score][run + 1] + ways
                ) % MOD
```

填 0 会截断末尾的 1 段，分数不变；填 1 新增 run+1 个子区间，所以新分数是 `score+run+1`。已经达到 K 的状态不再保存，因为后续追加字符不会让共鸣次数减少。

末尾一段 run 个 1 自己就贡献 run(run+1)/2，因此只需保留满足这个值小于 K 的 run。代码中的 `limit` 正是这个上界。K=0 时直接输出全部方案。

这一题我记的是“补集”和“结尾信息”如何一起缩小状态：在 K>0 时，时间为 O(NK√K)。当前源码保留全部 i 层，空间同样是 O(NK√K)；若以后改成滚动数组，只需保存相邻两层，但这里记录的仍是现有三维实现。

## P16229：用初始值抵消第一批的特殊费用

[源码](../../Exercise/dynamic_programming/P_16229_蓝桥杯_2026_省_A_外卖配送.py)

外卖订单必须按原顺序分批，但同一批的费用只与订单数量和工具有关。我先为每个批量 L 计算：

$$
cost[L]=\min_j\left(LA_j+\frac{L(L-1)}2B_j\right).
$$

这样分批 DP 不用再枚举交通工具。`dp[i]` 表示送完前 i 单的最小耗时，枚举最后一批有 L 单，前面的最优费用就是 `dp[i-L]`。

```python
dp[0] = -x

for i in range(1, n + 1):
    for L in range(1, i + 1):

        dp[i] = min(
            dp[i],
            dp[i - L] + cost[L] + x
        )

print(dp[n])
```

每次转移统一加一次折返费 x，再让 `dp[0]=-x` 抵消多收的第一笔。若方案有 q 批，最终折返费恰好是 qx-x=(q-1)x；这个负的初值只是计费方式，不代表真的存在负耗时。

我想留下的是这种边界处理：当只有第一段少收一笔固定费用时，可以把特殊情况放到初值，后面的转移保持一致。预处理花费 O(NM)，分批枚举花费 O(N²)，总时间 O(NM+N²)，额外空间 O(N+M)。

## P17515：拼接前缀和后缀时，保留接缝两端是否被选

[源码](../../Exercise/dynamic_programming/P_17515_ECUSTPC_2026_Fall_一分为二_2.py)

一分为二允许选 a 的前 k 项和 b 的后 n-k 项拼接，再选恰好 m 个互不相邻元素，最大化其中的最小值。我先二分门槛 x，只让不小于 x 的位置参与选择。

对于 a 的前 k 项，`a0[k]`、`a1[k]` 分别记录末位不选、末位选时的最多选取数；对于 b 的后缀，`b0[k]`、`b1[k]` 区分首位不选、首位选。单侧转移都是“不选当前位可接任意前态，选当前位必须接相邻位不选”。达不到门槛的选中态设成负无穷。

如果每一侧只留一个最大值，拼接时可能同时选中 a[k-1] 和 b[k]。源码在合并时明确排除这对相邻位置同时被选的情况：

```python
    for k in range(n + 1):
        best = max(
            a0[k] + max(b0[k], b1[k]),
            a1[k] + b0[k],
        )
        if best >= m:
            return True
```

第一项让左边末位不选，右边首位就不受限制；第二项选左边末位，右边首位必须不选。k=0 和 k=n 也参与枚举，分别覆盖全部用 b、全部用 a。

检查用的是“至少 m 个”。如果能选更多，删掉一些选中位置就能得到恰好 m 个，且不会制造相邻冲突。门槛越高，可选位置越少，因此可行性单调。答案必然来自原数组，源码对 `sorted(set(a+b))` 的下标二分。

每次判定 O(n)，连同去重排序，总时间 O(n log n)，空间 O(n)。我在这题保留的状态信息很具体：两段内部都能各自解决，但接缝的相邻限制要求额外记住各自靠近接缝的那一位。
