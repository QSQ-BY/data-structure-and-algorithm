# 双向 DP：项链的断点与合唱队形的峰顶

这次我留下两道需要合并左右信息的题。坏掉的项链按断点拼接两边能收集的珠子，合唱队形按同一个同学的位置合并左右子序列。合并之前，要先确定两边的状态各自对应什么位置。

## P1203：把环展开，在断点两侧分别选颜色

[源码](../../Exercise/dynamic_programming/P_1203_IOI_1993_USACO_1_1_坏掉的项链_Broken_Necklace.py)

项链有红、蓝、白三种珠子，白珠可以当成任一种颜色。每个断点的左右两侧可以分别决定收集红色还是蓝色，直到碰到不兼容的珠子。

当前实现把原串复制三遍，再枚举中间一段的断点。这样每个断点的左右都有足够长的连续区间。`left[i][0]` 记录以 `i` 结尾、只含红珠和白珠的最长连续段，`left[i][1]` 则对应蓝珠和白珠；`right` 记录从该位置开始向右的长度。

处理白珠时，红、蓝两个状态都能延续。我不需要在读到白珠时就替它决定颜色，而是保留两种可能，在断点处分别取最大值。以下是源码左向右递推的一部分，蓝色分支与它对称，这里省略：

```python
for i in range(size):
    bead = beads[i]

    if bead == 'r' or bead == 'w':
        left[i][0] = 1
        if i > 0:
            left[i][0] += left[i - 1][0]
```

遇到蓝珠时，红色状态保持初始化的零，连续段在这里断开。另一方向从右往左做同样的递推，就能在常数时间得到任意断点两侧的候选长度。

源码最后合并的部分是：

```python
for cut in range(n, 2 * n):
    # 断点在 cut-1 与 cut 之间
    left_count = max(left[cut - 1])
    right_count = max(right[cut])

    # 不能超过原项链的珠子总数
    collected = min(n, left_count + right_count)
    answer = max(answer, collected)
```

左边从 `cut-1` 算起，右边从 `cut` 算起，两边起点是相邻的两颗珠子。三倍字符串会让同一颗原珠子出现多次，所以总数必须截到 `n`。全白或全同色时，这个限制尤其容易看出来。

这份实现的时间和空间复杂度都是 `O(n)`。我保留这题，是因为“复制环形序列”和“白珠同时保留两种颜色状态”各自处理了一个限制，到了断点处才把结果合起来。

## P1091：tails 与每个位置的 LIS 长度要分开保存

[源码](../../Exercise/dynamic_programming/P_1091_NOIP_2004_提高组_合唱队形.py)

合唱队形要求先严格上升，再严格下降。我最初尝试用单调栈维护上升序列，随后换成 `bisect_left` 维护尾值，还想把正序和逆序得到的尾值数组直接合并。问题出在这两个数组已经丢失了原始位置：即使尾值相同，也不能据此认定它们对应同一个峰顶。

讨论到这里时，我追问过，这种 DP 做法是不是一定做不出来。后来明确了：二分维护 `tails` 的方向可以保留，只需要在扫描每个同学时，把这个位置的长度存下来。

`tails[pos]` 表示目前扫描过的元素中，长度为 `pos+1` 的严格上升子序列能取得的最小尾值。它服务于后面的二分查找；`left_len[i]` 则记录以第 `i` 个同学结尾的 LIS 长度，后面按峰顶位置合并时要用到它。

当前 `test02()` 的正向扫描如下：

```python
    left_len = [0]*(n)
    #以第i个同学为结尾的严格上升子序列的长度
    tails = []
    for i,height in enumerate(arr):
        pos = bisect_left(tails,height)
        if(pos == len(tails)):
            tails.append(height)
        else:
            tails[pos] = height

        left_len[i] = pos+1
```

二分找到第一个不小于 `height` 的尾值。它前面的尾值都严格更小，因此可以接上当前同学，得到长度 `pos+1`。相等身高只替换已有尾值，不会让长度增加，符合题目的严格递增要求。

还要区分 `pos+1` 和 `len(tails)`。例如依次处理 `130、150、170、140`，读到 `140` 时，整个前缀的 LIS 长度仍是三，但以 `140` 结尾的 LIS 长度只有二。合唱队形需要知道每个具体峰顶能接出多长的队伍，因此这里必须保存 `pos+1`。

反向扫描时重新建立 `tails`，从右向左求严格上升长度，得到的就是原方向上从位置 `i` 开始的最长严格下降长度 `right_len[i]`。左右长度都写回原数组下标，才能在同一个峰顶处合并：

$$
\text{保留人数}=\max_i\left(left\_len[i]+right\_len[i]-1\right),
$$

$$
\text{出列人数}=n-\text{保留人数}.
$$

峰顶在左右两边各算了一次，所以减一。题目允许峰顶位于两端，严格递增或严格递减的队伍都可以全部保留。

现在源码同时保留了 `O(n^2)` 的 `test01()` 和 `O(n log n)` 的 `test02()`，实际调用后者，额外空间为 `O(n)`。这道题留给我的具体认识是：`tails` 可以在扫描时提供每个位置的长度，但扫描结束后的尾值数组不能还原这些逐位置状态。后续要合并的信息，必须在它仍然可得时保存下来。
