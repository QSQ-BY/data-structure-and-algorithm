## P11006 纯职业小组：先求最多能拿多少人还不够

[源码](../../Exercise/greedy_algorithm/P_11006_蓝桥杯_2024_省_Python_B_纯职业小组.py)

题目问至少拿多少人，才能保证组成 `k` 个三人同职业小组。如果只想着怎样尽快凑出小组，得到的是某种有利选法，不能保证乱序抽取的结果。我需要考虑最不利情况：最多拿多少人，仍然只能组成至多 `k-1` 个小组。答案是在这个人数上再加一。

同职业的小队先合并。设一种职业共有 `number=3q+r` 人，不形成小组时最多拿 `min(2,number)` 人，所有职业这部分人数相加得到 `base`。

接着考虑允许多形成一个小组时，最多还能多拿几个人。这是“最多人数”的增量，不是从当前人数出发第一次凑出三人组所需的人数。以八个人为例，零组、一组、两组时最多能拿的人数分别是 2、5、8，两个增量都是 3。

一般情况下，每个职业的增量序列为：

- `r=0`：前 `q-1` 个增量是 3，最后一个是 1。
- `r=1`：前 `q-1` 个增量是 3，最后一个是 2。
- `r=2`：共有 `q` 个增量，每个都是 3。

源码将它们分别计入 `cnt3`、`cnt2`、`cnt1`。每个职业内部的增量非递增，所以全局优先选 3，再选 2、1，不会要求先取一个较小增量才能取到较大增量。下面是使用小组额度的部分，省略了最后对 `cnt1` 的同类处理：

```python
    remain = k - 1
    bad = base

    # 优先选择“一个小组可以多拿 3 人”的情况
    take = min(remain, cnt3)
    bad += take * 3
    remain -= take

    # 再选择多拿 2 人
    take = min(remain, cnt2)
    bad += take * 2
    remain -= take
```

`remain` 是还能允许出现多少个小组，`bad` 是在这个限制下已经构造出的最大人数。若所有人总共也凑不够 `k` 组，直接返回 `-1`；否则最后返回 `bad+1`。字典合并职业后只扫描各个职业，不需要按人数枚举，期望时间为 `O(n)`，空间为职业种类数。

补记时枚举了三种职业各有 1 到 4 人的情况，并枚举每种职业实际拿走多少人，核对最大失败人数，共 160 个用例通过。这个验证对应的正是“保证”和“存在一种选法”的区别。

## P16299 底层协议：互补余数不能同时选

[源码](../../Exercise/math/P_16299_蓝桥杯_2026_省_Python_C_组_底层协议.py)

编号范围是 `1..N`，两枚不同编号的和不能被 2026 整除。`N` 可以达到十的十八次方，不能逐个处理编号，但冲突只取决于模 2026 的余数。

对于 `r=1..1012`，余数 `r` 只和 `2026-r` 冲突。同一侧内部没有冲突，两侧又不能同时出现，所以各对中选数量较多的一侧即可。不同余数对之间没有冲突，可以独立累加。

余数 0 和 1013 需要单独处理：它们与自己相加也会得到 2026 的倍数。即使桶里有很多不同编号，也最多选一个。

当前实现先用 `q, rem = divmod(n, 2026)` 计数：每个余数先出现 `q` 次，余数 `1..rem` 再各加一次。这里从 1 开始补，因为编号从 1 开始。

```python
ans = 0
if(cnt[0] > 0):
    ans += 1
if(cnt[1013] >0):
    ans += 1

for i in range(1,1013):
    ans += max(cnt[i],cnt[2026 - i])

print(ans)
```

时间和空间都为 `O(2026)`，不会随 `N` 的数值线性增长。补记时检查了 `N=1、10、2025、2026、4052`，结果分别为 `1、10、1013、1014、2026`。

这题的分类依据是冲突关系：普通余数形成互补的两桶，0 和 1013 则在桶内就有冲突，不能套同一条“选整桶”的规则。

## P12161 研发资源分配：把排列看成若干个循环

[源码](../../Exercise/greedy_algorithm/P_12161_蓝桥杯_2025_省_Java_B_研发资源分配.py)

B 部门的提交顺序是一个排列，日期编号就是当天输赢的权重。当前实现先反向记录 `pos[x]`：B 使用等级 `x` 的那天，日期是 `pos[x]`。这样就可以按等级从小到大讨论，而不必按天枚举 A 的排列。

```python
pos = [0] * (n + 1)

for i, x in enumerate(p, 1):
    pos[x] = i#pos[i]表示使用等级为i的强度等级能拿到多少的回报

ans = 0
s = 0

for m in range(1, n + 1):
    if m >= 2:
        ans = max(ans, s - pos[m])
    s += pos[m]
```

这段代码很短，真正需要记住的是 `s-pos[m]` 的来历。固定一个等级 `m`，可以让 B 使用 `1,2,...,m-1` 时，A 分别使用 `2,3,...,m`；B 使用 `m` 时，A 使用 `1`。大于 `m` 的等级原样使用，双方打平。

这构成一个循环：前 `m-1` 个等级对应的日期全部赢，等级 `m` 对应的日期输，收益为：

$$
\sum_{x=1}^{m-1}pos[x]-pos[m].
$$

为什么枚举这样的前缀循环就够了？任意方案都可以看成从 B 的等级到 A 的等级的置换。取所有发生改变的等级中最大的一个 `m`，它不可能收到更大的等级，也不能收到自己，因此这一天必输，损失 `pos[m]`。其余改变的等级都小于 `m`，即使假设它们全赢，总收入也不超过 `sum(pos[1:m])`。

于是任何非平凡方案都不超过某个 `s-pos[m]`，而上面的循环又能达到这个值。全打平的收益为 0，所以 `ans` 从 0 开始。

循环检查 `m` 时，`s` 恰好是 `pos[1]` 到 `pos[m-1]` 的和，要先计算候选答案，再加上 `pos[m]`。算法时间、空间均为 `O(n)`。补记时对 `n<=4` 的全部 B 排列，以及 20 个 `n=5` 的排列，枚举所有 A 排列核对，共 53 个用例通过。
