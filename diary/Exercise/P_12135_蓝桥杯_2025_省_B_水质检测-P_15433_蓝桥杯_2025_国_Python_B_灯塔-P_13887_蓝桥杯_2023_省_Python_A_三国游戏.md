## P12135 水质检测：用当前连接位置处理下一段空列

[源码](../../Exercise/greedy_algorithm/P_12135_蓝桥杯_2025_省_B_水质检测.py) · [此前的 DP 记录](lg_cf2113D-lg_U552155-lg_p11642-lg_p12135-lg_p9749.md)

两行河床中，最左和最右已有检测器之外的空列不需要填。当前实现把每列编码为 0、1、2、3，分别表示全空、只有上面、只有下面、上下都有，再扫描这个有效区间。

`gap` 记录两个非空列之间的空列数。任何连接都至少要穿过这些列，因此至少增加 `gap` 个检测器。如果两端只能从不同行连接，还需要一个上下相通的位置，再增加一个。

```python
for i in range(l+1,r+1):
    if(state[i] == 0):
        gap+=1
        continue
    cur = state[i]
    if((cur==1 and edge == 2) or (cur==2 and edge == 1)):
        ans += gap+1
        edge = 3
        gap = 0
    else:
        ans += gap
        edge = cur
        gap = 0
```

`edge` 表示把此前检测器连好之后，当前最右非空列可以用于继续连接的状态。遇到上下错开的两端时，可以沿旧的行填过空列，并在当前列补上缺少的另一个格子。费用恰好是 `gap+1`，当前列上下都连通，因此更新为 3。

这也解释了为什么不能在这个分支直接写成 `edge=cur`：新增的检测器给下一段连接留下了上下两种选择，状态要保留这个结果。其他情况不需要额外换行，只补空列，然后用当前列原有状态继续扫描。

与之前的 DP 相比，这份实现直接选择了一种能达到当前必要费用的连接方式，并将换行放在当前列，保留对后续有利的状态。时间为 `O(n)`；当前文件显式保存每一列的 `state`，空间也是 `O(n)`。

补记时枚举了宽度 1 到 4 的所有两行布局，再枚举新增检测器的集合，用连通性检查求出暴力最优值。全部 340 个布局与当前扫描结果一致。

## P15433 灯塔：选中的集合确定以后，顺序不再产生冲突

[源码](../../Exercise/greedy_algorithm/P_15433_蓝桥杯_2025_国_Python_B_灯塔.py)

题目要求保留原操作序列的一个子序列，但成功点亮的灯塔中不可能出现相邻编号。因此可以先考虑：在出现过的编号中，最多选出多少个互不相邻的编号？

这个转换需要说明顺序为什么可以忽略。对于任意一组互不相邻、且在原序列中出现过的编号，各保留一次出现，并按原先顺序执行。因为选中的编号彼此不相邻，每个操作执行时都不会受到其他已选灯塔阻挡。这组选择一定能还原成合法子序列。

当前代码排序后从两端取，`vis` 表示编号是否还可用。以下是取左端的部分，右端按同样方式处理：

```python
while(left<=right):
    l = arr[left]
    r = arr[right]
    if(vis[l] == False):
        left+=1
        continue
    ans += 1
    vis[l] = False
    if(l - 1 >=0):
        vis[l - 1] = False
    if(l+1 <= n):
        vis[l+1] = False
```

选择当前最小可用编号是安全的：如果某个最优解没有选它，而选了它右边紧邻的编号，可以把后者换成它，不会和更右边的已选编号产生新冲突；如果两者都没选，就还可以加入它。最大可用编号同理，因此交替从两端选择也成立。`vis[l]=False` 同时避免同一个编号重复计数。

另一种理解是把去重后的编号拆成若干连续段。长度为 `len` 的一段就是一条路径，最多选 `(len+1)//2` 个编号；段与段之间没有相邻冲突，可以分别处理。

当前实现排序花费 `O(m log m)`，初始化可用数组花费 `O(n)`，双指针扫描为 `O(m)`，总空间为 `O(n+m)`。补记时随机生成 150 组小输入，直接枚举原操作序列的所有子序列并模拟点亮过程，结果与当前实现一致。

## P13887 三国游戏：把获胜条件写成每个事件的贡献

[源码](../../Exercise/greedy_algorithm/P_13887_蓝桥杯_2023_省_Python_A_三国游戏.py)

先固定一个获胜国家。例如魏国需要 `X>Y+Z`，事件 `i` 对这个条件的贡献就是 `A[i]-B[i]-C[i]`。选中的事件贡献总和严格大于零，就能保证魏国获胜。

于是问题变成：从一组有正有负的贡献里，最多选多少项，使总和严格为正。固定选择 `k` 项时，最大的总和一定由最大的 `k` 项组成，所以降序排列后检查前缀即可。

```python
def max_events(winner, other1, other2):
    contributions = sorted(
        (x - y - z for x, y, z in zip(winner, other1, other2)),
        reverse=True,
    )
    total = 0
    count = 0
    for value in contributions:
        if total + value <= 0:
            break
        total += value
        count += 1
    return count
```

`total` 保存已选前缀的贡献和。加入当前项后若变成零或负数，就不能再选这一项；后面的值只会更小，也不能让更长前缀重新变正，因此直接结束。严格大于号很重要，总和等于零只是兵力打平，不算获胜。

零贡献事件可以加入已经为正的前缀，不会影响胜负，却能增加事件数；如果最大的贡献都不为正，就连一个事件也选不了。分别假设魏、蜀、吴获胜，取三次计算的最大值；三次都为零时输出 `-1`。

算法时间为 `O(n log n)`，空间为 `O(n)`。补记时随机生成了 200 组不超过八个事件的输入，枚举所有非空事件子集，并直接计算三国总兵力来判断胜负，结果一致。这个比较函数所用的 `x-y-z`，就是从题目中的获胜不等式移项得到的。
