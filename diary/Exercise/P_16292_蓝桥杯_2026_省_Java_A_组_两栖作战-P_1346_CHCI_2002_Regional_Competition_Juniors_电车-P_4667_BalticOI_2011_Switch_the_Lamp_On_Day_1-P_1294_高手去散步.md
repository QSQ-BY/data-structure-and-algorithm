## P16292 两栖作战：空间复杂度之外，还要算实际存储

[源码](../../Exercise/backtrack_algorithm&search/P_16292_蓝桥杯_2026_省_Java_A_组_两栖作战.py)

相邻格子的地形相同，移动费用为 0；地形不同，费用为 1。把格子作为节点，就可以用 0-1 BFS 求从左上角到右下角的最少切换次数。成功松弛后，0 权边的终点放到队首，1 权边的终点放到队尾，时间和空间复杂度都是 $O(N^2)$。

这题让我卡住的是 PyPy 的 MLE。$N=5000$ 时有 2500 万个格子，写出 $O(N^2)$ 还不足以判断内存是否够用。当前代码把网格拆成单字符列表，距离也用二维列表保存，队列里再放坐标元组。以本地 64 位 CPython 的列表槽位大小估算，两张矩阵的槽位就约占 382 MiB，还没有计入运行中的整数、队列元素等开销。这个数只是本地存储估算，不能直接当成 PyPy 的实测峰值；PyPy 的列表策略和垃圾回收也会影响实际占用。

讨论中考虑了几种压缩方向：网格用字符串或 `bytearray` 保存，坐标编码成一维编号，用定长整数数组保存编号，并利用二值地形的性质按切换次数分层搜索。它们减少的是每个状态的存储开销，不能只看复杂度阶数来评价。

当前源码仍保留二维列表和坐标元组，只增加了终点出队时的提前结束。压缩方案还没有落到这个文件里，也没有在本机 PyPy 上完成最大规模内存验证。提前结束能减少部分输入上的搜索量，却不能消除最坏情况下的存储问题。

## P1346 电车：为什么不用保存改变后的开关

[源码](../../Exercise/backtrack_algorithm&search/P_1346_CHCI_2002_Regional_Competition_Juniors_电车.py)

每个路口默认指向输入中的第一条轨道，走这条边的代价为 0，走其他轨道的代价为 1。我当时的疑问是：既然司机改变了开关，下一次经过这里时，为什么算法还按最初的朝向计算？

这里要先想清楚最优路线。假设一条路线两次经过路口 `u`，中间绕了一圈，那么可以删掉这个环，第一次到达 `u` 时就选择原来最后离开 `u` 的轨道。如果那条轨道原本就是默认方向，不需要切换；如果不是，直接切换一次即可，而原路线为了最终走这条轨道，也至少要在 `u` 切换一次。删掉环不会增加费用。

因此总能选出一条不重复经过路口的最优路线。沿这样的路线，每次到达的开关都还没有被这条路线操作过，用初始方向确定边权就足够了。搜索中的不同分支是不同的候选路线，也不能把一个分支的改向直接写进共享邻接表，否则会影响其他分支。

当前实现的松弛部分如下，省略了读取默认轨道和枚举邻点的外层代码：

```python
        if(index == next):
            w = 0
        else:
            w = 1
        next_step = dis[cur] + w
        if(dis[next] <= next_step):
            continue
        dis[next] = next_step
        if(w == 0):
            q.appendleft(next)
        else:
            q.append(next)
```

`dis` 保存目前找到的最小切换次数，只有距离变小时才继续入队。同样是队列搜索，0-1 BFS 不能照搬普通 BFS 的“首次发现便确定最短距离”：终点可能先通过一条费用为 1 的边被发现，之后又通过两条费用为 0 的边得到更小的距离。

今天讨论后，我把提前结束的条件分清了：普通等权 BFS 首次发现终点时就可以结束，也可以等到终点出队；标准 0-1 BFS 则在终点首次出队时结束。当前电车代码采用后一种写法。邻接表实现的 0-1 BFS 时间复杂度为 $O(V+E)$，图和距离、队列所需空间为 $O(V+E)$。

## P4667 Switch the Lamp On：节点是格点，费用来自方格

[源码](../../Exercise/backtrack_algorithm&search/P_4667_BalticOI_2011_Switch_the_Lamp_On_Day_1.py)

电流沿每个方格的对角线走，所以这题搜索的位置是方格的顶点。$n\times m$ 个元件对应 $(n+1)\times(m+1)$ 个格点，起点是 `(0,0)`，终点是 `(n,m)`。格点坐标允许取到 `n` 和 `m`，元件数组的下标却只能取到 `n-1` 和 `m-1`。

从格点 `(x,y)` 到 `(nx,ny)` 时，经过的元件左上角就是 `(min(x,nx), min(y,ny))`。四个移动方向与所需导线的关系是：

| 格点移动 | 经过的元件下标 | 所需导线 |
|---|---|---|
| `(1,1)` | `(x,y)` | `\` |
| `(-1,-1)` | `(x-1,y-1)` | `\` |
| `(1,-1)` | `(x,y-1)` | `/` |
| `(-1,1)` | `(x-1,y)` | `/` |

下面摘录当前文件中枚举方向后的部分。先检查新格点是否合法，再读取中间元件；方向吻合就不用旋转，费用为 0，否则为 1。

```python
        nx = x + dx
        ny = y + dy
        if(nx <0 or nx > n or ny < 0 or ny > m):
            continue
        cur = g[min(x,nx)][min(y,ny)]
        if(cur == need[k]):
            w = 0
        else:
            w = 1
        nxt = dis[x][y] + w
        if(nxt >= dis[nx][ny]):
            continue
        dis[nx][ny] = nxt
```

这段对应关系理清以后，后面的队首、队尾入队规则和电车题相同。格点数量与边数都是 $O(nm)$，搜索时间和空间复杂度也都是 $O(nm)$。

每一步都同时改变横纵坐标各 1，因此 `x+y` 的奇偶性保持不变。起点的和为偶数，若 `n+m` 为奇数，就一定无法到达右下角，输出 `NO SOLUTION`。当前代码通过搜索结束后检查目标距离处理无解，没有单独添加奇偶判断。

这题还实际调整了读入方式：一次 `sys.stdin.buffer.read().split()` 读完数据，前两个字段转成 `n,m`，后面 `n` 段分别 `decode()` 成字符串。字符串下标仍然返回字符，与 `need` 中的斜杠类型一致，搜索代码可以保持原样。如果直接保留 `bytes`，单个下标返回的是整数，就必须连同后面的比较一起调整。

批量读入后，官方样例、边界用例和 300 组随机小图与 Dijkstra 的对拍都通过了。这里确认的是读入改动没有改变答案；本地运行时间不能直接代替评测机上的结果。

## P1294 高手去散步：每条当前路径都能成为答案

[源码](../../Exercise/backtrack_algorithm&search/P_1294_高手去散步.py)

这题可以从任意景点出发，在任意景点结束，要求同一个景点不能重复经过。我最初把答案更新放在“所有景点都访问过”的条件里，相当于额外要求路线覆盖整张图。题目并没有这个要求：一个有三个叶子的星形图，简单路径最多连接两个叶子，剩下的叶子不可能同时经过。

当前源码已经把 `ans = max(ans,total)` 放在 DFS 入口。下面是函数入口和完整的后续搜索部分：

```python
def dfs(cur,total):
    global vis
    global ans
    ans = max(ans,total)
    if(all(i==True for i in vis)):
        return

    for next_pos,add in g[cur]:
        if(vis[next_pos] ==True):
            continue
        vis[next_pos] = True
        dfs(next_pos,total + add)
        vis[next_pos] = False
```

每次进入函数，`total` 都是一条合法简单路径的长度，可以先更新答案，再尝试延长它。递归前标记下一景点，返回后恢复标记，让其他路径也有机会经过这个点。`vis` 表示的是当前递归路径上有哪些点，不能像普通 BFS 那样把一个点永久标记为已访问。

当前文件仍保留了“全部访问后返回”的判断，并将 `vis[0]` 设为 `True`。这个判断只是在没有新点可走时提前返回，不再限制答案更新的位置。`ans` 虽然仍初始化为负无穷，但只要枚举一个合法起点，入口处的 `total=0` 就会把它更新到至少 0。

讨论中的修正逻辑通过了样例和 800 组随机小图与状态压缩 DP 的对拍。不过枚举简单路径的搜索量最坏仍可能呈阶乘级增长，样例与小图对拍只检查答案，不能据此断言所有大图都能在时限内完成。

这题需要保留整条路径的访问信息。同一个 `cur`，如果已经经过的景点不同，后面还能走的路也不同；仅凭“到达这个点的总长度更大”去淘汰另一个状态，并不成立。
