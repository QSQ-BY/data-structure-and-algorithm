# 从逃离流星到瘟疫扩散：两道题里的 BFS 状态

今天连续写了 P2895 流星雨和 P1332 血色先锋队。它们都是网格 BFS，但出发点正好相反：P2895 只有一个起点，要赶在格子失效前逃出去；P1332 有多个感染源，要计算瘟疫最早什么时候到达每个位置。

写 P2895 时，我花了不少时间确认边界和状态是否合法。到了 P1332，多源 BFS 反而顺了很多。两道题放在一起看，我对“最早到达”这件事清楚了一些：队列只是维持搜索层次，真正决定结果的是状态含义、首次入队的条件和访问标记。

## P2895 流星雨：先算格子的截止时间

每颗流星会摧毁落点和四个相邻格。同一个位置可能被多颗流星影响，所以 `g[x][y]` 不能记录最后读到的时间，而要记录最早摧毁时间。当前代码分别处理中心格和相邻格：

```python
for (x,y,t) in pot:
    if(g[x][y] == -1):
        g[x][y] = t
    else:
        g[x][y] = min(g[x][y] , t)
    for (dx,dy) in directions1:
        nx = x + dx
        ny = y + dy
        if(nx<0 or ny<0):
            continue
        if(g[nx][ny] == -1):
            g[nx][ny] = t
        else:
            if(g[nx][ny] > t):
                g[nx][ny] = t
```

我一开始看到相邻格更新里已经写了 `min`，觉得这里应该没问题。后来顺着变量范围检查，才发现中心格原先是直接赋值，较晚到来的流星会覆盖较早的摧毁时间。问题不在“有没有写 `min`”，而在这段最小值更新到底覆盖了哪些格子。

预处理完成后，`-1` 表示永远安全，其余数值是进入该格子的截止时间。BFS 中到达下一格的时间是 `nt=t+1`，只有 `nt<g[nx][ny]` 才能进入；如果遇到 `g[nx][ny] == -1`，就找到了答案。

```python
while q:
    (x,y,t) = q.popleft()
    for (dx,dy) in directions2:
        nx = x + dx
        ny = y + dy
        nt = t + 1
        if(nx<0 or ny<0):
            continue
        if(g[nx][ny] == -1):
            ans = nt

        if(g[nx][ny] <= nt):

```

这里有两个让我停下来重新想的地方。最初只写向右和向上，会漏掉必须向下绕行的合法路径；补成四方向后，又忘了检查负坐标。Python 会把 `g[0][-1]` 当成最后一列，程序因此把不存在的格子认成安全位置，连样例都输出了 `1`。

一开始我还没有使用标记数组visited，从出队搜索顺序看确实没问题，但如果没有 `visited`，程序枚举的是一条条走法，而不是一个个不同的坐标。加入四方向后，甚至可以从相邻格绕回起点。一个格子第一次入队时已经取得最短到达时间，立刻标记才能把搜索规模控制在 $O(XY)$；流星预处理另需 $O(M)$。

## P1332 血色先锋队：所有感染源同时出发

P1332 不需要为每位领主单独跑一遍 BFS。把所有感染源都以时间 `0` 放进同一个队列，扩散到某个格子的第一刻，就是它到最近感染源的曼哈顿距离。

```python
n,m,cnt,q = read()
queue = deque()
g = [[-1]*(m+2)for _ in range(n+2)]#用-1表示还没被访问
for i in range(cnt):
    x,y = read()
    queue.append((x,y))
    g[x][y] = 0

directions = [ 
    (1,0),(0,1),(-1,0),(0,-1)
]
while queue:
    (cur_x,cur_y) = queue.popleft()
    for (dx,dy) in directions:
        nx = cur_x + dx
        ny = cur_y + dy
        if(nx<1 or nx>n or ny<1 or ny>m):
            continue
        if(g[nx][ny] == -1):
            g[nx][ny] = g[cur_x][cur_y] + 1
            queue.append((nx,ny))
```

这里的 `g` 同时承担访问标记和感染时间。所有源点先写成 `0`，之后只有 `g[nx][ny] == -1` 的位置能够入队。因为队列按时间逐层扩展，一个格子第一次被感染时，不可能还有更近的感染源尚未处理。整张地图只需要遍历一次，领主的位置随后直接查表即可。

设地图大小为 $n\times m$，感染源有 $a$ 个，询问有 $b$ 个，时间复杂度是 $O(nm+a+b)$，空间复杂度是 $O(nm)$。题面样例输出 `3、1、3`，我又测试了单个源点下距离分别为 `0、1、2` 的三个位置，结果一致。

## 两种“最早到达”

P2895 中，BFS 的时间要和格子的摧毁时间比较，搜索目标是第一个永远不会失效的位置；P1332 中，BFS 本身就在生成每个格子的最早感染时间。一个是在截止时间之前移动，一个是让多个源点共同向外扩散。

它们共用的部分也很明确：四方向必须先过边界检查，第一次入队就是最短时间，访问标记应在入队时完成。下次遇到网格传播题，我会先写清楚 `g[x][y]` 究竟表示“最早到达时间”“最晚进入时间”，还是单纯的访问状态，再决定队列里需要保存什么。
