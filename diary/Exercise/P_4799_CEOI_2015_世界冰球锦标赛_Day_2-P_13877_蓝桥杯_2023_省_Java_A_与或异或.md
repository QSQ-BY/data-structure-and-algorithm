# 从子集枚举到折半搜索，再看门电路的状态枚举

2026 年 9 月 14 日

今天练了 P4799 世界冰球锦标赛和 P13877 与或异或。前一题从普通 DFS 加剪枝写到折半搜索，后一题直接枚举十个门的类型。两题放在一起，正好让我重新梳理：一次递归调用表示什么，什么时候已经得到一个完整方案，以及这个搜索规模到底能不能枚举。

## P4799：选完最后一场以后，递归参数是什么

[源码](../../Exercise/backtrack_algorithm&search/P_4799_CEOI_2015_世界冰球锦标赛_Day_2.py)

这题给出最多 40 场比赛的票价和预算，统计总价不超过预算的子集数量。我最初沿用了 `index` 保存所选下标、`calculate()` 遍历求和的写法，用 `dfs(min, max)` 枚举下一场选哪一场。

讨论时，我问过：选中最后一场比赛时，为什么递归不是 `dfs(n-1, n-1)`？把“刚选了谁”和“接下来从哪里选”分开以后，这个问题就清楚了。循环里的 `number` 是刚选中的下标，递归传的是 `number+1`。选了最后一场后，`index` 已经包含下标 `n-1`，下一次调用自然是 `dfs(n, n-1)`。

因此，这种递归树里的每个节点都对应一个子集。即使已经没有下一场可选，当前子集仍然需要统计；第一次调用对应的空集也在其中，不需要最后再补一个 1。这和之前 [P12266 的子集统计](P_8801_蓝桥杯_2022_国_B_最大数字-P_12266_蓝桥杯_2024_国_Python_B_不同的总分值.md)是同一个问题，答案的位置取决于节点的含义。

## 剪枝能省掉哪些分支

票价都是正数，可以先排序。如果当前总价加上 `price[number]` 已经超预算，后面的比赛更贵，直接 `break` 就行。

我还加了另一种判断：如果剩下的比赛全部买得起，就直接统计它们的所有子集。对闭区间 `[min, max]`，剩余票价之和是 `suffix[min] - suffix[max+1]`；一共有 `max-min+1` 场，每场独立选或不选，可以一次增加 $2^{max-min+1}$。这个数已经包含“不再选任何比赛”，不能先统计当前子集再重复加一次。

但剪枝并没有消除最坏情况下的指数规模。40 场票价都是 1、预算为 20 时，既有很多买得起的组合，也无法在搜索前期把剩余部分整体计数。仅从前 39 场选出 20 场，就有 $\binom{39}{20}=68\,923\,264\,410$ 种，普通 DFS 仍然要访问大量节点。换成 C++ 可以减少单次调用的开销，搜索量本身不会因此缩小。

## 折半搜索：保存总价，再统计搭配数量

我后来把比赛分成两半，每半最多 20 场，各自枚举所有合法子集的总价。需要保存的子集总数从 $2^{40}$ 降到最多 $2^{20}+2^{20}$。

每个完整观赛方案都能唯一拆成一个左半子集和一个右半子集，因此左右两边只需要按总价配对。这里不能再用两层循环枚举所有配对，否则又会回到 $2^{40}$ 的规模。

当前 `test02()` 中的枚举核心如下，省略了外层变量初始化和函数末尾的 `return`：

```python
    def dfs(min,max,sums):
        nonlocal current_sum
        result = current_sum
        if(result > m):
            return
        sums.append(result)
        if(min>max):
            return
        for number in range(min,max+1):
            if(result + price[number] > m):
                break
            index.append(number)
            current_sum += price[number]
            dfs(number+1,max,sums)
            current_sum -= price[number]
            index.pop()
```

`sums` 记录这一半的子集总价，合法节点一进入就追加，所以包含空集的 0，也包含选到最后一场的方案。两次枚举都从空路径开始；每次加入票价以后，递归返回时再减掉，`current_sum` 始终等于 `index` 中已选比赛的总价。整轮搜索结束后，路径和总价都恢复为空、零。

这也是当前文件与最初版本的一处变化：我不再在每个节点重新遍历 `index` 求和，而是在选择和撤销时维护总价。`index` 仍保留着，便于对照回溯过程。原来的带后缀和剪枝的 DFS 留在 `test01()`，程序入口调用的是折半搜索 `test02()`。

折半枚举时不能照搬“剩余全部买得起就增加一个方案数”的剪枝。后面还要根据总价决定怎么搭配，必须保留各个子集的总价及出现次数，只有总数量是不够的。

两半枚举完以后，源码这样合并答案：

```python
    mid = n//2
    left = []
    right = []
    dfs(0,mid-1,left)
    dfs(mid,n-1,right)
    right.sort()
    ans = 0
    for s in left:
        #返回right中第一个值严格大于m-s的下标
        ans += bisect_right(right,m-s)
    print(ans)
```

左半花了 `s`，右半就只能花不超过 `m-s`。我专门追问了 `bisect_right` 这一行，后来把它的两层含义对应起来了：在升序列表中，第一个严格大于目标值的下标，也就是小于等于目标值的元素个数。

| 调用 | 返回的边界下标 | 同时表示的数量 |
|---|---|---|
| `bisect_left(a, x)` | 第一个 `>= x` 的位置 | `< x` 的元素个数 |
| `bisect_right(a, x)` | 第一个 `> x` 的位置 | `<= x` 的元素个数 |

例如右半总价排成 `[0, 2, 5, 6, 6, 9]`，剩余预算是 6，`bisect_right` 返回 5，意味着当前左半子集可以搭配五种右半方案。

相同总价不能去重。两个 6 可能来自不同的比赛组合，应该分别计数；左半重复的总价同样要分别参与累加。两边的 0 则让“只选一半”和“一场都不看”都能自然组合出来。

设较大的一半有 $k=\lceil n/2\rceil$ 场。当前枚举阶段维护总价，每半最多生成 $2^k$ 个子集；右半排序、逐个左半总价做二分，合起来的时间复杂度为 $O(k2^k)$，空间复杂度为 $O(2^k)$。

## P13877：枚举的是门的类型，输出沿层次计算

[源码](../../Exercise/backtrack_algorithm&search/P_13877_蓝桥杯_2023_省_Java_A_与或异或.py)

这题输入固定为 `1,0,1,0,1`，每个门可以选择与、或、异或，要求最终输出为 1。四层分别有 4、3、2、1 个门，总共十个位置，只有 $3^{10}=59049$ 种组合，可以完整枚举。

我的实现先在 `op` 中填好门的类型，再调用 `calculate()` 自上而下计算节点值。源码中的搜索部分是：

```python
def dfs(layer,index):
    if(layer >= 4):
        calculate()
        return
    for operation in operations:
        op[layer][index] = operation
        if(layer + index == 3):
            dfs(layer + 1,0)
        else:
            dfs(layer,index + 1)
```

第 `layer` 层有 `4-layer` 个门，最后一个门的下标是 `3-layer`，所以 `layer+index==3` 时转入下一层。到 `layer==4` 时，十个门都已经确定，这才是一份完整的门电路方案，可以计算输出。

这里的统计位置和 P4799 不一样。P4799 的当前路径已经能表示一个合法子集；P13877 中还没填完的 `op` 只是半成品，必须等全部位置确定以后才能判断。

计算节点值时，我把输入层与门的层号分开看：

| 已有节点 | 使用的门 | 计算出的节点 |
|---|---|---|
| `In[0]`，5 个输入 | `op[0]`，4 个门 | `In[1]`，4 个输出 |
| `In[1]` | `op[1]` | `In[2]`，3 个输出 |
| `In[2]` | `op[2]` | `In[3]`，2 个输出 |
| `In[3]` | `op[3]` | `In[4]`，1 个输出 |

因此，计算 `In[i][j]` 要使用 `op[i-1][j]`，输入来自 `In[i-1][j]` 和 `In[i-1][j+1]`，这一行共有 `5-i` 个输出。不同门的组合即使暂时得到相同的节点值，也仍是不同的电路方案，不能因为输出相同就少计。

搜索中没有把 `op[layer][index]` 清空，因为下一次选择会覆盖当前位置，而每次调用 `calculate()` 前所有门都已重新确定。中间节点也会按照层次重新计算，不依赖上一种方案残留的输出。

对每个组合计算十个门，计算量约为 $10\times3^{10}$ 次门运算。当前程序输出 `30528`，用独立的逐层状态计数核对也得到相同结果，全部组合数为 59049。
