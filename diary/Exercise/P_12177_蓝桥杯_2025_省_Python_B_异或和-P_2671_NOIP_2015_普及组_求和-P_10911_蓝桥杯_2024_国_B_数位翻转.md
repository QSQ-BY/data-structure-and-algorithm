## P12177 异或和：相反位的数量与下标和已经够用

[源码](../../Exercise/math/P_12177_蓝桥杯_2025_省_Python_B_异或和.py)

题目对一对位置的贡献带有异或值和位置距离。我按二进制位拆开异或，固定第 k 位后，只有该位不同的位置才能产生 2^k 的贡献。

 扫描右端点 j 时，前面相反位的位置 i 带来的距离总和为 j·数量-下标和。因此每一位只维护两类数量和下标和：

```python
for k in range(21):#逐位进行处理
    cnt = [0,0]
    sum = [0,0]
    for j,x in enumerate(arr):
        b = (x>>k)&1
        opposite = 1^b

        #当前数字与前面的数字在第k位产生的贡献
        distance_sum = j*cnt[opposite] - sum[opposite]
        ans += distance_sum * (2**k)
        #统计当前数字供后面的数字使用
        cnt[b] += 1
        sum[b] += j
```

先查询再加入当前元素，保证只统计 i<j，每对位置只处理一次。源码中的 sum 列表就是两类位置的下标和。

 按值域需要的 B 位处理，时间 O(nB)。除了原数组，每一位只用常数个计数器，无需保存历史位置列表。带距离权重的求和在展开以后，可以由数量和下标和直接表达。

## P2671 求和：中点由端点决定，组内贡献可以展开

[源码](../../Exercise/Ad-hoc/P_2671_NOIP_2015_普及组_求和.py)

原来的枚举围绕中点和距离展开，修正枚举后仍要面对 O(n²) 的规模。我在对话里专门问了如何解决 TLE。

 等距三元组的中点是 (i+j)/2。因此端点颜色相同、编号奇偶相同，就对应一个合法中点；中点本身不用再枚举。按颜色和奇偶性分组，维护数量 k、编号和 si、数字和 sa、编号乘数字和 sia，最后这样计算：

```python
    g = groups[key]
    g[0] += 1#k，位置数量
    g[1] += i#si，编号之和
    g[2] += a#sa,数字之和
    g[3] += i*a#sia，编号乘以数字之和
ans = 0
for k,si,sa,sia in groups.values():
    ans += (k-2)*sia + si*sa
print(ans%MOD)
```

对一组展开 (i+j)(a_i+a_j)。自身项 i·a_i 在所有无序对里出现 k-1 次；交叉项来自 si·sa，再减去其中的自身项 sia，所以贡献为 (k-2)·sia+si·sa。

 每个位置只进入一个组，字典操作按平均常数时间估计，总时间 O(n)，空间 O(n)。推导时使用题目从 1 开始的编号，不能把数组下标直接代入评分公式。

## P10911 数位翻转：连续区间的负收益必须一起承担

[源码](../../Exercise/dynamic_programming/P_10911_蓝桥杯_2024_国_B_数位翻转.py)

先计算每个数翻转后的增量 gain。原先把若干高收益区间放进堆里挑选，无法保证它们互不相交；在区间中跳过负收益位置，也破坏了连续性。

 对话里先采用 dp 与 end 两张表，后来我又问能不能只保留 end。end 记录最后一段恰好在当前位置结束时的收益，上一行的前缀最优值则用 best 维护。当前文件里的核心转移如下：

```python
for k in range(1, limit + 1):
    best = 0
    for i in range(1, n + 1):
        # 恰好选 k-1 个区间，且结束位置不超过 i-1
        best = max(best, end[k - 1][i - 1])

        # 延续第 k 个区间，或从当前位置新开第 k 个区间
        end[k][i] = max(end[k][i - 1], best) + gain[i - 1]
```

两种转移分别是延续上一位置的区间，以及从当前位置新开区间，两者都要加上 gain[i-1]，所以中间的负收益不能随意跳过。

 我随后又问能否把“最多选 k 段”改成“恰好选 k 段”。转移形式可以保留，但初始化必须一起变化：不可达状态和每行的 best 要设为负无穷，只用 end[0][0]=0 启动。最后题目仍允许最多 m 段，要比较 k=0 到 m 的所有情况。

 当前源码的 end 全部初始化为 0、best 也从 0 开始，因此这里按“最多”理解其实际行为；不能只把注释改为“恰好”就当成完成了状态转换。时间、空间均为 O(nm)，最终答案还要加回原数组总和。
