## P1435：两端字符决定下一步缩掉哪一边

[源码](../../Exercise/dynamic_programming/P_1435_IOI_2000_回文字串.py)

给字符串插入尽量少的字符，使它变成回文串。我用 `dp[left][right]` 表示把闭区间 `[left,right]` 变成回文串所需的最少插入次数。只剩一个字符时已经是回文，答案为零。

两端字符相同，可以让它们互相匹配，继续处理内部区间；两端不同，就给其中一端补一个相同字符，把它配对后留给更短的区间处理。当前实现按区间长度递增：

```python
for length in range(2,n+1):
    for left in range(n - length + 1):
        right = left+ length - 1
        if(string[left] == string[right]):
            if(length == 2):
                dp[left][right] = 0
            else:
                dp[left][right] = dp[left+1][right - 1]

        elif(string[left] != string[right]):
            dp[left][right] = min(
                dp[left+1][right],
                dp[left][right-1],
            ) + 1
```

`dp[left+1][right]+1` 对应在右侧补一个与左端相同的字符；另一个分支则在左侧补上右端字符。两种选择都要计入这次插入的代价，再比较哪种更少。

这里我需要记清楚长度为二的边界：两个相同字符中间是空区间，不直接读取尚未定义的 `dp[left+1][right-1]`，而是赋零。更长的区间只依赖长度减一或减二的状态，因此先枚举长度，依赖就已经算好。

样例 `Ab3bd` 的答案为二，可以补成 `dAb3bAd`。大小写仍是不同字符，不能在输入时统一大小写。当前二维实现的时间、空间复杂度都是 `O(n²)`。

## P1564：固定最后一个机房，前面的同学交给已算好的状态

[源码](../../Exercise/dynamic_programming/P_1564_膜拜.py)

每个机房只能接收连续的一段同学。合法条件有两个：这一段只膜拜同一位神牛，或者两类同学的人数差不超过 `m`。

我把 `dp[i]` 定义成前 `i` 位同学最少需要的机房数。固定这段前缀后，枚举最后一个机房从哪里开始：若它接收下标 `[j,i-1]`，剩下的前 `j` 位同学就由 `dp[j]` 负责，总数是 `dp[j]+1`。

下面摘录内层枚举；外层每处理一个新的 `i`，都会先把 `count1`、`count2` 清零：

```python
    for j in range(i-1,-1,-1):
        if(arr[j] == 1):
            count1 +=1 
        else:
            count2 += 1
        if(count1 == 0 or count2 == 0 or abs(count1 - count2) <= m):
            dp[i] = min(dp[i],dp[j] + 1)
```

`j` 向左移动时，每次只增加一位同学，区间人数可以直接累计，不必重新统计。`dp[0]=0` 对应没有同学时不需要机房，也让“前 `i` 位全部放进一个机房”的方案自然进入转移。

这里不能只判断人数差。比如 `m=0` 时，连续五位同学都膜拜甲，依然可以住同一个机房，所以“某一类人数为零”必须单独保留。

我还要留意枚举时不能遇到不合法区间就提前停下。假设 `m=0`，从右往左加入的类别依次为 `1、2、2、1`，中间会从人数相等变成不等，继续扩展后又相等。区间是否合法没有这种单调性，不能套用越长越不合法的直觉。

枚举右端点和左端点一共 `O(n²)` 次，判断每段只需常数时间，DP 和输入数组占 `O(n)` 空间。

## P2858：剩余区间的长度已经包含了天数

[源码](../../Exercise/dynamic_programming/P_2858_USACO_06_FEB_Treats_for_the_Cows_G_S.py)

每天从两端选一份零食卖掉，售价是初始价值乘当天的天数。无论之前怎么选，剩下的零食一定仍是原序列的一段连续区间，因此可以用 `dp[left][right]` 表示：剩下这段零食时，从当前天开始全部卖完的最大收益。

若原来有 `n` 份，当前剩下 `length` 份，就已经卖掉 `n-length` 份，下一份在第 `n-length+1` 天卖。天数能由区间长度推出，不需要再加一维状态。

源码先把单点区间初始化为 `dp[i][i]=arr[i]*n`，因为只剩一份时已经到了最后一天。随后这样转移：

```python
for length in range(2,n+1):
    day = n - length + 1
    for left in range(n - length + 1):
        right = length + left - 1
        dp[left][right] = max(
            arr[left]*day + dp[left+1][right],
            arr[right]*day + dp[left][right - 1]
        )
```

每个状态只有卖左端、卖右端两种选择，但今天的收入后面还接着一整个子问题。只看两端哪个价值小，无法直接决定哪个应该先卖，还要考虑这次选择会让哪些零食暴露到端点。

虽然填表时先算短区间，实际出售却从完整区间开始。这里的计算顺序是在先求未来的最优收益，然后回过头比较当前两种选择，并不是在模拟出售时间。`dp[0][n-1]` 对应第一天开始的完整问题，样例的最优收益为 `43`。

这份实现的时间、空间复杂度都是 `O(n²)`。复习时我会先确认“状态表示剩余部分的未来收益”，再看 `day=n-length+1` 和单点区间乘 `n`，这样两处定义能对得上。
