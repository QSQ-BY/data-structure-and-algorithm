## P2678：固定最短跳距后，贪心保留尽量靠前的石头

[源码](../../Exercise/binary_search/P_2678_NOIP_2015_提高组_跳石头.py)

NOIP 的跳石头要求移走至多 M 块石头，让最短跳距尽量大。我二分最短跳距 l，再计算至少需要删掉多少块石头。当前源码先把起点、各石头、终点之间的距离存进 `diff`。

```python
def check(l):
    cur = 0
    cnt = 0
    for d in diff:
        cur += d
        if cur < l:
            # 目前距离还不够
            # 必须继续和下一段合并
            # 相当于删掉一块石头
            cnt += 1
        else:
            # 已经凑出一个 >= l 的跳跃距离
            cur = 0
        if cnt > m:
            return False

    return True
```

`cur` 是从上一次保留的落脚点开始积累的距离。距离还不够，就跳过当前石头，把它和下一段合并；一旦达到门槛，就保留这个尽量靠前的落脚点并清零。保留位置越靠前，留给后面的位置越多。

最后一段也参与统计。如果到终点仍不足 l，计数增加一次应理解为删除前一块保留的中间石头，把末尾两段合并；终点本身不能删。此前完整一段已不短于 l，合并后仍合法，因此这种计数方式不需要另写终点分支。

门槛越高，所需删除数不会减少。这里找最大可行值，二分采用上取整中点；一次判定 O(N)，总时间 O(N log L)，保存间距用 O(N) 空间。没有中间石头时，`diff` 只有整段河宽 L，也能进入同一套判断。

## P8775：往返次数变成每个长度 y 窗口的容量要求

[源码](../../Exercise/binary_search/P_8775_蓝桥杯_2022_省_A_青蛙过河.py)

青蛙过河里，石头高度表示还能被使用多少次。上学 x 天要过河 2x 次；固定跳跃能力 y 后，我检查每段连续 y 个河内位置的高度和是否至少为 2x。

必要性来自一次跳跃的跨度：要完全跨过连续 y 个位置，需要至少跳 y+1。因此每次过河都必须在这段里使用至少一块石头，2x 次过河至少消耗 2x 份高度。

```python
def check(y):
    """
    跳跃能力为 y 时，
    能不能完成 2*x 次过河
    """
    # 检查所有连续 y 个位置
    for i in range(y, n):
        # 区间 [i-y+1, i]
        total = prefix[i] - prefix[i - y]
        if total < 2 * x:
            return False
    return True
```

前缀和让每个窗口 O(1) 求和，一次判定 O(n)。当 y=n 时，可以直接从岸跳到对岸，河内没有需要检查的完整窗口，判定自然为真。

这个条件也足够。令 q=2x，先把每块石头的容量截到 q；窗口和至少为 q 的性质不会改变。把各石头的可用次数从左到右展开，循环标上 1 到 q 的编号。每个窗口至少包含一整轮编号，因此每个编号都能在每段长度 y 的窗口中找到落脚点，同一编号的相邻落脚点距离就不会超过 y，首尾到岸的距离也满足要求。

每个编号对应一次过河，反向使用同一条路径即可安排返程；同一块石头总共分配的次数不超过它的高度。这说明窗口容量条件不仅是下界，还能构成完整的过河安排。

随着 y 增大，可行性只会放宽，二分最小可行值，总时间 O(n log n)、空间 O(n)。这题我主要保留的是判定条件的充分性，不能只因为“每个窗口都够用”就省略整条路径能否接起来的解释。

## P11005：一条边合并两个连通块时，新增的是两边大小的乘积

[源码](../../Exercise/graph_theory/P_11005_蓝桥杯_2024_省_Python_B_缴纳过路费.py)

缴纳过路费把路径代价定义成沿途最大边权，再对两点间所有路径取最小值。固定门槛 W 后，两点的最低代价不超过 W，等价于它们在只保留权值不超过 W 的边时连通。

我把边按权值从小到大加入并查集。两个原本独立、大小分别为 a 和 b 的连通块首次合并时，新增 a×b 对可达点对，它们的最小瓶颈值就是当前边权。

```python
for (w,u,v) in edges:
    if(w > r):
        break
    root_u = s.find(u)
    root_v = s.find(v)
    if(root_u == root_v):
        continue
    if(l<=w<=r):
        ans += s.size[root_u]*s.size[root_v]
    s.merge(root_u,root_v)
```

权值小于 l 的边虽然不直接贡献答案，也必须合并，因为它们决定后续连通块的大小。权值落在 `[l,r]` 时才累加乘积；超过 r 后可以停止。已经在同一连通块中的边不会产生新点对。

同权边逐条处理也可以：点对在本轮中只会首次连通一次，这一轮所有贡献都对应相同的瓶颈值。这个实现相当于直接统计区间内新增的连通点对，也可以理解成 F(r)-F(l-1)。

排序花费 O(M log M)，并查集操作总共 O(Mα(N))，存储 O(N+M)。我记下这题，是因为“路径最大边最小”在门槛固定后直接变成了连通性，不必为每对城市跑一次最短路。
