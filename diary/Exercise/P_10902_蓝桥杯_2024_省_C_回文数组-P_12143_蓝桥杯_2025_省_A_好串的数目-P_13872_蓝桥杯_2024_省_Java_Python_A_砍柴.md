## P10902：把回文条件写成对称位置的差

[源码](../../Exercise/greedy_algorithm/P_10902_蓝桥杯_2024_省_C_回文数组.py)

回文数组要求每对对称位置相等。单个数可以加减 1，也可以让相邻两个数一起加减 1。我把外侧和内侧两对位置的差放在一起看：只有两对差同号时，才有机会用一次双点操作同时减少两个差。

当前代码用左右指针向中间推进，下面摘录同号差的处理：

```python
    number1,number2,number3,number4 = arr[left],arr[left + 1],arr[right-1],arr[right]
    if(number1 > number4 and number2 > number3):
        gap = min(number1 - number4,number2 - number3)
        ans += gap
        arr[right] += gap
        arr[right - 1] += gap
    elif (number1 < number4 and number2 < number3):
        gap = min(number4 - number1,number3 - number2)
        ans += gap
        arr[left] += gap
        arr[left + 1] += gap
```

左边连续两个数都比各自的对称位置大，就把右边相邻两个数一起加；都小就把左边一起加。批量操作次数取两个差的较小值，做完后至少有一对相等。差异方向相反时，这种共享操作不能同时改善两对，先单独解决最外侧。

例如 `[1,2,3,4]` 的两对差分别是 -3、-1，共享一次加法后内侧配平，外侧还剩两次单点操作，总共三次。单独处理则需要四次。

同号差的共享部分先用在最外侧，不会损失后续可节省的次数：若把这部分机会留给更内侧的一对，每单位也至多省一次；把共享操作向外交换，可以先让当前外侧退出。当前实现每次要么移动指针，要么把相邻的一对差清零，因此总时间 O(n)。我把这题留下来，是为了复习贪心时能说清楚“一次操作同时减少了哪两份差”。

## P12143：能切成两段，等价于内部最多有一个断点

[源码](../../Exercise/greedy_algorithm/P_12143_蓝桥杯_2025_省_A_好串的数目.py)

好串中的每一段要求相邻数字相等，或后一位恰好大 1。于是，我把不满足这条关系的相邻位置叫作断点。一个子串可以切成两个这样的段，当且仅当内部最多有一个断点。

零个断点时，长度至少二的串任选一个位置切开即可；一个断点时就在断点处切；两个以上断点时，一次切分无法全部隔开。单字符按照题意单独合法。

右端点加入新字符时，代码先检查新出现的那条相邻边。下面摘录窗口收缩和计数：

```python
    while bad_cnt > 1:

        x = int(s[left])
        y = int(s[left + 1])

        if not (y == x or y == x + 1):
            bad_cnt -= 1

        left += 1

    # 所有以 right 结尾、起点 >= left 的子串都是好串
    ans += right - left + 1
```

`bad_cnt` 统计的是窗口内部的坏边。左端点右移时，移出去的是 `s[left] -> s[left+1]` 这条边，必要时把断点数减一。

窗口恢复合法后，以 right 结尾、起点在 `[left,right]` 的子串都合法，直接增加 `right-left+1`。左右端点各自只向右走，时间 O(n)，除字符串外只用常数个变量。

这题我想记住的是把“枚举切分点”转成“数相邻关系的例外”。一旦合法条件变成窗口里至多一个断点，就不用真的尝试每一种切法。

## P13872：从所有必败状态向后标记必胜状态

[源码](../../Exercise/Ad-hoc/P_13872_蓝桥杯_2024_省_Java_Python_A_砍柴.py)

砍柴每次可以减去一个不超过当前长度的质数，轮到 0 或 1 时无法行动。`dp[x]` 表示当前玩家面对长度 x 时是否必胜，只要存在一个合法动作能把对方送到必败状态，x 就是必胜。

源码先筛出质数，再按长度从小到大处理。这里用了反向标记：遇到必败的 x，就把所有 x+p 标成必胜，因为它们可以减去质数 p 到达 x。

```python
for x in range(maximum + 1):
    # 只有必败状态才需要向后标记
    if dp[x] == 0:
        for p in primes:
            if x + p > maximum:
                break
            dp[x + p] = 1
```

处理到 x 时，所有更小状态已经确定；若 x 仍未被任何必败前驱标记，说明它的每个合法后继都是必胜态，因此 x 必败。这个判断依赖“每次长度严格减小”，状态之间不会形成环。

0、1 是初始必败态，但后续发现的必败态也必须继续向外标记。例如 9 也是必败：减去 2、3、5、7 后得到 7、6、4、2，都是对手的必胜状态。

设预处理上界为 M。筛法为 O(M log log M)，标记部分的工作量是对每个必败 x 枚举不超过 M-x 的质数，不能直接算成 O(M)。预处理后每个询问 O(1)，数组和质数表共用 O(M) 空间。我在这里保留的是状态判定的归纳顺序，以及从必败态推出必胜态的方向。
