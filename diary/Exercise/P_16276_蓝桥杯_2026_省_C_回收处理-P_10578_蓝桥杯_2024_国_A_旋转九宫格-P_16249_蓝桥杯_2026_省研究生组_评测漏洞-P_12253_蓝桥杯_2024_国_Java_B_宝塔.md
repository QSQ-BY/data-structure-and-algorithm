## P16276 回收处理：固定分界线以后，两边分别选最优

[源码](../../Exercise/greedy_algorithm/P_16276_蓝桥杯_2026_省_C_回收处理.py)

从 $3n$ 个部件中选出 $n$ 个回收、$n$ 个处理，目标是让回收收益减去处理成本尽可能大。所有回收部件都必须在处理部件前面，这个顺序限制不能在排序时丢掉。

源码保留了两种做法。`test01()` 按下标递增枚举 $2n$ 个部件，前一半算收益，后一半算成本。它能表达题意，但需要枚举 $\binom{3n}{2n}$ 种选择，每次还要计算总分，只适合小规模。当前调用的是双堆版本 `test02()`。

我把分界线放在下标 `i` 前面：回收部件从 `arr[:i]` 中选，处理部件从 `arr[i:]` 中选。两侧都至少需要 $n$ 个候选，因此只需枚举 $n\le i\le 2n$。

- `left[i]` 是前 `i` 个部件中最大的 $n$ 个价格之和。
- `right[i]` 是从 `i` 开始的后缀中最小的 $n$ 个价格之和。

答案就是 $\max(left[i]-right[i])$。任意合法方案都能找到这样一条分界线；固定分界线后，两组不再争抢同一个位置，可以独立优化。

下面摘录维护左侧候选集合的代码，省略了前面的堆初始化：

```python
    s = sum(heap)
    left[n] = s
    for i in range(n,2*n):
        removed = heapq.heappushpop(heap,arr[i])
        s += arr[i] - removed
        left[i+1] = s
```

小根堆始终保留最大的 $n$ 个数。加入新价格时，`heappushpop` 移除候选中的最小值，再用“加入值减去移除值”更新总和。右侧需要保留最小的 $n$ 个数，代码将价格取负后放进小根堆，相当于维护一个大根堆。

两次扫描加一次分界线枚举，时间复杂度为 $O(n\log n)$，空间为 $O(n)$。这题值得记下的是：遇到两组元素必须前后分开的条件，可以先枚举它们之间的界线，再考虑每一侧怎样选。

## P10578 旋转九宫格：从终点出发，要沿反向边搜索

[源码](../../Exercise/backtrack_algorithm&search/P_10578_蓝桥杯_2024_国_A_旋转九宫格.py)

每一步只能把某个 $2\times2$ 区域顺时针旋转，要求到达 `123456789` 的最少步数。询问很多，目标状态却固定，所以当前代码从目标预处理一次 BFS，之后直接查表。

这里的方向需要单独想清楚。正向操作是顺时针旋转，反向 BFS 就要使用逆时针旋转，才能得到“每个状态到目标”的距离。如果从目标仍然顺时针走，得到的是目标到各状态的距离，有向图中这两个距离不一定相同。

源码中四个区域的反向置换是：

```python
rotate = {
    (0,1,3,4) : (1,4,0,3),
    (1,2,4,5) : (2,5,1,4),
    (3,4,6,7) : (4,7,3,6),
    (4,5,7,8) : (5,8,4,7),
}
```

字典的键表示需要修改的位置，值表示这些位置的新数字分别从哪里取。例如左上区域原来是上排 `a b`、下排 `c d`，应用第一条映射后变成上排 `b d`、下排 `a c`，正是逆时针旋转。

棋盘压成长度为 9 的字符串，距离字典 `s` 同时承担判重。每次生成新布局，先检查是否访问过，再记录距离并入队。所有边的代价都是 1，第一次到达就是最短距离。

样例中，目标棋盘旋转右上角一次得到的布局，需要再顺时针旋转三次才能回去，输出是 `3`。这个例子也能检查反向搜索有没有把方向弄反。状态数量最多为 $9!$，每个状态只有四种操作，字符串长度又固定，预处理时间和空间都可以记为 $O(9!)$；每次查询只需构造状态并查表。

## P16249 评测漏洞：先化简条件，再统计前面出现过的数

[源码](../../Exercise/hash/P_16249_蓝桥杯_2026_省研究生组_评测漏洞.py) · [题面](https://www.luogu.com.cn/problem/P16249)

条件是 $(a_i+a_j)^2=a_i+a_j$。令 $t=a_i+a_j$，就有 $t(t-1)=0$，因此只需统计和为 0 或 1 的数对。

扫描到当前数字 `number` 时，与它配对的数字只能是 `-number` 和 `1-number`。代码用字典 `s` 保存此前每个数字的出现次数，把这两个频次加进答案，然后才登记当前数字。

这个先后顺序直接保证了 $i<j$。例如输入 `[0, 0]`，第一个 0 没有前驱可配，第二个 0 才贡献一次；如果先登记再查询，就会把自己也算进去。两个补数相差 1，不会因为两次查询而重复统计同一对。

样例 `[-1, 0, 1, 2]` 中，合法配对是 `(-1, 1)`、`(-1, 2)` 和 `(0, 1)`，答案为 `3`。在哈希操作平均为常数时间的假设下，整段扫描是 $O(n)$，字典空间为 $O(n)$。回看这题，我更想保留的是“字典只描述当前下标之前的部分”这个含义，更新位置也就随之确定了。

## P12253 宝塔：位掩码筛候选，扫描验证可见数量

[源码](../../Exercise/backtrack_algorithm&search/P_12253_蓝桥杯_2024_国_Java_B_宝塔.py) · [题面](https://www.luogu.com.cn/problem/P12253)

棋盘的每一行、每一列都要放入 1 到 5，不能重复；四周的提示还规定了从对应方向能看到多少座塔。源码先用行列约束限制填数，再在棋盘填满后检查四个方向。

`row_state[x]` 和 `column_state[y]` 中的 1 表示仍可使用的高度。填到 `(x,y)` 时，两者按位与，就得到这个格子的候选集合。下面是当前搜索的一段，省略了前面的终止判断和后面的候选位移除：

```python
    x,y = divmod(pos,5)
    cur_state = row_state[x] & column_state[y]
    temp = cur_state
    while temp:
        bit = -temp&temp
        next_number = bit.bit_length()
        ans.append(next_number)
        g[x][y] = next_number
        row_state[x] ^= bit
        column_state[y] ^= bit
        if(dfs(pos+1,row_state,column_state)):
            return True
        row_state[x] ^= bit
        column_state[y] ^= bit
        g[x][y] = 0
        ans.pop()
```

`-temp & temp` 取最低的有效位，`bit_length()` 把它转成 1 到 5 的高度。候选位原本为 1，第一次异或把它清除，表示这一行和这一列已经使用这个高度；分支失败后再异或一次，恢复原状态。棋盘和答案列表也要一起恢复。

检查可见数量时，沿某个方向扫描，维护此前最高的塔。只有当前高度严格超过最高值，才会多看到一座。这比比较相邻两座塔更准确：即使比前一座高，也可能被更早的一座高塔挡住。

当前实现把可见数检查放在填满之后，时间取决于回溯实际访问的节点数，每个完整棋盘需要 $O(n^2)$ 的验证；它仍是指数级搜索。位掩码、棋盘和递归栈占用 $O(n^2)$ 空间。后续如果扩展规模，可以在一行填满时就检查左右提示，让冲突更早结束。
