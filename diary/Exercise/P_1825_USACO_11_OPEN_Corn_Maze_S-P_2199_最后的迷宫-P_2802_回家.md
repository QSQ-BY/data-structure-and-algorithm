# 三道迷宫题：传送、视线与血量状态

2026 年 9 月 5 日

今天的独立练习是 P1825、P2199 和 P2802，都是在网格里找最短路。把代码放在一起看，BFS 的队列和四方向移动基本没变，真正需要分别想清楚的是：走完一步后人在哪里，走到什么位置就算完成，以及同一个格子是否还需要再次搜索。

## P1825 Corn Maze：把强制传送合进一次移动

[源码](../../Exercise/backtrack_algorithm&search/P_1825_USACO_11_OPEN_Corn_Maze_S.py)

这题踩到传送点就必须传送，传送本身不耗时，而且落地后要先正常移动一步才能再次传送。我在代码里先用 `connect` 配对同字母的两个位置，再把“走向相邻格，以及可能发生的一次传送”合成一条转移。

下面是当前实现里检查下一状态的部分，省略了外围循环和入队代码：

```python
        # 先检查相邻格是否合法，此时不判断 visit
        if nx < 0 or nx >= n or ny < 0 or ny >= m:
            continue
        if g[nx][ny] == "#":
            continue
        # 踩到传送点，必须传送，只保留传送后的坐标，不可以选择不传送
        if connect[nx][ny] != (-1, -1):
            nx, ny = connect[nx][ny]
        # 对最终落点判重
        if visit[nx][ny]:
            continue
        visit[nx][ny] = True
```

这里的顺序很重要。先检查踩入的格子能不能走，再求出传送后的落点，最后对落点判重。队列里的坐标表示这一步全部结束后的位置，传送入口只是途中经过的地方。

到达落点后，下一轮仍然从四个相邻格开始扩展，不会原地再次触发传送。这样每条转移都恰好消耗一步，可以直接使用普通 BFS。预处理和搜索的时间、空间复杂度都是 $O(nm)$。

这题让我注意到，题面里出现零耗时操作时，可以先看它是不是某个动作必然附带的结果。这里把强制传送并入移动后，搜索图上的边权就统一了。

## P2199 最后的迷宫：终点是一批能看见奖杯的位置

[源码](../../Exercise/backtrack_algorithm&search/P_2199_最后的迷宫.py)

哈利只要看见奖杯就能拿到它，不需要走到奖杯所在的格子。视线有八个方向，移动却只有上下左右四个方向，这两个规则要分开处理。

我的实现先从奖杯向八个方向延伸，遇到墙或边界就停止，把沿途位置标记进 `can_see`。这相当于提前找出所有能结束搜索的位置。

```python
    can_see[target_x][target_y] = True
    for (dx,dy) in directions2:
        for stride in range(1,max(n,m) + 1):
            nx = dx*stride + target_x
            ny = dy*stride + target_y
            if(nx <=0 or nx>n or ny<=0 or ny>m):
                break
            if(g[nx][ny] == "X"):
                break
            can_see[nx][ny] = True
```

视线沿直线且不能穿墙，所以从奖杯向外标记，也就能确定哪些地方可以看回奖杯。如果起点已经在这些位置中，直接输出 `0`；否则从起点做四方向 BFS，第一次到达 `can_see` 中的位置就得到最短时间。

每个询问都重新建立可见集合和访问标记。八条射线的处理不超过 $O(n+m)$，BFS 最坏遍历整张地图，因此单次询问时间是 $O(nm)$，空间也是 $O(nm)$；有 $Q$ 次询问时，总时间为 $O(Qnm)$。当前代码用 `bytearray` 保存两份标记，避免为每个位置保存更重的对象。

回看这题，我更想记住“先确定什么状态算成功”这个步骤。把目标改成一个位置集合之后，后面的最短路搜索就很直接了。

## P2802 回家：相同位置，不同血量

[源码](../../Exercise/backtrack_algorithm&search/P_2802_回家.py)

我一开始把问题想简单了，visit 数组还是只保留了位置状态，但是这次位置还不足以描述状态。小 H 初始有 6 点血，每走一步扣 1 点，经过补给格可以回满。同样站在一个格子上，剩 1 点血和剩 6 点血，接下来能走的路显然不同。

所以代码用 `visit[x][y][hp]` 判重，队列保存 `(x, y, cur_hp, step)`。下面这段保留了扣血、补给和判重的实际顺序：

```python
        next_hp = cur_hp-1
        if(next_hp <= 0):
            continue
        if(g[nx][ny] == 0):
            continue
        if(nx <=0 or nx>n or ny<=0 or ny>m):
            continue
        if(g[nx][ny] == 4):
            next_hp = 6
        if visit[nx][ny][next_hp] == True:
            continue
        visit[nx][ny][next_hp] = True
```

先扣血并判断是否存活，再处理补给。题目规定，即使刚好走到补给格或家门口，只要血量已经降到 0，就不能补血，也不算到家。因此，剩 1 点血时不能再靠下一格的补给续命；必须在移动后仍然活着，才有机会把血量恢复成 6。

处理完补给之后，再用最终的血量判重。例如，两条路线分别带着 2 点和 4 点血走进同一个补给格，补血后都会变成同一个状态 `(nx, ny, 6)`，只需要保留最早到达的那次。普通空地则不同，先到但血量少的路线不一定能完成后面的路，不能仅凭“这个格子已经来过”就删掉另一种血量。

补给格每次经过都能使用，不会被消耗，所以状态里不需要记录哪些补给已经拿过。有效血量只有 1 到 6，共有至多 $6nm$ 个位置与血量的组合，每个组合最多向四个方向扩展一次。时间、空间复杂度都是 $O(6nm)$，把固定的血量上限视为常数后，就是 $O(nm)$。BFS 按步数逐层扩展，第一次活着到家时的步数便是答案。

## 三题放在一起看

这三道题让我把 BFS 中几个容易混在一起的概念分开了：

| 题目 | 队列里的状态 | 一次移动结束后要处理什么 | 什么时候结束搜索 |
|---|---|---|---|
| P1825 | 位置 | 若踩到传送入口，先换成传送落点，再判重 | 到达出口 |
| P2199 | 位置 | 正常四方向移动 | 到达任意能看见奖杯的位置 |
| P2802 | 位置与血量 | 扣血、检查存活、补血，再对完整状态判重 | 活着到家 |

以后再写迷宫搜索，我想先把“队列中的一个元素究竟代表什么”写清楚。P1825 的入口不是最终落点，P2199 的奖杯坐标不是唯一终点，P2802 的位置也不是完整状态。把这些定义确定下来，才知道 visit 应该在哪里检查、需要开几维。
