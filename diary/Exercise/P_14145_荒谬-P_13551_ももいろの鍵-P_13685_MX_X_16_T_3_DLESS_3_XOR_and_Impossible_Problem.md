## P14145：用中心点把左右两部分连起来

[源码](../../Exercise/Ad-hoc/P_14145_荒谬.py)

这题要构造一张简单有向无环图，让距离恰好为 2 的点对尽量多，至少达到 $\frac{n(n-1)}2-n\lceil\log_2n\rceil$。

我采用分治：先选一个中心点，左边所有点连向中心，中心再连向右边所有点。这样任取左边的 $u$ 和右边的 $v$，都有一条 $u\to center\to v$ 的路径。左右两部分内部再分别做同样的构造。

写递归时，需要把节点编号和列表下标分清楚。`mid` 是当前列表的中间位置，`left[mid]` 才是这一层的中心节点。递归以后，列表不再从节点 1 开始，用下标当节点编号就会连到别的区间里。

当前源码中，连边与左半部分的递归如下，省略了函数入口、对称的右半部分递归和输出：

```python
    for i in left:
        edges.append((i,center))
    for j in right:
        edges.append((center,j))

    if(left):
        mid = len(left) // 2
        new_center = left[mid]
        new_left = left[:mid]
        new_right = left[mid + 1:]
        dfs(new_center,new_left,new_right)
```

每一层都保持 `left` 中的编号小于 `center`，`right` 中的编号大于 `center`，并且两边都不再包含中心点。于是所有边都从小编号指向大编号，不会出现环；中心点退出后续递归，也不会反复生成同一条边。

我还需要确认两步路径真的是最短路。对于任意 $u<v$，沿着递归往下找：如果某一层的中心恰好是其中一个端点，就有一条直接边；否则，在它们第一次分到左右两侧时，就能经过这一层的中心两步到达。左右递归只处理各自内部，不会再给这对跨区间的端点补上一条直接边。

因此所有 $u<v$ 的点对，距离都是 1 或 2。设总边数为 $m$，距离为 2 的点对数就是

$$
x=\frac{n(n-1)}2-m.
$$

每层递归的连边数不超过 $n$，需要连边的层数不超过 $\lceil\log_2n\rceil$，所以 $m\le n\lceil\log_2n\rceil$，正好满足要求。构造时间和存边空间都是 $O(n\log n)$。

整理日志时重新运行了当前版本。$n=2000$ 时输出 17964 条边，距离为 2 的点对有 1981036 个，高于题目要求的 1977000；$n=3$ 和 $n=8$ 的构造也核对了边的合法性与点对数量。

## P13551：补码配对为什么要倒着扫

[源码](../../Exercise/Ad-hoc/P_13551_ももいろの鍵.py)

这题把 $0,1,\ldots,n$ 分成尽量多组，要求每组按位与为 0。只有 0 可以单独成组，其他组至少需要两个数，所以组数最多是 $\lfloor(n+2)/2\rfloor$。接下来要构造出能达到这个数量的配法。

对当前数字 `cur`，先构造与它二进制位数相同的全 1 掩码：

$$
mask=2^{\operatorname{bit\_length}(cur)}-1.
$$

`mask ^ cur` 与 `cur` 在这些位上恰好互补，按位与一定为 0。但每一对合法，还不代表整个划分合法：同一个数不能被用两次，也不能漏掉数字。

我提出用 `used` 数组记录哪些数已经配过。扫描顺序也得一起确定。如果先留出 0，再从小到大随意配，$n=6$ 时可以先配出 `(1,2)`、`(3,4)`，最后剩下的 5 和 6 却不能配在一起。

最后采用从大到小扫描。我还是保留了奇偶分支，这样更容易对应组数上界：$n$ 为偶数时，先把 0 单独分组；$n$ 为奇数时，直接让所有数字参与配对，不提前指定 0 的搭档。

源码中的偶数分支如下，省略了输入、特判、`answers` 与 `used` 的初始化，以及后面的奇数分支和输出：

```python
    if(n%2 == 0):
        answers.append((1,0))
        used[0] = True
        for cur in range(n,0,-1):
            if used[cur]:
                continue
            mask = (1<<cur.bit_length()) - 1
            next = mask ^ cur
            answers.append((2,next,cur))
            used[cur] = used[next] = True
```

奇数分支使用相同的倒序循环，只是不先取出 0。检查 `used[cur]` 要放在计算补码之前，当前数只要已经成为别人的搭档，就直接跳过。

### `111` 和 `11` 不都会找 0 吗

这是我写完后继续追问的地方。单独计算时确实如此：`111 ^ 111 = 0`，`11 ^ 11 = 0`。但倒序扫描时，较小的数可能已经被前面的数配走了。

以 $n=7$ 为例，统一写成三位二进制，实际过程是：

| 扫描到的数字 | 配对的数字 | 十进制配对 |
|---|---|---|
| `111` | `000` | 7 和 0 |
| `110` | `001` | 6 和 1 |
| `101` | `010` | 5 和 2 |
| `100` | `011` | 4 和 3 |

轮到 `011` 时，3 已经与 4 配过，`used[3]` 为真，不会再去计算它自己的两位补码。

这个顺序可以按区间来理解。设当前尚未处理的最大值为 $r$，令 $mask=2^k-1$、$l=mask\mathbin{\oplus}r=mask-r$。区间 $[l,r]$ 内的数字在这个掩码下两两互补，高半部分与低半部分一一对应。倒序扫描会先把高半部分逐个配掉，再跳过已经用过的低半部分，剩下的又是 $[0,l-1]$。

若 $r$ 为偶数，$l$ 为奇数，下一轮最大值 $l-1$ 仍是偶数，最终只剩 0，所以可以提前把它单独取出。若 $r$ 为奇数，每轮处理后仍保持奇数上界，最后会把 0 一起配掉。这也解释了两个分支为什么都能达到最大组数。

整个扫描的时间和空间都是 $O(n)$。保留奇偶分支后的版本通过了 734 组本地检查，包括 $n=100000$ 和 600 组连续输入，检查了数字覆盖、重复使用、每组按位与以及组数最优性。

## P13685：数一数乘积里有多少个 2

[源码](../../Exercise/Ad-hoc/P_13685_MX_X_16_T_3_DLESS_3_XOR_and_Impossible_Problem.py)

这题要求计算所有 $i<j$ 的 $(a_i\oplus a_j)$ 的乘积，最后对 $2^{64}$ 取模。我最开始写了两层循环，但 $n$ 可以到 $10^6$，不能把所有点对都枚举出来。

模数给了一个可以提前结束的条件：只要整个乘积能被 $2^{64}$ 整除，答案就已经确定为 0。同奇偶性的两个数，二进制最低位相同，异或后最低位为 0，所以结果一定是偶数。每出现这样一对，就至少贡献一个因子 2；如果异或结果直接为 0，整个乘积也直接为 0。

### 为什么 17 个数已经够了

我追问了 `n >= 17` 的依据。把 17 个数按奇偶性分成两组，同组内部的点对数在两组人数尽量接近时最少，也就是分成 8 个和 9 个：

$$
\binom82+\binom92=28+36=64.
$$

这意味着乘积至少含有 64 个偶数因子，必然被 $2^{64}$ 整除。$n>17$ 时，任取 17 个数，它们内部的乘积已经满足这个条件，乘上其他点对的结果也不会改变整除性。

这里的 17 是只考虑奇偶性就能证明的充分界，并不意味着它是全题最紧的阈值。

### 阈值不一定要卡得很紧

我后来又问，这个范围是不是可以宽泛一些，不一定非要算到 17。只要阈值以上一定为 0，阈值以下的暴力规模能接受，就可以使用更宽松的界。

当前代码选择了 130。$n\ge130$ 时至少有 65 个数奇偶性相同，从中固定一个数，与另外 64 个数分别异或，就得到 64 个偶数因子。这种证明也足够支持提前返回。

当前源码的计算部分如下，省略了导入、`MOD` 和读取函数的定义，以及多组数据的外层循环：

```python
def solve():
    n = int(input())
    arr = [0] + list(read())
    if(n >= 130):
        return 0
    ans = 1
    for i in range(1,n+1):
        for j in range(i+1,n+1):
            ans *= arr[i]^arr[j]
            ans %= MOD
    return ans
```

数组要先读完，再判断是否提前返回，否则下一组输入的位置会错。保留下来的两层循环处理 $n\le129$ 的情况，每组最多枚举 8256 对；结合 $\sum n\le10^6$，总枚举次数不超过 $64\sum n$，也就是约 6400 万次。这个量在 Python 下仍可能偏慢，当前版本只核对了四组样例和 $n=129、130$ 两个边界，没有据此认定最大数据能通过。

如果改用 17，进入暴力的每组至多只有 120 对。对这题来说，我不必继续追求最小阈值，但选定阈值后仍要算一遍剩余的暴力规模；130 容易证明，17 同样不难证明，后者能少做很多循环。
