## CF2113D：一次交换真正改变了什么

这道牌局题最开始很容易被比赛过程牵着走：每轮比较后，胜者的牌消失，败者的牌留在牌顶，看起来必须完整模拟每一种交换。直接枚举两个位置再模拟确实能做小数据，但交换位置有 (O(n^2)) 种，没法应付总规模 (2\times10^5)。

换一个角度，问题可以改成判断“能不能拿到至少 (k) 分”。为了让自己的前 (k) 张牌尽量可靠，我真正关心的是这段前缀的最小值。一次交换最多能把其中最小的一张换出去，因此需要维护前缀最小值、前缀第二小值和后缀最大值：不交换时保留原来的前缀最小值；交换时，用后缀最大值替换前缀最小值，新前缀的下界是第二小值与后缀最大值中的较小者。

```python
    for k in range(1, n + 1):
        value = player[k - 1]

        # 更新前 k 张牌的最小值和第二小值
        if value < min1:
            min2 = min1
            min1 = value
        elif value < min2:
            min2 = value

        # 不交换时，前 k 张牌的最小值
        best_min = min1#不交换的前缀最小值

        # k < n 时，才能从后半部分换一张牌进来
        if k < n:
            after_swap = min(
                min2,
                suffix_max[k]
            )#交换后的前缀最小值
            best_min = max(best_min, after_swap)#把交换和不交换的值取一个最大值

        # 庄家前 n-k+1 张中需要存在小于 best_min 的牌
        if best_min > competitor_prefix_min[n - k + 1]:
            answer = k
```

对手一侧则维护前缀最小值。这样，每个 (k) 都只需常数时间完成判断，整道题从枚举交换降到了线性扫描。现有代码重新运行了题面样例，输出为 `6 2 3`。

## U552155：切一刀，增加的是一个后缀和

把数组分成 (k) 段后，第 (i) 段的和会乘上 (i)。如果暂时不切，所有元素的系数都是 1，答案就是整个数组的和。在位置 (j) 前增加一个切分点后，位置 (j) 到结尾的所有元素都会被分到更靠后的一段，系数统一增加 1，所以这一刀带来的增量恰好是从 (j) 开始的后缀和。

各个切分点的贡献彼此独立。要得到 (k) 段，只需从所有合法后缀和中选出最大的 (k-1) 个。代码先倒序求后缀和并降序排序，再逐个累加，就能依次得到所有 (k) 的答案，时间复杂度是 (O(n\log n))。题面样例的两组结果也与预期一致。

这道题没有复杂的数据结构，关键是看出“段的权重变化”可以拆成每个切分点的独立贡献。原本像分段 DP 的题，最后变成了排序。

## P11642：把替换区间看成收益区间

原数组总和记为 (S)。如果把 (a_i) 改成 (x)，总和的变化量就是 (x-a_i)；选择一段区间进行替换，新增收益便是：

```text
(x-a_l) + (x-a_{l+1}) + ... + (x-a_r)
```

于是题目等价于在新数组 (b_i=x-a_i) 上求最大子段和，最后把这段最大收益加回 (S)。题目允许不操作，因此收益为负时应当选择 0。这个转换把区间枚举压缩成了线性 DP，也让我又看到一次：题面要求修改原数组时，先计算“每个位置对答案造成的增量”，常常比直接讨论修改后的数组更简单。

## P12135：每一列只保留三个连通状态

河床只有两行，真正变化的是每一列最终铺上面的格子、下面的格子，还是两个都铺。先找到最左和最右的已有检测器，外侧的空列不可能帮助连通，可以直接裁掉。之后只维护三个状态的最小新增数量。

```python
    # 当前列最终只选上格、只选下格、上下都选时的最小新增数量。
    dp_top = 0 if bottom[0] == "." else inf
    dp_bottom = 0 if top[0] == "." else inf
    dp_both = (top[0] == ".") + (bottom[0] == ".")

    for i in range(1, n):
        top_cost = top[i] == "."
        bottom_cost = bottom[i] == "."

        next_top = min(dp_top, dp_both) + top_cost if bottom[i] == "." else inf
        next_bottom = min(dp_bottom, dp_both) + bottom_cost if top[i] == "." else inf
        next_both = min(dp_top, dp_bottom, dp_both) + top_cost + bottom_cost

        dp_top, dp_bottom, dp_both = next_top, next_bottom, next_both
```

只选上格时，上一列必须同样连在上面，或者上一列上下都选；只选下格时完全对称。当前列上下都选会把两行接起来，因此可以从任意旧状态转移。状态数固定以后，时间复杂度是 (O(n))，额外空间是 (O(1))。

## P9749：剩余油量不能从状态里消失

这题一开始写成了 DP：`dp[i]` 表示到达站点 (i) 的最小花费，再枚举上一次买油的站点。问题在于，最小花费本身不足以描述到达站点时的状态。每个站点只出售整数升的油，走完一段以后经常还会剩下一部分可行驶里程；转移时如果重新对下一段距离向上取整，就会重复买油。

最后保留下来的量只有三个：累计走过的距离、到目前为止总共买过的油量、已经经过站点中的最低油价。

```python
ans = 0
total_distance = 0
bought = 0
min_price = float("inf")

for i in range(n - 1):
    min_price = min(min_price, price[i])
    total_distance += a[i]

    required = (total_distance + d - 1) // d
    ans += (required - bought) * min_price
    bought = required
```

走到新的边界时，`required` 表示为了覆盖累计路程总共至少需要多少升油。此前已经买过 `bought` 升，因此只补差值；新增的这些油按当前经过的最低价格计算。向上取整只对累计路程做一次，之前多买一整升留下的里程自然会保留下来。样例重新运行后输出 `79`。
