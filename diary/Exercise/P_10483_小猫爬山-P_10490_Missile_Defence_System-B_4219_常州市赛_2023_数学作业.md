## P10483：枚举允许的缆车数，搜索能否装下全部小猫

[源码](../../Exercise/backtrack_algorithm&search/P_10483_小猫爬山.py)

小猫爬山是容量受限的分组问题，N 不超过 18。我从一辆缆车开始枚举上限，判断能否把所有小猫装下，第一次可行的上限就是最优答案。

这里的 `depth` 实际表示允许的缆车数；递归已经处理了多少只猫由 `index` 表示。`cnt` 是已开的车数，`s` 保存每辆车的当前载重。下面摘录放置当前小猫的分支，超出车数上限和处理完全部小猫的判断在此前：

```python
    for i in range(cnt):
        if(s[i] + w <= limit):
            next_s = s.copy()
            next_s[i] += w
            next_cnt = cnt
            if(dfs(cnt,next_s,index + 1,depth)):
                return True
    else:
        next_s = s.copy()
        next_s.append(w)
        next_cnt = cnt+1
        if(dfs(next_cnt,next_s,index+1,depth)):
            return True
    return False
```

当前猫可以放进任意一辆仍有空间的车，也可以新开一辆。源码里的 `for ... else` 没有配合 `break`，因此已有车辆的分支都没找到可行方案后，仍然会尝试新开车，不能把它理解成“只有一辆旧车都放不下时才开车”。

每个分支复制载重列表，让不同选择互不影响。搜索枚举的是分组方案，最坏仍是指数规模；逐层增加允许车数保证首次成功时最优，已有车辆之间的不同放置选择仍由递归逐个尝试。

我在这道题留下的是两种数量的区分：递归层数由小猫数量决定，迭代加深的限制是答案中的组数。

## P10490：方向需要搜索，同一方向里的归属可以贪心

[源码](../../Exercise/backtrack_algorithm&search/P_10490_Missile_Defence_System.py)

导弹防御系统把序列分成若干条严格上升或严格下降的子序列，目标是系统总数最少。当前实现同样枚举允许的系统数，用 `su+sd` 与上限比较；每个导弹尝试归入上升系统或下降系统。

在上升方向里，不必把导弹放到每个可接收的系统都试一遍。我选择尾值小于当前高度、且尾值最大的那个系统。源码中的上升分支如下：

```python
        for i in range(su):
            if(number > up[i]):
                if(k==-1 or up[i] > up[k]):
                    k = i
        if(k != -1):
            temp = up[k]
            up[k] = number
            if dfs(index+1,su,sd,depth):
                return True
            up[k] = temp
```

假设两个可用尾值 t1<t2<x。把 x 接到 t2 后，留下的尾值是 t1、x；接到 t1 后则留下 t2、x。前一种保留了更小的 t1，以后可接收的高度范围更大，因此不会更差。下降方向对称，选择大于 x 的最小尾值。

没有适合的系统时才新建。即使已有系统能接收，也无需为同一方向额外尝试“故意新建”：延续现有系统不会增加系统数，留下的小尾值或大尾值也更有利于后续选择。

每个导弹仍要搜索“上升还是下降”，这部分无法由上述局部贪心替代。递归失败后恢复被改过的尾值，是让另一分支从同一状态出发。最坏仍是指数搜索，但同方向内部的多个分支被压成一个。和小猫爬山放在一起看，我能更清楚地分辨哪些分支具有支配关系，哪些选择必须保留。

## B4219：只缓存剩余数的范围和剩余目标

[源码](../../Exercise/backtrack_algorithm&search/B_4219_常州市赛_2023_数学作业.py)

数学作业要求把 n 写成互不相同的斐波那契数之和，序列从 1、2 开始。n 可以到 10^12，不能按目标值开普通背包数组，但可用斐波那契数只有 O(log n) 个。

当前运行的是 `test02()`。我用 `dfs(k,rest)` 表示只允许使用前 k 个数时，凑出 rest 的方案数；从最大的可用数开始，分成选与不选。下面摘录函数体，函数外的 `@lru_cache(None)` 负责缓存相同状态：

```python
    def dfs(k, rest):
        # 已经凑够：剩下的数全部不选
        if rest == 0:
            return 1

        # 没有数可选，或者全部选上也不够
        if k == 0 or rest > prefix[k]:
            return 0

        # 必须全部选上，恰好一种方案
        if rest == prefix[k]:
            return 1
        number = f[k - 1]
        # 当前最大数太大，只能不选
        if number > rest:
            return dfs(k - 1, rest)
        # 不选当前数的方案数 + 选当前数的方案数
        return dfs(k - 1, rest) + dfs(k - 1, rest - number)
```

`rest=0` 表示剩下全部不选，恰有一种方案；`rest>prefix[k]` 表示把可用的数全选上也不够，直接无解；恰好相等时只有全部选上的一种方案。当前最大数超过 rest 时，只能跳过它。

两条递归都把 k 减一，所以每个斐波那契数最多使用一次。之前怎样选出的剩余目标不影响后续方案数，缓存键只需要 `(k,rest)`，不必保存已经选过的列表。

设实际访问了 S 个不同状态，每个状态只做常数次判断和转移，时间和缓存空间为 O(S)，递归深度 O(log n)。斐波那契数少并不意味着所有子集也少；这里减少工作量依靠的是范围剪枝和重复状态合并，不能直接把整个搜索写成 O(log n)。
