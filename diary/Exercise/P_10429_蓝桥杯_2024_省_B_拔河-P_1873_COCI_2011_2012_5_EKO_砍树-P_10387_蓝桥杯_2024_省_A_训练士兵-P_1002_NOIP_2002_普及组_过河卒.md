# 拔河、砍树、训练士兵、过河卒：四道独立练习

这篇只记录 `Exercise` 目录下的四道练习，不混入正式比赛内容。四题的做法分别落在区间枚举与滑动窗口、答案二分、分层贪心和记忆化搜索上。题型并不连着，正好能看出同一个“缩小枚举范围”的目标，在不同题里会变成完全不同的写法。

## P10429 拔河：在区间和序列上找最近的合法二元组

两个队伍都必须是连续区间，并且前一段要在后一段之前。直接枚举两段区间需要四层循环。现有实现先生成全部连续区间，记录 `(区间和, 左端点, 右端点)`，然后按照区间和排序。

排序以后，问题变成寻找最窄的窗口，使窗口中至少存在两段互不相交的区间。当前执行的 `solve2()` 用两个单调队列维护窗口内的最大左端点和最小右端点：

```python
while(len(min_right_index)>0 and intervals[min_right_index[-1]][1] < left):
    min_right_index.pop()
while(len(min_left_index)>0 and intervals[min_left_index[-1]][2] > right):
    min_left_index.pop()
min_right_index.append(window_right)
min_left_index.append(window_right)

while(intervals[min_right_index[0]][1] > intervals[min_left_index[0]][2]):
    temp_ans = temp_ans = (
        intervals[window_right][0]
        - intervals[window_left][0]
    )
    answer = min(answer,temp_ans)
```

只要最大左端点大于最小右端点，窗口中就能找到两段前后分离的区间。此时尝试收缩左边界，当前窗口两端的区间和之差就是一个候选答案。共有 `O(n²)` 个连续区间，排序和滑动窗口合起来需要 `O(n² log n)` 时间，空间为 `O(n²)`；`n≤1000` 时规模还能接受。

题面样例重新运行后输出 `1`。

## P1873 砍树：二分最高可行高度

锯片越低，获得的木材越多；锯片越高，获得的木材越少，因此“高度 `k` 能否取得至少 `m` 米木材”具有单调性。代码在 `[0, max(heights)]` 上二分，使用向上取整的中点：

```python
while(left < right):
    mid = (left + right + 1)//2
    if(check(mid) == 1):
        left = mid
    else:
        right = mid - 1
```

可行时继续提高下界，不可行时降低上界。`check` 在累计木材达到 `m` 后立即返回，不必继续扫描剩余树木。时间复杂度为 `O(n log H)`，其中 `H` 是最高树木的高度，额外空间为 `O(1)`。

两组题面样例分别得到 `15` 和 `36`。

## P10387 训练士兵：比较当前一层的团体价与单练总价

把士兵按所需训练次数排序后，可以按“训练层数”考虑费用。当前还没完成训练的士兵，如果各自训练一次，总价是 `sum_price`；购买一次组团训练的价格则是 `s`。只要 `s≤sum_price`，这一层选择组团训练不会更差。

```python
while(s <= sum_price):
    diff[0] -= 1
    ans += s
    while(len(diff) > 0 and diff[0] == 0):
        sum_price -= arr[0][0]
        diff.popleft()
        arr.popleft()
while(len(arr) > 0):
    ans += sum_price * diff[0]
    sum_price-= arr[0][0]
    diff.popleft()
    arr.popleft()
```

`diff` 记录相邻完成层数之间的距离。当最前面的距离降为零时，对应士兵已经完成训练，需要从当前单练总价里删掉他的价格。组团训练不再划算后，剩余层数可以整段按个人训练费用结算。

排序需要 `O(n log n)`，逐层购买组团训练的循环最多执行 `max(c_i)` 次；题目给出的上限为 `10^6`。题面样例输出 `16`。

## P1002 过河卒：记忆化搜索

代码先把马所在位置和八个攻击位置放入 `blocks`，再从 `(0,0)` 开始，只向右或向上搜索。`@cache` 让每个坐标只计算一次，状态数量为 `O(target_x × target_y)`。

```python
@cache
def dfs(cur_x:int,cur_y:int)->int:
    if((cur_x,cur_y) in blocks):
        return None
    elif(cur_x == target_x and cur_y == target_y):
        return 1

    ret = 0
    for (dx,dy) in dir2:
        next_x = cur_x + dx
        next_y = cur_y + dy
        if(next_x > target_x or next_y > target_y):
            continue
        if((next_x,next_y) in blocks):
            continue
        ret+=dfs(next_x,next_y)

    return ret
```

题面样例 `6 6 3 3` 得到 `6`。额外检查发现了一个未处理的边界：当起点 `(0,0)` 本身被马控制时，第一次调用 `dfs(0,0)` 会返回 `None`，程序也就打印 `None`；正确答案应该是 `0`。后续修正时，应让阻塞状态返回数字 `0`，这样递推的返回类型始终一致。
