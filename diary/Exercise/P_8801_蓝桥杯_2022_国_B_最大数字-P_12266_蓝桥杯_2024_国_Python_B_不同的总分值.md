## P8801 最大数字：高位优先，但保留两种资源分配

[源码](../../Exercise/backtrack_algorithm&search/P_8801_蓝桥杯_2022_国_B_最大数字.py)

每一位都能循环加一或减一，加法最多用 $A$ 次，减法最多用 $B$ 次。数字最多 18 位，可以从左到右搜索。

高位增大带来的收益，低位无法补偿，所以处理当前数字 `x` 时，应当尽量把它增大。但把这一位变成 9 可能消耗加法，也可能消耗减法，不能随便固定一种优先顺序。

例如 `N=12，A=8，B=2`。第一位用 8 次加法变成 9 后，剩下两次减法无法增大个位，结果是 92；如果第一位用两次减法经过 0 变成 9，加法就能留给个位，结果是 99。

当前源码仍是 DFS，下面摘录两个分支，省略了函数入口的终止判断和末尾的返回：

```python
    x = digits[i]
    # 方案一：用加法尽量增大当前位
    k = min(a, 9 - x)
    ans = dfs(i + 1, a - k, b, value * 10 + x + k)

    # 方案二：用减法绕到 9
    # 当前已经是 9 时，不需要花费操作
    if x != 9 and b >= x + 1:
        ans = max(
            ans,
            dfs(i + 1, a, b - x - 1, value * 10 + 9)
        )
```

加法分支使用 `min(a, 9-x)` 次，把当前位尽量增大；减法分支只有在还能使用至少 `x+1` 次时才值得尝试，这样可以经过 0 绕到 9。减法如果不能绕回去，只会减小当前位。同一位混用加减可以相互抵消，完整绕圈也不会带来收益，因此不需要逐次模拟操作。

`value` 保存已经确定的前缀，每处理一位就乘 10 再加上当前数字。搜索深度为 $n$，每层最多两个分支，时间复杂度为 $O(2^n)$，递归空间为 $O(n)$。最多 18 位时，这个规模可以接受。

## P12266 不同的总分值：每个搜索节点都对应一个子集

[源码](../../Exercise/backtrack_algorithm&search/P_12266_蓝桥杯_2024_国_Python_B_不同的总分值.py)

十道题的分数是 `5,5,10,10,15,15,20,20,25,25`，每题只能得满分或 0 分。我的做法是枚举所选题目的下标，用 `index` 保存当前子集，把总分放进集合 `ans` 去重。

检查时，原程序输出 26。原因是当时只在 `min > max` 时调用 `calculate()`，而 `max` 始终为 9，递归入口又是 `dfs(number+1,max)`，所以只有选择了下标 9 才会统计。

这使所有被统计的子集都包含最后一道 25 分题，漏掉了 `0、5、10、15、20`。只选第一道题时，`index=[0]` 已经是合法答案，却没有在那个节点被记录。

当前代码把统计放到了函数入口：

```python
def dfs(min,max):
    calculate()
    if(min > max):
        return
    for number in range(min,max+1):
        index.append(number)
        dfs(number+1,max)
        index.pop()
    return
```

这里枚举的是“下一道选哪一题”。当前路径无论长短，都是一个合法子集，所以进入递归就应当统计。第一次调用时路径为空，也会记录总分 0。下标始终递增，同一个下标集合不会换一种顺序再次出现；不同集合可能得到相同总分，再交给 `set` 合并。

如果采用逐题决定“选或不选”的写法，则通常在处理完所有题目后统计。两种递归树的节点含义不同，不能只照搬同一个终止条件。

共有 $2^n$ 个子集，当前 `calculate()` 每次遍历所选下标，时间复杂度为 $O(n2^n)$。路径和递归栈占用 $O(n)$，另有去重集合的空间；本题只有 31 种总分。若将来要减少重复求和，可以让递归携带当前总分。
