## P1439 两个排列的最长公共子序列：先压空间，再利用排列性质

最开始我关心的是二维 LCS 数组造成的 MLE，也要求保留两行滚动数组，不直接改成一维。只保存当前行和上一行，空间从 $O(n^2)$ 降到 $O(n)$，但两重循环还在，时间仍然是 $O(n^2)$。

进一步优化来自两个序列都是排列。我记录第一个排列中每个数的位置，再按第二个排列的顺序读取这些位置。公共子序列需要同时保持两个序列中的先后顺序，因此转成了位置序列的严格上升子序列。

```python
pos = [0] * (n + 1)
for i, number in enumerate(arr1):
    pos[number] = i

#dp[k]表示长度为k+1的上升子序列能取得的最小末尾位置
dp = []
for number in read():
    position = pos[number]
    j = bisect_left(dp, position)
    if j == len(dp):
        dp.append(position)
    else:
        dp[j] = position

print(len(dp))
```

`dp[k]` 保存长度为 `k+1` 的上升子序列能够取得的最小末尾位置。二分找到替换位置，让相同长度的候选结尾尽量小，给后面留下扩展空间。时间降到 $O(nlog n)$，第二个排列也可以边读边处理。

我还问了普通 LCS 能不能同样处理。这里的位置映射依赖元素唯一；一般序列中，同一个值可能出现在多个位置，不能用一个 `pos[value]` 代表全部匹配。这份优化也不是 $O(n)$，二分仍然贡献一个对数因子。

## P2758 编辑距离：替换会改变最优对齐

我尝试过根据 LCS 长度，直接用较长字符串的长度减去它，理解成其他位置需要替换、删除或插入。但编辑距离允许替换，最优操作中的对齐方式不一定以保留最长公共子序列为前提。

例如 `ab` 变成 `ba`，LCS 长度为 1，但一次编辑做不到，实际需要两次。于是我直接定义 `dp[i][j]`：把原串前 `i` 个字符变成目标串前 `j` 个字符的最小次数。

```python
for i in range(1,n+1):
    for j in range(1,m+1):
        dp[i][j] = min(dp[i][j],dp[i-1][j] + 1,dp[i][j-1] + 1)
        if(begin[i-1] == end[j-1]):
            dp[i][j] = min(dp[i-1][j-1],dp[i][j])
        else:
            dp[i][j] = min(dp[i][j],dp[i-1][j-1]+1)
```

从上方来是删除，从左方来是插入，从左上方来是匹配或替换。空串边界分别初始化为前缀长度。每一步都对应具体操作，时间和当前二维实现的空间都是 $O(nm)$。

## P1549 棋盘问题：`best_score` 是完整方案提供的上界

这题继续用了搜索。我用位掩码保存还未使用的数字，按格子顺序填写，只需检查新数与上方、左方的和是否为素数。填完完整棋盘后，再保存答案副本。

讨论时我要求先不用额外的下界剪枝，重点确认 `best_score` 的含义。它保存目前完整方案中，第一行和第一列之和的最小值；递归参数 `score` 保存部分方案已经产生的代价。后续加入的数字都是正数，部分代价不小于最优完整答案时，就不可能再改进答案，可以返回。

这个剪枝减少了实际搜索，但不会把排列搜索变成多项式算法。位掩码方便枚举和恢复未用数字，也不能替代对搜索规模的判断。

## P11248 矩阵移动：滚动数组和减少转移常数要分开说

状态还要记录最多使用多少次技能。我先保留当前行、上一行，把空间压到 $O(mx)$；之后又看了 `solution2` 怎样减少重复索引和分支。

```python
if(cell == "?"):
    dst[0] = max(up[0],left[0])
    #有额度时可将一次修改安排在当前格子，不影响最优得分
    for k in range(1,x+1):
        dst[k] = max(up[k-1],left[k-1])+1
else:
    get = int(cell)
    for k in range(x+1):
        dst[k] = max(up[k],left[k])+get
```

遇到 `?` 且还有额度时，可以把一次修改安排在当前格子。如果某个方案此前至多用了 `k-1` 次，当前直接加 1 即可；如果此前已经用了 `k` 次，就可以把过去某个 `?` 的修改挪到当前，得分不变。因此这里不必再单独保留不修改当前格子的同额度分支。

我当时追问过：循环不还是 `n*m*x` 吗？确实如此。这个版本优化的是常数与空间，没有消掉技能次数的枚举，时间仍然为 $O(nmx)$。
