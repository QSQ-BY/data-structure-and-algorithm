## P1766 液体滴落：每次下落都重新寻找轨道

[源码](../../Exercise/simulation/P_1766_液体滴落.py)

这题我先检查了原来的实现，后来又在 `test02` 里复现了一遍。水滴的状态用横坐标 `x` 和当前高度 `cur_y` 表示：垂直下落时，枚举能接住它的线段，找到下方高度最大的那一条，再直接移动到这条线段较低的端点。

线段可以相交，水滴沿轨道滚动时又不受其他轨道影响，所以我需要区分两个过程。只有垂直下落时才寻找下一条轨道；一旦落到轨道上，就一直沿它滑到低端，中途经过交点也不换轨。

对于左右端点已经按横坐标排好的线段，在当前横坐标处的高度是

$$
h=y_1+\frac{y_2-y_1}{x_2-x_1}(x-x_1).
$$

题目明确说线段不包含端点，因此当前 `test02` 使用严格条件 `x1 < x < x2`。水滴刚滑到端点以后，这条线段便不会再次接住它。这个条件也会在计算斜率前排除 `x1 == x2` 的线段。计算交点高度时保留 `Fraction`，避免大坐标下用浮点数比较两条接近的轨道。

每落到一条轨道，当前高度都会下降；离开以后不会再落回它。最多经历 $n$ 条轨道，每次扫描全部线段，因此这个模拟最坏是 $O(n^2)$，还带有有理数计算的开销。它把运动过程表达得很直接，但面对 $10^4$ 条线段，不能仅凭样例通过就认为性能已经足够。

## P6155 修改：为什么可以用栈安排最终位置

[源码](../../Exercise/greedy_algorithm/P_6155_修改.py)

这题我反复追问了两个地方：为什么能想到用栈，以及最后的 `cnt` 循环到底在统计什么。题目允许任意交换费用数组 `b`，所以每个元素增加多少次，与这些次数最后配上哪一个费用，可以分开考虑。

假设增加次数已经确定。若 $d_1\ge d_2$，费用满足 $b_1\le b_2$，那么

$$
d_1b_1+d_2b_2\le d_1b_2+d_2b_1.
$$

因此，增加次数越多，应该分到越便宜的费用。不过，只知道这一点还不够：不同的安排会产生不同的增加次数分布。

我把最终互不相同的整数看作一个个待占用的位置 `t`。排序后的 `a` 中，所有不大于 `t` 且尚未安排的元素，都可以占用它。这里优先选原值最大的元素，让原值更小的元素继续等待。例如 `a = [3, 3, 4]`，先把一个 `3` 放在位置 `3`，到位置 `4` 时让原本就是 `4` 的元素占用，另一个 `3` 推到 `5`。增加次数便是 `[0, 0, 2]`，可以把两次增加都交给最便宜的费用。

这个选择可以用交换来理解。设两个可用原值为 $x\le y\le t$，另一个最终位置为 $u>t$。把 $y$ 放在 $t$、$x$ 放在 $u$，产生的次数是 $t-y$ 和 $u-x$。相比反过来安排，次数总和不变，但大的次数变得更大，小的次数变得更小。配合“大的次数用小的费用”，这样不会更贵。

已经排好序的元素按顺序加入后，最大的可用原值正好在末尾，所以用栈就能完成选择。当前源码的安排过程是：

```python
for _ in range(n):
    if not stack:       # 没有待安排元素，跳到下一个 a
        t = max(t, a[i])

    while i < n and a[i] <= t:
        stack.append(a[i])
        i += 1

    d = t - stack.pop()  # 栈顶是可用元素中原值最大的
    cnt[d] += 1
    t += 1
```

栈里有等待元素时，当前空位就应当使用；把它空着只会让某个元素增加更多。栈为空时直接跳到下一个原值，不必逐个扫描中间的大段空白。这里用的是普通栈，排序已经保证了栈顶最大，不需要再写一套维护单调性的弹栈过程。

`cnt[d]` 表示有多少个元素增加了 `d` 次。例如增加次数为 `[0, 0, 2]`，就是 `cnt[0] = 2`、`cnt[2] = 1`。它记录的是次数的频率，之后再按次数从大到小分配费用：

```python
ans = 0
j = 0
for d in range(n - 1, -1, -1):
    for _ in range(cnt[d]):
        ans += d * b[j]  # b 已升序：大的 d 配小的 b
        j += 1
```

外层决定本轮分配哪一种增加次数，内层把具有这个次数的元素逐个取出，`j` 指向还没用过的最小费用。若 `b = [1, 2, 3]`，上面的例子就是 $2\times1+0\times2+0\times3=2$。虽然有两层循环，内层总执行次数仍然是 $\sum_d cnt[d]=n$。

一个元素等待期间，最多有另外 $n-1$ 个元素占用位置，因此增加次数不会超过 $n-1$，长度为 `n` 的计数数组足够。总时间复杂度由排序决定，为 $O(n\log n)$，空间复杂度为 $O(n)$；最后按题意对 $2^{64}$ 取模。

## P1686 挑战：排序把同一行、同一列放到一起

[源码](../../Exercise/greedy_algorithm/P_1686_挑战.py)

这题先把每一步走到的位置记成 `(x, y, id)`，包含编号为 `0` 的起点。捷径要求是一条水平或竖直的线段，因此先按坐标分组，再找组内相邻的候选点，可以避免枚举所有点对。

我当时问，按 `x` 排序以后，为什么检查的是上下方向。现在把“分组”和“组内排序”分开看就清楚了：先比较 `x` 是为了让同一列连续出现，`x` 相同时再按 `y` 排序，检查的就是这一列里上下相邻的点。当前两个比较函数分别承担这两轮排序：

```python
def cmp_x(a,b):
    if(a[0] != b[0]):
        return a[0] - b[0]
    return a[1] - b[1]

def cmp_y(a,b):
    if(a[1] != b[1]):
        return a[1] - b[1]
    return a[0] - b[0]
```

第二轮先按 `y` 分组，再按 `x` 排序，寻找同一行内左右相邻的点。扫描时还要显式检查主坐标相同，不能把两个分组边界上的点误当成同行或同列。

判断候选点时，先按路径编号交换两端，让 `start < end`。原来沿路径走这一段需要 `end - start` 步，直线长度则是 `abs(x1 - x2) + abs(y1 - y2)`。只有直线长度严格更短，才构成捷径。编号相邻的点本来就只差一步，可以提前排除。

空间上不相邻的两端，如果中间还有同一直线上的访问点，可以把大线段分成更短的线段。假如这些小段都不能缩短原路径，那么各段对应的编号差就都等于直线距离；利用编号差的三角不等式，大线段也无法成为捷径。因此寻找最短捷径时，只需检查组内空间相邻的点。

方向要从路径较早的点指向较晚的点来判断。统一采用东边 `x + 1`、西边 `x - 1` 后，`x2 > x1` 就表示向东；方向判断必须与生成坐标时的约定一致。

候选答案返回 `(length, start, -end, direction)`。Python 的元组从左到右比较，只有当前项相同才比较下一项，因此 `candidate < best` 会先选长度更短的，再选起点编号更小的，最后选终点编号更大的。把 `end` 写成负数，就是把“终点越大越好”转换成统一的“元组越小越好”；输出时再取一次负号还原。

两次排序各需要 $O(n\log n)$，扫描是 $O(n)$。记录路径和排序所需的空间为 $O(n)$。

## P13888 翻转：相邻相同的字符会固定下来

[源码](../../Exercise/greedy_algorithm/P_13888_蓝桥杯_2023_省_Python_A_翻转.py)

这题只允许把 `010` 变成 `000`，或把 `101` 变成 `111`。检查代码时，需要弄清楚一次翻转对后续操作的影响。

只要相邻两个字符相同，它们就都无法先翻转，因为每个字符都有一个与自己相同的邻居。一次合法翻转会使中间字符与左右两边都相同，之后这个位置便固定下来。因此，每个位置最多翻转一次；已经等于目标的字符不能改，不等于目标的字符则必须改一次。

这也解释了为什么必须维护翻转后的字符串。例如初始串为 `0101`、目标串为 `0011`，中间两个位置单独看都能翻转，但先改其中一个，另一个就失去了翻转条件。正确答案是 `-1`，不能把原串中的两个合法位置独立计数。

当前源码已经在计数前执行 `string[i] = target[i]`，后面的判断会读到实际的新状态。翻转只能减少其他位置的操作机会，不会让原来不能翻转的位置变得可翻转，所以从左到右扫描时，遇到必须改变却不能改变的位置，直接判无解即可。存在方案时，答案就是起始串与目标串不同的位置数。

检查时对长度 $1$ 到 $7$ 的全部 21844 组起始串与目标串做过暴力搜索核对，补上实际翻转的版本全部一致。单组扫描时间是 $O(n)$。这道题让我把贪心依据具体落到了一个性质上：相邻相同的字符一旦出现，就再也不能被拆开。
