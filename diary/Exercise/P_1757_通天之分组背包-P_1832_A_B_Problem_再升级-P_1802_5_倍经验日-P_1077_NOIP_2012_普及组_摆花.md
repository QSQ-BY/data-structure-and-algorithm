## P1757：一组物品共同构成一轮选择

[源码](../../Exercise/dynamic_programming/P_1757_通天之分组背包.py)

这题每组最多选一件。复习实现时，我要看清楚外层循环处理的是整组物品：同一组内的候选方案都应该从“还没有处理这一组”的状态出发。

当前源码的转移如下：

```python
dp = [0]*(m+1)
for items in groups.values():
    for capacity in range(m,-1,-1):
        for weight,value in items:
            if(capacity >= weight):
                dp[capacity] = max(
                    dp[capacity],
                    dp[capacity - weight] + value
                )
```

`dp[capacity]` 表示容量不超过 `capacity` 时能获得的最大价值。保持它原来的值，就对应这一组一件都不选；枚举组内物品，则比较选其中某一件的结果。

物品重量为正时，容量倒序遍历保证了较小的 `dp[capacity-weight]` 还没被这一组更新。因此，即使当前容量下比较了多件物品，每个候选方案也只会加入这一组的一件。这里的顺序是“组、容量、组内物品”。如果改成“组、组内物品、容量”，后一件物品可能接着前一件的结果继续转移，同组互斥的限制就丢了。

我把这题记下来，是为了以后看循环顺序时能解释它保护了哪一层状态。设总物品数为 `n`、容量为 `m`，这段实现的时间复杂度为 `O(nm)`，DP 数组占 `O(m)` 空间，分组存储另外占 `O(n)`。

## P1832：同一个素数可以继续使用，但不重复统计排列

[源码](../../Exercise/dynamic_programming/P_1832_A_B_Problem_再升级.py)

把一个整数拆成若干素数之和，可以看成完全背包计数。先筛出不超过目标值的素数，再按素数种类逐层处理。这里 `2+5` 和 `5+2` 是同一种拆分，样例里的 `7` 只有 `7`、`2+5`、`2+2+3` 三种方案。

我在源码里保留了二维状态：`dp[i][total]` 表示只用前 `i` 个素数，组成 `total` 的方案数。下面是实际转移：

```python
for i in range(1, prime_count + 1):
    prime = primes[i - 1]

    for total in range(n + 1):
        # 不使用当前素数
        dp[i][total] = dp[i - 1][total]

        # 至少使用一个当前素数
        if total >= prime:
            dp[i][total] += dp[i][total - prime]
```

两个分支覆盖了“当前素数用零次”和“至少用一次”。后一项读的是当前行 `dp[i][total-prime]`，其中可以已经用过当前素数，再加一个仍然合法。`total` 从小到大遍历，让这个状态先被计算出来。

每种拆分按最后一种素数的使用情况归入一个分支，不需要枚举素数加入的先后次序。当前素数可以重复使用，因此“至少使用一个”的分支读当前行；素数种类已经被限制在前 `i` 种之内，排列顺序不会成为额外的方案。

初始化 `dp[0][0]=1` 表示组成零的空方案，这是后面所有计数的起点。设素数个数为 `P`，当前二维 DP 的时间和空间复杂度都是 `O(Pn)`；这里保留二维形式，能直接看出“上一行”和“当前行”的区别。

## P1802：输掉也有收益

[源码](../../Exercise/dynamic_programming/P_1802_5_倍经验日.py)

5 倍经验日可以沿用 01 背包，但每个对手都有两种结果：不花药输掉，获得 `lose_get`；药水足够时花 `need` 瓶获胜，获得 `win_get`。所以源码比较的是 `dp[cur]+lose_get` 和 `dp[cur-need]+win_get`；药不够时，也要把失败经验加进去。药水数量为零的状态同样要处理，最终统一乘五。

这题我只记这个建模差别。“不花药”仍然完成了一场战斗，收益需要进入这一层状态。也可以把所有失败经验作为基础收益，再把取胜看成花药换取 `win_get-lose_get` 的额外收益。当前代码采用直接比较输赢两种结果的写法，时间复杂度为 `O(nm)`，DP 空间为 `O(m)`。

## P1077：每种花选多少盆，就确定了一种摆法

[源码](../../Exercise/dynamic_programming/P_1077_NOIP_2012_普及组_摆花.py)

摆花一开始需要先把“摆放顺序”从问题里去掉：同种花放在一起，各种花按编号排列，只要每一种的盆数确定，整排花就确定了。因此我要数的是满足总和为 `m`、且每种数量不超过 `a[i]` 的选择方案。

我先写了 `dp[i][j]`：只考虑前 `i` 种花，恰好摆 `j` 盆的方案数。第 `i` 种放 `k` 盆时，剩下的 `j-k` 盆交给前 `i-1` 种花：

$$
dp[i][j]=\sum_{k=0}^{\min(a[i],j)}dp[i-1][j-k]\pmod{10^6+7}.
$$

当前文件保留的是二维实现，初始化和转移摘录如下：

```python
dp = [[0]*(m+1)for _ in range(n+1)]
for i in range(n+1):
    dp[i][0] = 1

for i in range(1,n+1):
    for j in range(1,m+1):
        #k表示当前第i种花选择多少个
        for k in range(min(a[i],j) + 1):
            dp[i][j] += dp[i-1][j-k]
            dp[i][j] %= MOD
```

`k=0` 对应这种花一盆不摆，不能省略。每一层的 `dp[i][0]=1` 表示所有已考虑的花都选零盆；恰好摆正数盆却无法组成的状态则保持零。这里要把不同选择的方案数相加，不是取最大值。

样例里两种花分别最多放三盆、两盆，总共要放四盆。枚举第二种花的数量，只有“第一种三盆、第二种一盆”和“各放两盆”两种合法选择。同种花之间没有区别，种类顺序又已经固定，不需要再乘排列数或组合数。

这份二维实现的时间复杂度为 `O(nm·min(A,m))`，其中 `A=max(a)`，空间为 `O(nm)`，足够处理题目的数据范围。我在这题里需要记住的是计数对象：每个方案就是一组各花种的数量。枚举当前花种的盆数，就能把方案划分成互不重叠的几类，再把它们相加。
