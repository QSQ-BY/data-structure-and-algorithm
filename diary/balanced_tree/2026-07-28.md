# 2026-07-28：红黑树，旋转不难，难的是颜色怎么跟着变

昨天学完 AVL 树并学完了红黑树的理论部分，今天自己从头实现了一遍红黑树，才发现两者的难度不在一个层次上。

AVL 树的调整目标很直观：比较左右子树的高度，判断属于 LL、LR、RR、RL 中的哪一种失衡，再做对应的左旋或右旋，最后把高度更新好。红黑树也会旋转，但旋转反而不是最难的部分。真正麻烦的是每次改变结构以后，节点颜色应该怎样跟着变化，才能继续满足红黑树的五条性质。

## 新节点为什么先染成红色

我在节点里用三个整数表示颜色：

```cpp
#define RED (0)
#define BLACK (1)
#define DBLACK (2)

Node* get_new_node(int key){
    Node* p = (Node*)malloc(sizeof(Node));
    p->key = key;
    p->color = RED;
    p->lchild = p->rchild = NIL;
    return p;
}
```

新插入的节点默认是红色。这样做不会立刻改变从根到各个 `NIL` 节点的黑色节点数量，只可能让一条路径上出现两个相邻的红色节点。也就是说，插入时需要集中修复的是“双红”问题。

递归找到插入位置以后，我在返回过程中逐层调用 `insert_maintain`。如果父节点和叔叔节点都是红色，就把它们染黑，并让祖父节点变红，相当于把冲突继续向上交给更高一层处理；如果只有一侧是红色，就要先判断红色路径是直线还是折线，再把旋转和重新染色放在一起完成。

```cpp
if(root->lchild->color==RED and root->rchild->color==RED){
    root->color = RED;
    C(L(root)) = C(R(root)) = BLACK;
    return root;
}

if(flag==1){
    if(C(R(root->lchild)) == RED){
        root->lchild = left_rotate(root->lchild);
    }
    root = right_rotate(root);
}else{
    if(C(L(root->rchild)) == RED){
        root->rchild = right_rotate(root->rchild);
    }
    root = left_rotate(root);
}
root->color = RED;
root->lchild->color = root->rchild->color = BLACK;
```

这部分仍然能看到 AVL 树的影子：折线需要先旋转一次，直线再围绕祖父节点旋转。不过，AVL 树旋转完更新高度就可以了；红黑树还要考虑红色上浮还是下沉，以及根节点最终必须重新设为黑色。左右旋只是改变局部结构，重新染色才是在恢复红黑树的约束。

## 删除和插入不是同一套修复方法

插入主要怕连续出现两个红色节点，删除更麻烦，因为删掉一个黑色节点可能让某条路径少掉一个黑色节点。为了把这个差额记录下来，我在代码里增加了 `DBLACK`，先把问题表示成“双重黑”，再交给删除维护函数逐层消除。

```cpp
if(root->lchild ==NIL or root->rchild ==NIL){
    Node* temp = NIL;
    if(root->lchild != NIL) temp = root->lchild;
    else if(root->rchild != NIL) temp = root->rchild;
    temp->color += root->color;
    free(root);
    return temp;
}
```

双重黑不是真的给红黑树增加一种长期存在的节点颜色，而是删除过程中的临时记号。红色节点被删掉时不会影响黑色节点数量；黑色节点被删掉时，留下的孩子或 `NIL` 就暂时多背一层黑色，后面再根据兄弟节点及其孩子的颜色处理。

也正是在这里，分支一下子多了起来。兄弟节点是红色还是黑色，兄弟有没有红色孩子，红色孩子在近侧还是远侧，当前根节点又是什么颜色，都会影响下一步是换色、单旋、双旋，还是把双重黑继续向上传递。插入和删除维护颜色的策略并不相同，不能用一套模板硬套。

## 比 AVL 难的，是每个分支都要守住同一组性质

今天自己手动实现红黑树代码以后，我最大的感受就是：红黑树的难点不是某一次旋转，而是要在一大堆情况里始终记得自己正在维护什么。

AVL 树失衡时，我看高度差就能知道问题在哪一侧；红黑树没有这样直接的数字提示。判断时必须同时看当前节点、父节点、叔叔节点，删除时还要看兄弟节点和兄弟的两个孩子。每换一种颜色组合，处理策略都可能改变，插入和删除又各自有一套分支。代码越往后写，越不能只凭“这个形状看起来该左旋”来判断。

不过，把这些情况放回五条平衡性质里以后，分支也不是毫无来由。插入是在消除双红，同时保持各条路径的黑高不变；删除是在消除双重黑，把少掉的那一层黑色补回来。只要先判断究竟破坏了哪条性质，再看周围节点能不能通过换色吸收问题，最后才考虑旋转，思路就比死记每一种图形清楚一些。

写完今天这份实现，我对“平衡”也有了新的认识。AVL 树严格维护高度，红黑树维护的是颜色关系和黑高，所以它允许结构没有那么整齐，却仍能把树高控制在对数范围内。接下来再看 B 树之前，我想先把删除维护里的兄弟、近侄子和远侄子重新画一遍；这些角色一旦认错，后面的颜色和旋转方向就会一起乱掉。
