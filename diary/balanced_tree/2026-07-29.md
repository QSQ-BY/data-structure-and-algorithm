# 2026-07-29：B 树，最难的是让每一个下标对齐

今天一整天都在写 B 树。

前两天实现 AVL 树和红黑树时，一个节点都只保存一个键值，孩子也只有左、右两个。到了 B 树，节点本身变成了一小段有序表：里面有一组关键字，还有一组与区间对应的孩子指针。调整时移动的也不再只是几条连接，而是一整段关键字和分支。

刚开始看图时，分裂、借位、合并的方向并不难理解。真正落到代码里，最费力的是让每个下标对齐。关键字只要错一位，父节点的分隔值就会落到错误的区间；指针错一位，接回去的可能就是另一棵子树。

## 一个节点里同时放下关键字和分支

今天的节点定义是：

```cpp
typedef struct Node{
    int n;//当前节点所存储的关键字的数量
    int key[MAX_M+1];//节点中所存储的关键字
    struct Node* next[MAX_M+1];//每个节点最多有m+1条边 
}Node;
```

`n` 表示当前节点拥有的关键字数量。若节点中有 `n` 个关键字，它就会把数值范围切成 `n+1` 段，因此需要 `n+1` 个孩子指针。这个关系贯穿了今天所有操作：

```text
key   : K0  K1  K2 ... K(n-1)
next  : A0  A1  A2 ... An
```

AVL 树和红黑树里，我只需要分清左孩子和右孩子；B 树里则要先确认当前处理的是第几个关键字、它左右两侧分别是哪两个孩子。代码中的 `pos` 有时表示父节点关键字的位置，有时又决定 `next[pos]` 和 `next[pos+1]` 这一对孩子。只看变量名很容易混，必须把它放回节点结构里理解。

## 节点分裂，中间关键字交给父节点

5 阶 B 树的节点最多稳定保存 4 个关键字。插入第 5 个关键字后，节点暂时上溢，需要从中间断开：

```cpp
    int spos = MAX_M/2;
    Node* node1 = get_new_node();
    Node* node2 = get_new_node();
    node1->n = spos;
    node2->n = MAX_M-1-node1->n;
    for(int i=0;i<spos;i++){
        node1->key[i] = child->key[i];
        node1->next[i] = child->next[i];
    }
    node1->next[spos] = child->next[spos];
    for(int i=0;i<node2->n;i++){
        node2->key[i] = child->key[i+spos+1];
        node2->next[i] = child->next[i+spos+1];
    }
    node2->next[node2->n] = child->next[child->n];
```

`spos` 左边的关键字进入 `node1`，右边的进入 `node2`，中间关键字上升到父节点。关键字的分界还算直观，孩子指针更容易错：左节点要比自己的关键字多复制一个指针，右节点最后也要单独接上最右侧分支。

分裂完成后，父节点还要在 `key[pos]` 放入上升的关键字，并用 `next[pos]`、`next[pos+1]` 接住两个新节点。今天反复检查根节点分裂时，我才真正意识到根节点为什么需要单独包装一层插入操作：普通节点上溢后可以交给父节点处理，根节点没有父节点，只能现场创建一个新根。

## B 树里的旋转，其实是在兄弟之间借关键字

AVL 树和红黑树的左右旋会改变局部根节点。B 树仍然使用“左旋”“右旋”这两个名字，但做的事情已经不一样了。删除造成某个孩子下溢后，它会经过父节点向兄弟借一个关键字：

```cpp
Node* erase_maintain(Node* root,int pos){
    //下限
    int low_bound = (MAX_M+1)/2-1;//向上取整
    if(root->next[pos]->n >= low_bound) return root;//未发生失衡
    
    //发生失衡
    if(pos>0 and root->next[pos-1]->n > low_bound){
        //向前兄弟节点借，右旋
        root = right_rotate(root,pos-1);
    }else if(pos<root->n and root->next[pos+1]->n > low_bound){
        //向后兄弟节点借，左旋
        root = left_rotate(root,pos);
    }else{
        //合并操作
        if(pos>0) root = merge_node(root,pos-1);//merge(root,j)->把j和j+1节点进行合并
        else root = merge_node(root,pos);
    }
    return root;
}
```

向左兄弟借时，父节点的分隔关键字先下沉到当前节点，左兄弟最大的关键字再上升到父节点；向右兄弟借时则完全对称。除了关键字，还要把对应的孩子指针一起转移。这里最容易混的是 `pos`：下溢节点位于 `next[pos]`，如果向左借，真正参与旋转的分隔关键字在 `key[pos-1]`；如果向右借，分隔关键字就是 `key[pos]`。

兄弟节点没有多余关键字可借时，就只能把左节点、父节点中的分隔关键字和右节点合在一起。合并以后父节点少一个关键字，也少一个孩子，问题可能继续向上传递；如果最后根节点的关键字数量变成 0，就让它唯一的孩子成为新根。

## 平衡树收尾，下一章转向递归转非递归

写完 B 树以后，从二叉搜索树开始的平衡树部分就算正式结束了。回头看这几天，AVL 树围绕高度做旋转，红黑树把颜色变化也放进调整过程，B 树则把一个节点扩展成多组关键字和分支。它们维护平衡的方式各不相同，写代码时却都绕不开同一件事：结构发生变化以后，原来的有序关系还得保留下来。

明天开始进入下一章，学习怎样把递归函数改成非递归。以前写树时，递归会替我保存当前节点、返回位置和处理到哪一步；换成非递归以后，这些状态都要自己安排。刚写完一整天依赖递归下降和回溯维护的 B 树，再回头拆解递归过程，衔接得正好。
