# 2026-07-27：从二叉搜索树到 AVL，有序之后还要保持平衡

今天一整天都在和树打交道。

先学的是普通的二叉搜索树。它和之前写过的二叉树在结构上没有什么区别，真正改变的是节点之间的关系。以前实现普通二叉树时，我会用 `rand()%2` 随机决定新节点放到左边还是右边；二叉搜索树不再随机，而是比较新值与当前节点的大小，一层层确定插入方向。

## 二叉搜索树：插入位置由大小关系决定

```cpp
Node* insert(Node* root,int key){
    if(root == nullptr) return get_new_node(key);
    if(key == root->key) return root;
    if(key<root->key) root->lchild = insert(root->lchild,key);
    else root->rchild = insert(root->rchild,key);
    return root;
}
```

这段插入代码很短，但它已经把二叉搜索树最重要的关系固定下来了：比根节点小的值进入左子树，比根节点大的值进入右子树，遇到空位置时才创建节点。每次递归只会沿一条路径继续，因此插入、查找和删除的时间都与树高 `h` 有关，是 `O(h)`。

也正因为这个规则，中序遍历会自然得到一个有序序列。以前遍历只是访问整棵树的一种方式，到了二叉搜索树里，遍历顺序和节点之间的大小关系真正连了起来。

不过，只满足“左小右大”还不够。如果插入的数据本身接近有序，节点可能一直倒向同一边，树会逐渐退化成链表，操作也会从理想的 `O(log n)` 变成 `O(n)`。AVL 树要解决的就是这个问题。

## AVL 树：给有序再加一道高度约束

AVL 树仍然是一棵二叉搜索树，只是多了一个平衡条件：

```text
|H(left) - H(right)| <= 1
```

今天学到这里时，我对“平衡树”这个名字有了更具体的理解。不同平衡树首先要回答的，都是怎样才算平衡。AVL 树用左右子树的高度差来约束结构，红黑树则会换成另一套条件。后面的维护操作看起来各不相同，本质上都是在插入或删除打破原有条件以后，把树重新调整回来。

为了判断 AVL 树是否失衡，我在节点中增加了 `height`，并用高度为 0 的虚拟空节点 `NIL` 统一处理边界。递归插入或删除返回时，先更新当前节点的高度，再调用 `maintain` 检查这一层。这样，搜索树原本从上到下寻找位置的过程，又多了一段从下到上恢复平衡的过程。

## 左旋和右旋：局部换根，不破坏整体有序

今天最让我觉得精妙的是左旋和右旋。以左旋为例：

```cpp
Node* left_rotate(Node* root){
    printf("left_rotate:%d\n",root->key);
    Node* new_root = root->rchild;
    root->rchild = new_root->lchild;
    new_root->lchild = root;
    update_height(root);
    update_height(new_root);
    return new_root;
}
```

原根节点的右孩子成为新根，新根原来的左子树则接到旧根的右侧。指针关系变了，节点之间的大小顺序却没有变。调整完成后先更新旧根高度，再更新新根高度，最后把新根返回给上一层。右旋的过程与它对称。

旋转真正巧妙的地方就在这里：它不需要重新构造整棵树，只改变失衡位置附近的几条连接，就能降低过高一侧的高度，同时继续满足二叉搜索树的顺序。

## 四种失衡，最后都落到左右旋

AVL 树的失衡分为 LL、LR、RR、RL 四种。下面这部分是左子树过高时的维护逻辑：

```cpp
Node* maintain(Node* root){
    if(abs(H(R(root)) - H(L(root))) <= 1) return root;
    int type = 0;
    if(H(L(root))>H(R(root))){
        if(H(root->lchild->rchild) > H(root->lchild->lchild)){
            //LR失衡类型
            root->lchild = left_rotate(root->lchild);
            type++;//type = 1
        }
        //LL类型失衡
        root = right_rotate(root);
        type++;//type = 2
    }
```

LL 型只需要对当前节点右旋。LR 型不能直接右旋，要先对左孩子做一次左旋，把折线拉直，再对当前节点右旋。右子树过高时同理，RR 型对应左旋，RL 型则先右旋右孩子，再左旋当前节点。

这样看下来，四种类型并不是四套完全不同的算法。真正需要判断的是失衡发生在哪一侧，以及过高的路径是直线还是折线；最后使用的仍然是左旋和右旋这两个基本动作。
