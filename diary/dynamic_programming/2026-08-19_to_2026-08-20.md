## 8 月 19 日：先从“怎么问”开始优化

墙面染色里，我没有继续围着所有颜色排列硬算，而是把 `f[n]` 定义成长度为 `n`、首尾颜色不同的方案数。新加入一面墙后，按它与已有颜色的关系分类，就能得到

```text
f[i] = f[i - 1] * (k - 2) + f[i - 2] * (k - 1)
```

这个转移让我再次看到，动态规划最费力的部分通常不是写循环，而是找到既能覆盖答案、又方便从较小规模推过来的状态。

鸡蛋硬度问题把这种感觉放大了一遍。最直接的状态是“用若干鸡蛋测若干层楼，最坏情况最少扔几次”，每次还要枚举第一次从哪一层扔。优化后，我把问题反过来问成：“有 `i` 个鸡蛋、最多扔 `j` 次，最多能确定多少层？”代码里的核心转移变成了：

```python
for i in range(2,n+1):
    flag = 0
    for j in range(1,1002):
        dp[i][j] = dp[i][j-1]+dp[i-1][j-1]+1
        if(dp[n][j]>=m):
            ans = j
            flag = 1
            break
```

鸡蛋碎了以后能检查 `dp[i-1][j-1]` 层，没有碎则能继续检查 `dp[i][j-1]` 层，中间再加上当前这一层。状态一换，原来“枚举落点再取最坏情况”的过程就被压进了一条加法递推里。不过当前实现把投掷次数上界写成了固定的 `1002`，在极端数据下还需要按输入范围重新处理，这个优化现在更重要的价值还是把状态关系理顺了。

当天的两道洛谷练习走的是另外两条路线。P11229 小木棍没有特别明确的算法考点，主要看能不能观察出答案的组成规律，再根据火柴数量对 7 的余数构造最小正整数。P1815 蠕虫游戏则是一道模拟题，考的是对数据结构的理解：我用 `deque` 保存虫身上的每一个点，才能在每一步移动后及时维护尾巴的位置。模拟时还要先移除尾部，再判断新头部是否撞到身体，这样“头刚好进入尾巴刚离开的格子”不会被误判。

## 8 月 20 日：把几个经典优化真正写进代码

今天先连续整理了三个动态规划优化。鸡蛋问题交换状态中的因果变量，最长上升子序列另建 `tails`，多重背包再用二进制分组。这些做法都不是在原来的循环上小修小补，思维性和技巧性很强，第一次看到时也很难凭空想到。

回文切割把二维区间状态压成了一维：`dp[i]` 只表示前 `i` 个字符的最少切割次数，再提前枚举回文中心，把所有能作为结尾的回文段记录下来。最长严格上升子序列则从枚举前驱的 `O(n²)` 转成维护 `tails`：

```python
for i,number in enumerate(arr):
    pos = bisect_left(tails,number)
    if pos == len(tails):
        tails.append(number)
    else:
        tails[pos] = number
print(len(tails))
```

这里的 `tails[i]` 不是最终答案中的某一条固定子序列，而是“长度为 `i + 1` 的上升子序列能够取得的最小结尾”。结尾越小，后面越容易接入新数字；配合二分查找，复杂度降到了 `O(n log n)`。多重背包则把每种物品的数量拆成 `1、2、4……` 和最后的余数，把一组多件物品变成若干件 0/1 物品，再倒序枚举容量。

## 杨辉三角不只是算组合数

P1118 是一道很经典的 DFS，题目一看就能想到用组合型枚举搜索排列，真正巧妙的是藏在反复求和里的杨辉三角。最初我在搜索到叶子后再模拟一遍相邻求和，后来才把最终结果写成原排列的加权和。每个位置被累加的次数，正好是杨辉三角第 `n - 1` 行的组合数，所以 Python 可以直接用 `math.comb` 生成系数：

```python
coefficient = [comb(n-1,i) for i in range(n)]

bit = -temp&temp
number = bit.bit_length()
next_sum = current_sum + number*coefficient[pos-1]
if(next_sum > sum):
    temp -= (-temp & temp)
    continue
```

这样一来，每放入一个数就能立刻更新加权和，不必在叶子节点重新做 `O(n²)` 的相邻求和。可用数字也直接留在位掩码里：`lowbit` 取出一个候选位，`bit_length()` 把它还原成数字，不再额外初始化索引数组。

这版搜索已经能按从小到大的候选顺序得到字典序最小解，也能在当前和超过目标时剪枝。但这个剪枝只有一个方向：如果目标很大，而剩余数字无论怎样排列都达不到，程序仍可能枚举大量排列。后面若继续优化，需要根据“剩余数字 × 剩余系数”估计可达到的最小值和最大值，再决定是否提前返回。

## P2196：连通块不是路径

最后检查 P2196 时，我一开始很自然地掉进了并查集的陷阱，一股脑把所有连通点的价值都加了起来。可题目要找的是一条合法路径，不是整个连通块。并查集只能回答两个点是否连通，却不能表示“从编号较小的点沿边依次走到编号较大的点”这条路径，更无法直接求路径上的最大地雷总数。

想清楚这一点后，后面的做法反而很经典：这就是线性一维 DP。`dp[i]` 保存以地窖 `i` 结尾的最大地雷数。只要从 `j` 转移到 `i` 得到了更大的值，就同时更新 `previous[i]`：

```python
previous = [-1]*(n+2) 
for i in range(1,n+1):
    for j in range(1,i):
        if(visit[j][i] == 1):
            if(dp[j] + arr[i] > dp[i]):
                dp[i] = dp[j] + arr[i]
                previous[i] = j
```

`previous` 之所以能还原最优路径，不是因为它记录了所有可能的前驱，而是因为它和 `dp` 在同一个“找到更优转移”的条件里同步更新。`dp[i]` 一旦代表当前以 `i` 结尾的最优值，`previous[i]` 就代表产生这个值的那个前驱。最后找到全局最大的终点，再沿着 `previous` 一直回退，就能把对应路径倒着取出来。

这两天反复出现的不是某一个固定模板，而是同一个问题：当前状态到底保存了什么，它能不能把答案需要的信息完整地带到下一步。鸡蛋问题靠换状态消掉了枚举，P1118 靠组合系数把整棵求和三角压成一次加权，P2196 则要求最优值和前驱一起更新。
