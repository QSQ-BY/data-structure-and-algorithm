## 立定跳远：二分之外的一次等价转换

今天第一道洛谷是 P10909。二分答案本身很明显：如果最远跳跃距离 `L` 能完成，那么更大的距离也一定能完成，`check(L)` 具有单调性。真正需要转一下的地方，是那次可以跳到 `2L` 的爆发技能。

一开始看它像是二分判定里的特殊情况，似乎要单独记录技能有没有使用。想明白以后其实简单得多：一次 `2L` 跳跃相当于在普通跳跃模型里省掉一个落脚点，也就等价于多给一个新增检查点。于是检查点预算从 `m` 变成 `m+1`，后面仍然按普通跳跃判断。

```python
temp = m
temp += 1#小明的技能和可插入的新检查点的作用本质是一样的

# ... 省略 check(L) 的区间模拟

while(left < right):
    mid = (left + right)//2
    if(check(mid) == 1):
        right = mid
    else:
        left = mid+1
```

这道题的二分框架没有太多意外，弯子全在建模上。把技能单独拿出来模拟，状态会多一层；把它换成一个额外检查点后，判定函数就回到了熟悉的形式。目前代码还是逐次模拟新增检查点，之后可以再把一段距离需要的检查点数改成整除公式，避免在 `m` 很大时循环太久。

## 宝石极差：想当然的单边贪心不够用

第二道 U535992 是今天最后一题，也确实卡得更久。做到这里脑子已经有点转不动了，一开始很自然地认为：先做操作一再做操作二，相当于把元素搬过去又搬回来，不能有效减小极差。因此只要比较“全部处理最小值”和“全部处理最大值”哪一种更好就行。

这个判断忽略了重复极值带来的变化。左右混合操作虽然会产生额外代价，却可能同时越过两端较大的间隔，结果反而优于任何单边策略。后来又尝试用差分数组和双端队列模拟，每次弹出较大的端点；这个模型能准确表示一次操作，但“当前收益更大”并不代表后面仍然更优，切换方向时还要先消化另一端新增的零差分。

最后还是回到枚举。排序后，设 `l` 表示左边不再保留的元素数，`r` 表示右边不再保留的元素数。只处理一端分别需要 `l` 或 `r` 次；两端都处理时，先搬过去的那批元素还会在另一端再处理一次，所以最少操作数是：

```text
l + r + min(l,r)
```

固定 `l` 后，`r` 越大，新的最大值越小，因此只需要求预算内最大的 `r`。

```python
for l in range(k+1):
    if(k >= 3*l):
        r = k - 2*l
    else:
        r = (k-l)//2
    ans = min(ans,arr[n-1-r] - arr[l])
```

当 `r>=l` 时，代价是 `2l+r`；否则代价是 `l+2r`，上面的两个分支正是从这两个不等式里解出最大的 `r`。枚举看起来比“固定选一边”笨一些，却完整覆盖了两端操作的组合，排序后的扫描仍然只是线性的。

今天最后这道题耗时最长，不是公式本身难，而是我一直想给它找一个固定方向的贪心策略。下次再碰到这种可以从两端操作的题，我想先写清楚最终保留的是哪个区间、左右各有多少元素被处理，再判断局部选择有没有单调性。这样或许能早点发现：有些题需要枚举的不是每一步操作，而是最终方案的边界。
