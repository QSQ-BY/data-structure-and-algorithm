## 数字三角形：同一张表可以从两个方向理解

经典动态规划的第一题是数字三角形。我分别写了自底向上和自顶向下两种版本。自顶向下时，`f[i][j]` 表示从顶点走到第 `i` 层第 `j` 个位置能够取得的最大和，转移是 `f[i][j] = max(f[i-1][j], f[i-1][j-1]) + val[i][j]`。

每个位置只有左上和右上两个前驱，所以只要按层向下遍历，转移依赖一定已经计算完。我先用负无穷初始化整张表，因为三角形边缘有一个前驱并不存在，不能让补出来的 `0` 意外参与最大值比较。整个过程访问三角形中的每个状态一次，时间和空间复杂度都是 `O(n^2)`。

这道题也让我看清了昨天网格题的结构。网格只能向右或向下走，数字三角形只能向左下或右下走；图形不同，实质上都是在一个有明确先后顺序的状态图上取最优前驱。

## 三类背包：差别藏在“旧状态还是新状态”里

0/1 背包中，每件物品最多使用一次。我把二维状态压成一维以后，容量必须倒序更新：

```python
dp = [0]*(V+1)
for i in range(1,n+1):
    cur_weight,cur_value = read()
    for j in range(V,cur_weight-1,-1):
        dp[j] = max(dp[j],dp[j-cur_weight] + cur_value)
```

倒序时，`dp[j-cur_weight]` 仍然是处理当前物品之前的旧状态，因此同一件物品不会在这一轮被重复拿走。复杂度从二维写法的 `O(nV)` 时间、`O(nV)` 空间，压到了 `O(nV)` 时间、`O(V)` 空间。

完全背包允许一种物品使用任意次。今天的实现保留了两行滚动数组，核心转移是 `dp[index][j] = max(dp[rindex][j], dp[index][j-cur_weight] + cur_value)`。第一项读取上一行，表示不拿当前物品；第二项读取当前行，而 `dp[index][j-cur_weight]` 已经可能包含当前物品，所以它可以继续转移到更大的容量。这里必须让容量正序增长，才能沿着当前行反复使用同一种物品。0/1 背包的倒序和完全背包的正序不是模板上的小差异，而是在控制转移究竟读取上一轮还是这一轮的状态。

多重背包则在外层枚举某件物品可用的次数，每次继续按 0/1 背包倒序更新。当前写法直接展开 `s` 件，逻辑很直观，复杂度是 `O(V · Σs_i)`；以后再学二进制拆分时，可以回到这里比较优化前后的物品数量。

## 回到昨天的 C 题：从搜索路径改成计算状态

昨天 AWC 0135 Beta 的 C 题让我在 DFS 里不断重复展开同一个格子。今天学完数字三角形后，我给这道题补上了迭代 DP：

```cpp
dp[1][1] = g[1][1];
for(long long i=1;i<=n;i++){
    for(long long j=1;j<=m;j++){
        if(i==1 and j==1) continue;
        dp[i][j] = g[i][j] + max(dp[i-1][j],dp[i][j-1]);
    }
}
cout<<dp[n][m]<<endl;
```

`dp[i][j]` 表示从起点到 `(i,j)` 能收集到的最大价值。到达它的最后一步只有从上方下来或从左边过来，因此两个前驱取最大值，再加上当前格子的价值即可。行列顺序本身就是拓扑顺序，每个格子只计算一次，时间复杂度稳定为 `O(NM)`。本地样例输出为 `29`，和题面一致。

昨天我把 `dp[x][y]` 当成 DFS 的剪枝记录，状态变大时还要重新搜索后续路径；今天它真正变成了一个可以直接复用的答案。差别不在数组名字，而在状态定义是否已经回答了一个完整的子问题。

## ABC 471：做出四题，也碰到现在还接不住的题

晚上的 ABC 471 做出了四题。前三题都是比较直接的基础模拟，真正需要转一下的是 D 题：充电器里的每块电池都会随着时间一起增长，如果每次查询都更新堆里的所有数据，复杂度肯定压不下来。

我把电池插入时的电量 `w` 减去插入时刻 `t`，存下不随时间变化的基准值 `w-t`。取出电池时，再给最大的基准值加上当前时间，并用 `V` 限制电量上限：

```cpp
long long t, w;
cin >> t >> w;
s.insert(w - t);

// ……省略读取查询时间和空集合分支
long long max_key = *s.begin();
s.erase(s.begin());
long long ans = min(vmax, max_key + t);
cout << ans << "\n";
```

这样不需要让容器里的每一个数跟着时间变化。所有电池共同增长的部分被推迟到查询时统一加回，`multiset` 只负责维护最大的基准值。D 题样例在本地跑出了 `85、100、25、-1`。

E 题要求汇总所有 K 元子集的“元素和的平方”。我写的是暴力组合枚举，它会走过全部 `\binom{N}{K}` 种选择，结果很明显会超时。答案似乎还要用到数论或组合计数，这已经超出了我目前的能力范围，所以今天不再硬往下展开。

最后让我觉得最有意思的反而是 F 题。它和以前写过的“把若干字符串拼成最大数”很像，原题只要比较两种拼接顺序；这次却限制了必须选择恰好 K 个字符串，于是还要决定哪些字符串进入答案。每个字符串都有选与不选两种状态，选择数量又必须受到 K 的约束，本质上正好落回今天刚练过的 0/1 背包。
