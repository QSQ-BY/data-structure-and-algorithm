## 8 月 17 日：最长严格上升子序列

我把 `dp[i]` 定义为“以第 `i` 个数结尾的最长严格上升子序列长度”。如果前面的 `arr[j]` 小于 `arr[i]`，就可以把第 `i` 个数接到以 `j` 结尾的序列后面：

```python
for i in range(2,n+1):
    for j in range(1,i):
        if(arr[j] >= arr[i]):continue
        if(dp[j]+1 > dp[i]):
            dp[i] = dp[j] + 1
            pre[i] = j
    if(dp[i] > ans):
        ans = dp[i]
        index = i
```

这里的递推关系很直接：在所有满足 `j < i` 且 `arr[j] < arr[i]` 的位置中，取最大的 `dp[j]`，再加一。当前写法用两层循环枚举前驱，时间复杂度是 `O(n²)`；`pre[i]` 额外记录最优转移来自哪里，所以最后还能沿着前驱下标还原出一条具体的上升子序列。

这道题没有出现什么真正卡住我的地方。状态围绕“结尾位置”定义以后，哪些旧状态可以转移过来一眼就能看清，剩下的只是把长度和路径一起维护好。

## 8 月 17 日：最长公共子序列

第二题是最长公共子序列。我用 `dp[i][j]` 表示两个字符串分别取前 `i` 位和前 `j` 位时的答案，并把完整的二维数组压成两行：

```python
for i in range(1,n+1):
    index1 = i%2
    index2 = 1-index1
    for j in range(1,m+1):
        dp[index1][j] = max(dp[index2][j],dp[index1][j-1])
        if(a[i] == b[j]):
            dp[index1][j] = max(dp[index1][j],dp[index2][j-1]+1)
```

如果 `a[i]` 和 `b[j]` 相同，就可以在两个字符串都缩短一位的答案后面接上这个字符；如果不同，就比较舍掉 `a[i]` 或舍掉 `b[j]` 后的结果。每个状态只依赖上一行和本行左侧，因此滚动数组足够，时间复杂度是 `O(nm)`，空间复杂度降到 `O(m)`。

和前面的最长上升子序列一样，这题最重要的部分还是状态定义。一旦确定“两个前缀的最长公共子序列”就是子问题，递推关系几乎是顺着最后一位字符的关系自然写出来的。

## 8 月 18 日：区间 DP，枚举切口只是第一步

回文切割是今天接触区间 DP 的入口。我用 `dp[i][j]` 表示子串 `[i,j]` 最少需要切多少刀，再按区间长度从短到长更新。如果整个区间本身是回文串，答案就是零；否则枚举第一刀的位置 `k`，把左右两个已经计算过的区间接起来。

这个框架看起来和以前的递推没有隔得很远，但状态顺序变了。普通线性 DP 经常沿着下标向前推，区间 DP 则必须先保证短区间已经完成，长区间才能放心使用它们。今天不少时间都花在确认 `length、l、r、mid` 的相对关系上。循环顺序不是随意摆放的，长度必须在区间起点之前确定，否则转移时可能读到还没有计算的状态。

棋盘分割把同一套思路搬到了二维矩形上。状态除了分割块数，还要带着左上角和右下角四个坐标，矩形得分则用二维前缀和快速取得。我一开始把它和 P1388 的乘号分配混在了一起，后来才看清题目规则的差别：棋盘题每次固定割下一块成品，只让剩余矩形继续切，所以块数分配只有 `(1,t-1)` 和 `(t-1,1)`；表达式的左右子区间却都可能继续使用乘号，不能省掉数量枚举。

## 8 月 18 日：乌龟棋的滚动数组优化

动态规划优化这一题以前接触过，方法仍然是找出不必完整保留的旧状态。乌龟棋原本可以用四种卡片的已使用数量组成四维状态，而第一维 `a` 在转移时只会访问当前层和上一层，因此我把它滚动成两层：

```python
dp = [[[[0]*(num_4+2) for _ in range(num_3+2)] for _ in range(num_2+2)]for _ in range(3)]
dp[0][0][0][0] = val[0]
for a in range(0,num_1+1):
    index1 = a%2
    index2 = 1-index1
    for b in range(0,num_2+1):
        for c in range(0,num_3+1):
            for d in range(0,num_4+1):
                if(d==0 and b==0 and c==0 and a==0): continue
                pos = a + 2*b + 3*c + 4*d
                dp[index1][b][c][d] = val[pos]
                ans = 0
                if(a>0):ans = max(ans,dp[index2][b][c][d])
                if(b>0):ans = max(ans,dp[index1][b-1][c][d])
```

这里删掉的是历史层，而不是待计算的状态。所有 `a、b、c、d` 组合仍然要遍历，时间复杂度没有变化；空间中与一号卡片数量有关的那一维，则从 `num_1+1` 层降成了常数层。

## 8 月 18 日：洛谷 P1388，切开以后还要分配乘号

今天的第一道额外练习刚好对应区间 DP。P1388 要在固定顺序的数字之间加入恰好 `k` 个乘号，其余位置放加号，括号可以自由添加。我把状态定义为 `dp[l][r][cnt]`：区间 `[l,r]` 恰好使用 `cnt` 个乘号时能够得到的最大值。

```python
for mid in range(l, r):
    # 最外层是加号
    for left_cnt in range(cnt + 1):
        right_cnt = cnt - left_cnt
        left = dp[l][mid][left_cnt]
        right = dp[mid + 1][r][right_cnt]
        if left != -1 and right != -1:
            dp[l][r][cnt] = max(dp[l][r][cnt], left + right)

    # 最外层是乘号
    for left_cnt in range(cnt):
        right_cnt = cnt - 1 - left_cnt
        left = dp[l][mid][left_cnt]
        right = dp[mid + 1][r][right_cnt]
        if left != -1 and right != -1:
            dp[l][r][cnt] = max(dp[l][r][cnt], left * right)
```

最外层是加号时，左右乘号数量之和等于 `cnt`；最外层是乘号时，根节点自己已经消耗一个乘号，左右只能再分配 `cnt-1` 个。这里不能只保存左右区间“不限乘号数量的最大值”，因为那个最大值很可能用了错误数量的乘号。`mid` 解决的是从哪里切，`left_cnt` 解决的是资源怎样分配，它们是两件事。

这道题和刚学的内容贴得很紧，但也正因为刚学，状态定义、循环顺序和乘号守恒都花了很久才完全理顺。最后代码不算长，真正费时间的是确认每一层循环为什么必须存在。

## 8 月 17 日：Codeforces Round 1117（Div. 2）

今天又打了一场 Div. 2，A、B、C 三题全用 Python 写。整体思路来得不慢，只是 Python 还没有写熟，有些地方没有 C++ 那种落笔就能写完的感觉。

### A：只看首字母是否存在

A 题是比较常规的哈希。每个初始单词都可以使用无限次，而缩写只由所选单词的首字母组成，所以没有必要保存完整单词，也不用关心某个首字母出现了多少次。我只把所有初始单词的首字母转成大写后放进哈希表，再逐位检查每个询问串：只要出现一个不在表中的字符，这组数据就不可能成立。

缩写生成后虽然也会加入集合，但它们的首字母仍然来自原有首字母集合，不会凭空产生新的字母。因此这题不需要按某种顺序模拟缩写的加入过程。想清这一点以后，代码就只是一次建表和若干次查询，确实很简单。

### B：一片山脉只剩下“最高高度加山的数量”

B 题主要靠数学直觉。山脉已经按高度非递增排列，巨人每跨过一座山，都相当于在总过程里多承受一次高度变化。最后真正决定一方能坚持多久的量，不是整组山高的具体分布，而是最高山的高度加上山的数量。

因此两边分别计算 `a[0] + n` 和 `b[0] + m` 即可。Bea 先手，所以两者相等时第一位巨人获胜，否则值更大的一方获胜。题面看起来像要模拟很长的互相投掷过程，压缩以后却只需要读出每组山的第一个高度。

### C：知道答案是 `m-1`，却差一点没找到该省谁

C 题最可惜。我很快判断出最少需要 `m-1` 个摄像头：给其中 `m-1` 个候选坝的入边装上摄像头以后，看到哪条候选边就能缩小目的地；如果一条都没有看到，目的地就是被省下的那个候选点。反过来，少两个摄像头时至少会留下两个目的地无法区分，所以答案就是 `m-1`。

真正卡住我的是应该省去哪一个点。我隐约感觉到，如果两个候选点在同一条父子路径上，摄像头放错位置就会有问题。比如省掉子节点的入边，而父节点也是候选坝，那么海狸停在父节点和继续走到子节点时，可能留下完全一样的摄像记录。也就是说，被省去的点不能有另一个候选坝作为祖先。

题目已经给了 `p_i < i`，父节点编号一定小于子节点，祖先编号也会一路变小。因此直接省去编号最小的候选点就行：它不可能再有一个编号更小的候选祖先。其余候选点全部安装摄像头，不需要建哈希表遍历父子关系，甚至父节点数组都不用参与判断。最后的实现非常短：

```python
arr = list(read())
index = min(arr)
for i in range(m):
    if(arr[i] == index):continue
    ans.append(arr[i])
ans = [m-1] + ans
print(*ans)
```

今天 C 题并不是完全没想到，而是已经摸到了“父子相连会混淆”这一层，却没有继续把它压成编号条件。赛后再看，复杂的树结构几乎都被 `p_i < i` 这一条保证消掉了。下次再遇到这种“可以省去一个特殊点”的构造题，我得更主动地找一个天然没有候选祖先的点，而不是先想着把整棵树的信息都维护起来。

## 8 月 18 日：赛后补 D，思路能落地但复杂度不够

D 题是今天重新捡起来做的。面积 `S` 固定以后，每一个因数都对应一种整数边长的矩形；把所有可能矩形叠起来，可以看成一条高度单调下降的阶梯轮廓。我最初按照这个想法构造了每一列的高度，再做前缀和回答询问。小数据能够跑通，但 `S` 最大到 `10^14`，逐列枚举、逐列存储、逐列查询全都不可行。

最后我让 AI 帮我把完整轮廓压成因数分段。只枚举到 `sqrt(S)`，同时收集成对因数；相邻两个因数之间的列高相同，所以一整段只保存右端点，并把“段宽乘段高”加入面积前缀和：

```python
def build_matrix(n)->tuple[list[int],list[int]]:
    small_divisors = []
    large_divisors = []
    for i in range(1,isqrt(n)+1):
        if(n%i != 0):continue
        small_divisors.append(i)
        if(i*i != n):
            large_divisors.append(n//i)
    large_divisors.reverse()
    divisors = small_divisors + large_divisors
    prefix = [0]
    prev = 0
    for divisor in divisors:
        width = divisor-prev
        height = n//divisor
        prefix.append(prefix[-1]+width*height)
        prev = divisor
    return divisors,prefix
```

查询 `(x,y)` 时，`n//divisor >= y` 等价于 `divisor <= n//y`。用二分找到最后一个满足条件的因数后，前面的列统一按高度 `y` 计算，后面的部分再从压缩前缀面积里取出来。预处理从 `O(S)` 降到 `O(sqrt(S))`，每次查询也从线性扫描降到了对因数数组的二分。

这道题让我意外的地方，是想到“矩形并集形成轮廓”还远远不够。因数枚举、分段面积和查询二分必须一起接上，任何一环仍按列处理都会直接超限。现在这份代码是在 AI 帮助下完成优化的，我还不能把它算作自己独立拿下的 D 题，但至少第一眼已经能建立模型，也能在解释中慢慢弄懂 `bisect_right`、面积前缀和以及为什么要减去前一段面积。

我想等编码能力再往前走一点以后，把现在这份实现放到一边，从题面重新做一次。到时候真正要检查的不是能不能记住二分函数怎么写，而是看到 `S≤10^14` 时，能不能自己及时放弃逐列数组，想到只保存那些真正发生变化的因数断点。
