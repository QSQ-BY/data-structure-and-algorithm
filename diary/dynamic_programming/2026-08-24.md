## 两个限制条件，也可以看成背包容量

P1509 要在预算和点数都有限的情况下选择任务，第一目标是完成尽可能多的任务；数量相同时，再让总时间最短。它仍然是 0/1 背包，只是每个状态需要同时保存两层信息。

```python
new_count = count[i - 1][j - rmb][k - rp] + 1
new_time = total_time[i - 1][j - rmb][k - rp] + t

if new_count > count[i][j][k]:
    count[i][j][k] = new_count
    total_time[i][j][k] = new_time
elif (
    new_count == count[i][j][k]
    and new_time < total_time[i][j][k]
):
    total_time[i][j][k] = new_time
```

`count[i][j][k]` 记录前 `i` 个任务在预算 `j`、点数 `k` 下最多能选几个，`total_time` 则记录达到这个数量时的最短时间。比较时必须先看任务数，只有任务数相同才比较时间，这正好对应题目的优先级。

这题让我重新注意到，DP 状态里不一定只放一个数。如果答案有明确的主次目标，可以为同一个状态保存一组信息，再按题目规定的顺序比较。这里用了三维数组，时间和空间都会随 `nmr` 增长，不过数据范围都不超过 100，直接写仍然能够接受。

## 去掉书，也可以反过来想成选书

P1103 的题面说要去掉 `k` 本书，但代码先把它换成了“选择 `n-k` 本书”。把书按高度排好后，真正需要决定的是保留哪些位置，以及相邻两本保留书的宽度差。

```python
K = n-K
dp = [[float("inf")]*(n+2)for _ in range(n+2)]
for i in range(1,n+1):
    dp[i][1] = 0
    for k in range(2,i+1):
        for j in range(1,i):
            dp[i][k] = min(dp[i][k],dp[j][k-1]+abs(datas[j][1] - datas[i][1]))
```

这里的 `dp[i][k]` 表示第 `i` 本书必须保留，并且一共保留 `k` 本书时的最小不整齐度。枚举上一件保留的书 `j`，新增的代价只是两本书宽度差的绝对值。最后再从所有可能的结尾里取最小值。

“删除若干元素”有时会让状态显得别扭，换成“保留固定数量的元素”以后，前驱和新增代价都清楚了。今天其他练习里也反复遇到类似的事：题目表面在讲股票、杂务、单词或食物，落到状态上以后，还是最长子序列、前驱完成时间和多约束背包这些熟悉关系。

## 洛谷日常：两道二分答案

今天的洛谷刷题是 P1182 和 P3743，两道都是二分答案，整体不算太难。

P1182 要把数列分成若干连续段，使最大段和尽量小。答案越大，分段就越容易，因此可行性呈现出从不可行到可行的单调变化。二分一个段和上限后，只要贪心地从左往右装入当前段，放不下就新开一段，就能判断这个上限是否可行。

```python
left = max(arr)
right = sum(arr)

while(left < right):
    mid = (left+right)//2
    if(check(mid) == 1):
        right = mid
    else:
        left = mid+1
```

左右边界也很自然：答案至少要容纳最大的单个元素，至多是所有元素之和。寻找的是第一个可行值，所以 `check(mid)` 成立时保留 `mid`，否则把左边界推进到 `mid+1`。

P3743 把整数答案换成了实数时间。给定使用时长 `t` 后，每台设备缺少的能量是 `max(0, a[i] * t - b[i])`；把所有缺口相加，再和充电宝能提供的 `p*t` 比较，就得到了单调的 `check(t)`。如果所有设备的总耗能速度不超过充电速度，可以一直使用，直接输出 `-1`；否则在有限区间内做浮点二分。

这两题的共同点很明显：都不直接构造最优方案，而是先问“给我一个答案，我能不能做到”。只要这个判断随答案单调变化，后面的二分写法就很熟悉了。P1182 的检查依靠贪心分段，P3743 的检查依靠能量缺口求和，难点主要在把题意改写成一个可判定的问题。
