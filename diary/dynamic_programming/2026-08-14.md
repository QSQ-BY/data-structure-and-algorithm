# 递推篇收尾，周赛里撞上记忆化 DFS

今天正式结束了动态规划章节中递推部分的学习。和昨天一样，还是五道题，不过今天这五道题之间的跨度更大：数的计算、神经网络、栈的输出序列、传球游戏，以及最后的双圆盘汉诺塔。做完以后，递推不再只是“找到前一项再往后算”，它也可以发生在拓扑图、环形位置和方案划分里。

下一部分就要进入经典动态规划问题了。本来我以为今天只是一个平稳的章节收尾，晚上的 AtCoder 周赛却提前让我撞上了递推、DFS 和动态规划之间的那条分界线。

## 五道递推题，把状态拆分练到章节末尾

今天五道题的状态各不相同。P1028「数的计算」需要累加前面一段状态；P1038「神经网络」沿拓扑序传播节点值；P1057「传球游戏」则要处理圆环上左右两个相邻位置。最后的 P1096「双圆盘汉诺塔」得到 `f[i] = 2 * f[i-1] + 2`，答案会超过普通整数范围，所以我直接用字符串完成乘二和进位，没有为了这一道题硬套一整套大整数类。

五道题中，P1044「栈」最能代表这两天反复练习的“分类”方法：

```cpp
for(int i=3;i<=n;i++){
    f[i] = 0;
    for(int x=1;x<=i;x++){
        f[i] += f[x-1]*f[i-x];
    }
}
```

这里按照某个元素出栈时左右两部分的规模进行划分。当左边有 `x-1` 个元素、右边有 `i-x` 个元素时，两部分的方案数分别是 `f[x-1]` 和 `f[i-x]`，组合数量就是二者的乘积。枚举所有 `x` 后相加，得到 `f[i]`。以前看到这种两层循环，我很容易先把注意力放在下标上；现在更愿意先问：这次循环到底按照什么性质把全部方案分开？

做到这里，递推篇算是完整收尾了。昨天的钱币划分和数的划分还集中在二维计数，今天的五道题则把同一种状态思维带到了更多题型里。下一步，我准备继续往经典动态规划问题走。

## AtCoder 周赛：第三题卡在了“会 DFS”之后

今天的 AtCoder 周赛只有 60 分钟，节奏比我预想得紧。前两题是比较直接的签到题，很快就写完了；第三题要求在网格中只能向右或向下移动，求从左上角到右下角能够收集到的最大价值。

看完题面，我很自然地想到了之前学过的回溯。每个格子只有向下和向右两个选择，用 DFS 把路径展开，再记录到达每个位置时最大的前缀和。思路并不是完全没有根据，代码也确实能得到正确答案：

```cpp
void dfs(long long x,long long y,long long sum){
    if(dp[x][y] >= sum) return;
    dp[x][y] = sum;
    if(x == n and y == m){
        return;
    }
    long long dx;
    long long dy;
    dx = x+1;
    dy = y;
    if(dx<=n and dx>=1){
        dfs(dx,dy,sum+g[dx][dy]);
    }
    // ……省略结构相同的向右分支
}
```

真正的问题藏在 `sum` 里。`dp[x][y]` 虽然可以剪掉更差的路径，但只要后来出现一个更大的前缀和，这个格子下面的整片搜索就要重新展开。同一个位置不是只计算一次，数据稍微变大以后，运行时间就迅速失控。把 `map` 换成二维数组只能减少查找开销，并没有改变重复搜索的次数。

赛后请教 AI，我才知道这道题真正希望我想到的是动态规划，或者把 DFS 写成记忆化搜索：让 `dfs(x,y)` 表示“从当前格子走到终点的最大价值”，计算一次后直接保存返回值。这样每个格子只需要求解一次，复杂度才能稳定在 `O(NM)`。

这也解释了我在比赛中为什么会手足无措。我不是完全不会做，移动方向、递归出口和基本剪枝都能写出来，但题目要求的状态定义已经超出了我目前学到的位置。60 分钟里，我一直在熟悉的回溯框架里继续优化，自然很难突然把它改造成还没有正式学过的记忆化 DFS。

## 留到经典动态规划里再回来

今天的比赛有些可惜，前两题之后没能继续推进名次。不过第三题并没有白卡：我又完整练了一次网格 DFS，也第一次具体看到“能够剪枝的 DFS”和“每个状态只计算一次的记忆化 DFS”究竟差在哪里。

接下来开始学习经典动态规划问题时，我想把这道 C 题一直放在旁边。等真正学到记忆化搜索，再回来把 `sum` 从参数里拿掉，让 DFS 返回一个状态的答案。到那时，今天卡住的地方应该会比单独背一条状态转移更容易记住。
