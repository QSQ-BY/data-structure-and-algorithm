## 两道 DFS：边界不是只判断成功

第一题 P1473「零的数列」要在 `1～N` 之间插入空格、加号或减号，让表达式结果为零。DFS 的三种选择并不难，空格连接数字时需要撤回原来的末项，再把拼接后的数字按原符号加入当前结果，这一层状态我基本理顺了。

这道题真正提醒我的是：递归出口不能只写“满足答案时返回”。当符号已经全部放完，即使当前结果不为零，也必须结束这一条路径。如果只处理 `cnt == N && current_result == 0`，那些不符合答案要求的叶子还会继续调用 DFS，层数越走越深，永远回不到合法状态。

以前我检查边界时，总在问“什么时候找到答案”；今天开始意识到，还要问另一句话：**什么时候已经不可能成为答案？** 成功和失败都是递归树的叶子，两个出口缺一不可。

第二题 P2040「打开所有的灯」用九位二进制整数表示整个棋盘。某一位为 `1` 表示对应的灯亮着，按下一盏灯时，对它自己和上下左右的位置执行异或。这个状态压缩我已经能比较自然地写出来：二维坐标通过 `x * 3 + y` 映射到某一位，`state ^= 1 << index` 就完成一次翻转。

```cpp
void dfs(int t,int step){
    if(dp.find(t) == dp.end()){
        dp[t] = step;
    }else{
        if(dp[t] <= step) return;
        else dp[t] = step;
    }
}
```

这里的 `dp[t]` 记录到达状态 `t` 的最少步数。如果以前已经用更少或相同的步数到达过它，当前路径就没有继续搜索的价值。这个剪枝也能阻止不同灯状态之间反复绕圈。

我一开始却在调用 DFS 之前就执行了 `dp[t] = 0`。随后 `dfs(t, 0)` 一进入函数，就发现当前状态已经以相同步数出现过，于是直接返回，九个按灯分支一个都没有展开。问题不在状态压缩，也不在 DFS 主体，而在“谁负责登记初始状态”：既然 DFS 入口本身会登记，就不能在外面提前占位。

灯的翻转则完全落在位运算上：

```cpp
int next_t = t;
for(int k=0;k<5;k++){
    int dx = i+dir[k][0];
    int dy = j+dir[k][1];
    if (dx >= 0 and dx < 3 and dy >= 0 and dy < 3) {
        int index = dx * 3 + dy;
        next_t ^= 1 << index;
    }
}
```

这两道题放在一起看，正好补全了今天对边界条件的认识。一类边界决定什么时候停止，一类剪枝决定什么状态不值得继续。写完递归主体以后，我以后要固定检查三件事：成功叶子是否返回、失败叶子是否返回、进入下一层前是否错误地改变了判重状态。

## 动态规划开篇：先把状态说成人话

今天的主线正式进入动态规划，第一部分先从递推开始。刚接触时，我觉得它和马尔可夫链、递归函数的设计有些相像，都是从已有状态推出下一个状态。不过动态规划比直接递归更强调两件事：状态必须覆盖题目真正需要区分的信息，递推式里的每一项也必须对应一类互不重叠的方案。

如果状态定义含糊，后面的式子即使长得像答案，也很难判断有没有重复或遗漏。所以今天五道题里，我最是先用一句话解释 `f[i][j]` 到底表示什么，这里就展开两道让我影响深刻的题目剩下的三道题都是一样的方法思路。

## 钱币划分：一次分类消掉顺序重复

钱币问题要求使用前若干种面额凑出目标金额，硬币数量不限，但方案不考虑排列顺序。我最后采用的状态是：

```text
f[i][j]：使用前 i 种钱币凑出 j 元的方案数
```

核心转移如下：

```cpp
for(long long i=1;i<=m;i++){
    f[i][0] = 1;
    for(long long j=1;j<=n;j++){
        f[i][j] = f[i-1][j];
        if(j<val[i-1]) {
            f[i][j] = f[i][j]%9973;
            continue;
        }
        f[i][j] += f[i][j-val[i-1]];
        f[i][j] = f[i][j]%9973;
    }
}
```

`f[i-1][j]` 表示完全不用第 `i` 种钱币；`f[i][j-val[i-1]]` 表示至少使用一枚第 `i` 种钱币，先拿走这一枚，再继续用前 `i` 种钱币凑剩余金额。这两类方案不会重叠，加起来正好覆盖全部情况。

我觉得精妙的地方在于，“不考虑顺序”没有通过排序或集合去重解决，而是直接写进了状态维度。每一层只决定是否继续使用当前及更早的钱币，不会重新回头排列已经处理过的面额。递推式本身就排除了 `(1,2,2)` 和 `(2,1,2)` 被重复统计的可能。

这题也让我更直观地看到完全背包的味道：第二项仍然停留在第 `i` 行，因为同一种钱币可以继续使用。下标到底回到 `i-1`，还是留在 `i`，不是格式问题，它直接对应“每件物品只能用一次”还是“可以无限使用”。

## 数的划分：按“有没有 1”拆成两个世界

最后一题 P1025「数的划分」要求把整数 `i` 拆成 `j` 份，不考虑各部分的排列顺序。这里的状态是：

```text
f[i][j]：把整数 i 划分成 j 个正整数的方案数
```

递推只有一行：

```cpp
for(int i=1;i<=n;i++){
    for(int j=1;j<=i and j<=k;j++){
        f[i][j] = f[i-1][j-1]+f[i-j][j];
    }
}
```

这次分类依据是方案中是否存在 `1`。

如果至少有一个 `1`，删掉它以后，问题变成把 `i-1` 分成 `j-1` 份，对应 `f[i-1][j-1]`。如果所有部分都大于 `1`，就从每一份里各减去 `1`，总和减少 `j`，份数不变，对应 `f[i-j][j]`。

这比直接枚举每一份取多少更干净。DFS 需要维护当前位置、当前最小值和已有总和，还要不断检查剩余份数是否可行；递推则找到了一个能把全部方案一刀分开的性质。两类方案之间没有交集，各自又能无损地还原回来，所以这一行式子虽然短，背后的分类非常完整。
