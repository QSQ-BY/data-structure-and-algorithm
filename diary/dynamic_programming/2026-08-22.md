## 多重背包：按余数分组后维护滑动窗口

多重背包以前用过二进制拆分，把一类物品拆成若干件 0/1 物品。今天学的单调队列方法走了另一条路：容量按照物品体积 `v` 的余数分组，同一组中的状态每次相差一个 `v`，于是“最多选 `s` 件”就变成了固定长度的滑动窗口。

```python
for remainder in range(0,v):
    q = deque()
    for j in range(remainder,V+1,v):
        dp[index2][j] -= j//v*w
        while(len(q)>0 and dp[index2][q[-1]] < dp[index2][j]):
            q.pop()
        q.append(j)
        while((q[-1] - q[0])//v > s):
            q.popleft()
        dp[index1][j] = dp[index2][q[0]] + j//v*w
```

把原状态减去 `j // v * w` 后，转移中随选取件数变化的价值被消掉了。队列里只保留当前窗口中有可能成为最优解的位置，队首就是这一容量需要的最大值；最后再把当前位置对应的价值加回来。每个位置至多入队、出队一次，所以每种物品只需线性扫过所有容量，总复杂度是 `O(nV)`，空间由两行 DP 承担。

这套写法让我眼前一亮。原本需要枚举物品件数的转移，经过余数分组和代数变形后，居然能直接套进单调队列。难点不在队列本身，而在于先把那个“窗口”从背包公式里找出来。

## 白色矩形：把二维矩阵压成一排高度

矩形这道题对状态的定义也很巧。先把每个白格向下连续的白色数量记成高度，固定一行后，二维的全白矩形就变成了直方图问题。代码从右往左维护一个单调栈，找到右侧第一个高度更小的位置：

```python
for i in range(n,0,-1):
    q = deque()
    q.append(m+1)
    for j in range(m,0,-1):
        while(f[i][q[-1]] >= f[i][j]):
            q.pop()
        dp[j] = f[i][j]*(q[-1]-j) + dp[q[-1]]
        dp[j]%=100007
        ans += dp[j]
        ans %= 100007
        q.append(j)
```

`dp[j]` 表示以当前行、当前列作为左边界时能够形成的白色矩形数量。到下一个更矮的位置之前，当前高度可以完整延伸，贡献是 `f[i][j] * (q[-1] - j)`；越过这个位置后，剩下的部分直接复用 `dp[q[-1]]`。这样，每一行都能在线性时间内算完，总复杂度是 `O(nm)`。

我以前看到矩形计数，很容易先想到枚举左上角、右下角。这道题却先重新解释每个格子的含义，再让单调结构处理高度关系。状态怎么定义、后面的递推怎么接，都很值得再单独做一遍。

## 老式打字机：斜率优化把转移候选排成一条队列

最后一种是斜率优化。老式打字机的基础转移并不难写：令 `S[i]` 为前缀和，`dp[i]` 为打印前 `i` 个字符的最小磨损，则

```text
dp[i] = min(dp[j] + (S[i] - S[j])² + M)
```

直接枚举 `j` 是 `O(n²)`。展开平方后，把只与 `j` 有关的量放到一边，就能把两个候选决策的优劣写成斜率关系。代码用双端队列保存仍可能成为最优解的候选点：

```python
q = deque()
q.append(0)
for i in range(1,n+1):
    while(len(q)>=2 and slope(q[1],q[0]) < 2*sum[i]):
        q.popleft()
    set(i,q[0])
    while(len(q) >=2 and slope(q[-1],q[-2]) > slope(i,q[-1])):
        q.pop()
    q.append(i)
```

计算 `dp[i]` 前，队首如果已经不可能优于第二个候选，就把它移走；加入新候选 `i` 时，再从队尾删掉会破坏斜率顺序的点。由于题目中的字符消耗都是正数，前缀和单调递增，每个候选只会进出队列一次，转移便从 `O(n²)` 降到了 `O(n)`。

斜率优化最巧妙的地方，仍然不是最后这几行队列代码，而是前面的推导：展开式子、分离变量、比较候选，再把关系总结成可以维护的通用模型。现在我能跟着公式看懂它，但要在比赛里从一条普通 DP 转移独立推到这里，我还差得很远。这大概只能靠以后反复推、反复写，慢慢把它变成自己的东西。

## 洛谷三题：从记忆化搜索到状态压缩

今天的第一道洛谷题 P8786 是一道比较直接的 DFS，但我一开始看错了题意，在错误的方向上耗了不少时间。但后面也是顺利解决了，也是在这道题里，我第一次使用 Python 的 `@cache`：相同参数的递归结果只算一次，搜索就不会在重复状态上反复展开。

这里需要记住的是，缓存键只由函数参数组成。如果某个会变化的全局状态会影响返回值，它也应该作为参数传进去，否则缓存可能复用错误结果。

P9242 接龙数列是一道入门级 DP。最初我用双重循环枚举前驱，和朴素的最长上升子序列很像，但 `N` 到 `10^5`，这样写一定会超时。后来把状态压成长度为 10 的数组：`len[d]` 保存末位数字为 `d` 的最长接龙数列长度。读到一个首位为 `head`、末位为 `tail` 的数时，只需更新

```text
len[tail] = max(len[tail], len[head] + 1)
```

问题需要的并不是“以每个位置结尾的所有答案”，而只是按末位数字分类后的最优值。这个思路和最长上升子序列维护最优结尾很像，都是把大量历史状态压成真正会参与后续转移的那一小部分。

最后的 P12349 难了很多。刚读题时，我几乎完全无从下手，最后通过和 AI 交流才把状态理顺。翻转整行不会改变同行左右硬币的关系，只会改变相邻两行之间是否同面。因此可以先用 `val[i][up][down]` 预处理第 `i` 行在上下边界状态确定时的总价值，再用只有两个边界状态的 DP 逐行转移。原本看起来有 `2^n` 种翻转方案，最后被压成了 `O(nm)` 的预处理和常数状态转移。

这道题我现在是能沿着实现解释清楚了，但还不能算独立想到。以后再碰到“对整行或整列进行操作”的矩阵题，我想先检查两件事：操作内部有哪些关系始终不变，真正受到影响的是否只有相邻边界。P12349 的突破口就藏在这里。
