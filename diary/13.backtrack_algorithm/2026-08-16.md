状态掩码也比前几天顺手得多。以前看到一串左移、异或和 `lowbit`，还需要把每一位画出来才能确认含义；现在已经能自然地把一个整数看成一组布尔状态，再围绕“这一位表示什么”“下一层应该删去哪一位”去写代码。今天真正还会让我绕进去的，是递归函数到底应该返回什么，以及上一层拿到这个返回值以后该做什么。

## 三道题，三种不同的返回方式

B4158 需要给字符串中的 `*` 依次填数字，并找到第一个能够组成质数的答案。这里的状态很直接：`state` 表示还有哪些星号没有填写，`index` 保存星号在原字符串中的位置，`string` 则是当前已经填到一半的结果。

我让递归函数返回 `int | None`。找到答案就把这个整数一路向上传，没有找到则返回 `None`：

```python
def dfs(state:int,index:list[int],string:list[str])->int|None:
    if(state == 0):
        if(is_prime(int("".join(string))) == True):
            return int("".join(string))
        return
    bit = (-state&state)
    string_index = index[bit.bit_length() - 1]
    for digit in range(10):
        string[string_index] = str(digit)
        new_state = state^bit
        ans = dfs(new_state,index,string)
        if(ans is not None):
            return ans
        string[string_index] = "*"
    return
```

这个返回值并不汇报“这一层填得对不对”。它回答的是：从当前状态继续填下去，能不能得到一个完整答案？如果可以，就把答案本身带回来，并且停止搜索其他分支。

P10386 又不一样。这一题要统计所有满足条件的 5×5 棋盘，因此不能找到一个方案就结束。递归函数不需要返回成功或失败，而是把所有合法叶子都走一遍，再通过全局变量累计答案：

```python
if pos == N * N:
    if check(g):
        ans += 1
    return
```

同样是 DFS，一个要“找到第一个”，一个要“统计全部”，返回值的设计自然不同。以前我容易先写一个 `dfs()` 再临时决定返回什么，结果上一层到底应该继续、退出还是累加就会乱。今天把这两题放在一起看，我觉得顺序应该反过来：先写清楚递归函数向调用者承诺什么，再写递归过程。

## 数字接龙：布尔返回值表示“后面存在完整路径”

数字接龙是今天最难的一题。棋盘上的数字必须按照 `0,1,...,k-1` 循环，所有格子恰好经过一次，最后还必须落在右下角；如果有多条路径，还要输出字典序最小的一条。

不考虑对角线交叉时，我已经能把主体状态写出来：`pos` 是当前位置，`visit` 表示还没走过的格子，`cur_number` 是当前位置的数字，`ans` 保存方向序列。起点先从 `visit` 中删掉，每次移动再清除下一格对应的 bit。

这题里的 `dfs()` 返回 `bool`。它真正表达的是：从当前状态出发，后面是否存在一条覆盖所有剩余格子、并且最终到达右下角的完整路径。

```python
next_visit = (1<<next_pos)^visit
ans.append(dir_ans[i])
temp_ans = dfs(next_pos,g,next_visit,next_number)
if(temp_ans == True):
    return True
ans.pop()
return False
```

递归返回 `True` 时，当前 `ans` 已经是一条完整答案，所以这一层不能再 `pop()`，而要立刻继续向上传递成功。返回 `False` 才说明刚才的方向走不通，需要撤销选择，再试下一个方向。循环结束仍然没有成功，当前状态才是真的无解。

我现在能把这段流程讲清楚，但写的时候还是容易在“谁返回给谁”这里绕一下。问题不止是偶尔把某个判断条件写反，我还没有完全习惯从递归函数的调用者视角定义返回值。接下来再遇到搜索题，我准备先在函数旁边写一句话：`dfs(state)` 的返回值究竟回答什么问题。等这句话确定以后，再决定什么时候返回、上一层收到结果后怎样处理。

## 对角线交叉：状态不只属于格点，也可能属于边

数字接龙最后留下的坑是对角线交叉。我第一次写时完全没有处理这个限制。回头看，这并不是在原来的 `visit` 后面随便补一个条件就行，因为 `visit` 只记录哪些格点走过，却没有记录格点之间究竟连过哪条边。即使某两个点都访问过，也不能说明它们之间的对角线真的出现过。

八皇后里我接触过用掩码记录正、负对角线，但那里的一个 bit 对应棋盘上的一整条对角线。数字接龙不同：可能发生交叉的是每个单位方格内部的两条短对角线。问了 AI 以后我才知道，可以给 `(n-1)×(n-1)` 个单位方格分别编号，再用一个新的位图记录哪些方格已经使用过对角线。

如果一次移动同时改变一行和一列，它就是对角线移动。取两个端点行号、列号的较小值，可以得到所在单位方格的左上角；再按行优先给这个方格编号。对应 bit 已经是 `1`，说明这个方格之前用过另一条对角线，这一步会发生交叉；否则设置该 bit，并把新位图传给下一层。

这里一个方格只需要一个 bit，不必区分 `/` 和 `\`。已经走过的那条对角线无法再次使用，因为两个端点都访问过了；所以同一方格第二次出现对角线移动，只可能走另一条边，而这两条边一定相交。

这套方法我今晚已经把原理弄懂了，但没有继续赶着把代码补完。明天我想先不照着现成代码抄，自己给 DFS 增加一个对角线位图参数，把方格编号、冲突判断和下一状态写出来，再用今天的样例验证路径能否从忽略交叉时的 `35271244` 回到合法的 `41255214`。这会是检验我是否真的理解这种状态定义，而不只是看懂解释的最好办法。
