# 2026-08-06：单调结构收尾，回溯从八皇后开始

今天的代码分成三块。第一块是单调栈与单调队列最后三道习题，第二块是两道洛谷日练，第三块则是新章节回溯算法的开篇。真正占据我大部分注意力的还是第一块和第三块：前者把单调结构推到了比“维护最大值、最小值”更深的位置，后者则让我第一次正面面对状态树、DFS 和剪枝。

## 接雨水：单调栈不只是拿来找最近元素

最后三道单调结构习题里，接雨水给我的冲击最大。前面刚做完最大矩形面积，我很自然地继续想：能不能利用单调栈维护的大小关系，直接找到左右边界？但接雨水和最大矩形的建模方式完全不同。它不是先求出每根柱子左右最近的某个元素，而是让整个栈模拟水槽逐层形成的过程。

```cpp
stack<int> s;
for(int i=0;i<height.size();i++){
    while(!s.empty() and height[s.top()] < height[i]){
        int cur_h = height[s.top()];
        s.pop();
        if(s.empty()) break;
        ans += (min(height[s.top()],height[i]) -cur_h)*(i - s.top()-1);
    }
    s.push(i);
}
```

新来的 `height[i]` 可以充当右侧墙壁，被弹出的栈顶是水槽底部，弹出后的新栈顶则是左侧墙壁。左右墙壁中较矮的一边决定水面高度，两堵墙之间的下标距离决定宽度。每弹出一层，就结算这一层新增的水量；如果弹出后栈空了，说明左边没有墙，自然也接不住水。

这道题如果让我完全从零开始想，我大概很难主动联想到单调栈。以前我更关注“栈最终维护了什么性质”，今天才开始注意“元素为什么在这一刻被弹出”。接雨水的答案正藏在这个弹出过程里，从题面走到这段代码的抽象实在是难。

## 最短子数组：队列里保存的是候选左端点

第二题要求找到和至少为 `k` 的最短非空子数组。只要涉及区间和，第一步还是前缀和：区间 `[j,i)` 的和可以写成 `prefix[i] - prefix[j]`。真正困难的是，单调队列里的每一个下标究竟代表什么。

```cpp
deque<int> q;
q.push_back(0);
for(int i=1;i<n+1;i++){
    while(!q.empty() and prefix[i] - prefix[q.front()] >= k){
        ans = min(ans,i - q.front());
        q.pop_front();
    }
    while(!q.empty() and prefix[q.back()] > prefix[i]) q.pop_back();
    q.push_back(i);
}
```

队列保存的是一批尚未被淘汰的候选左端点，它们对应的前缀和保持单调。队头是当前最小的候选前缀和，因此最容易与 `prefix[i]` 凑出一个达到阈值的区间。一旦满足条件，就不能只记录一次答案：继续弹出队头、检查下一个候选，区间会越来越短，直到不再满足阈值为止。

队尾的处理则是在删除“已经被支配”的选择。如果新前缀和更小，而且下标更新，那么旧的较大前缀和以后既不能得到更大的区间和，也不能得到更短的长度，继续留着没有意义。今天把队头和队尾两端的职责分开以后，我才算真正明白这道题，而不是只记住两段 `while`。

## 双生序列：比较的不是数值，而是结构形成的过程

最后一题双生序列一眼就是单调队列题，实际实现时却最让我犯难。题目要求两个序列任意区间内“最右侧最小值”的下标相同。

最难想到的点是：如果两个结构在处理每一个位置后元素数量始终相同，那么这一轮弹出的元素数量也相同。只要上一轮留下的下标结构一致，两边弹出同样多的下标、再压入同一个新下标，结构就会继续一致。这样才能保证以后查询任意区间时，最右侧最小值落在相同位置。遇到相等元素时还要弹出旧下标，因为题目指定取最大的下标，新位置会取代旧位置。

即使听过老师讲解，这个弯也很难立刻转过来。它让我意识到，单调栈和单调队列的意义远不止“队头是最值”。队列有多少元素、每个元素为何留下、一次加入触发了多少次弹出，这些都可能编码题目需要的关系。今天这三道收尾题确实很值，它们把我的注意力从最终性质推回了结构形成的全过程。

## 两道洛谷日练：今天确实可以一笔带过

今天的两道洛谷题都比较直接。「小梦的 AB 交换」只要注意最终字符串只有 `ABAB...` 和 `BABA...` 两种形态，再统计某一类位置上的字符数量，就能用一点“数学直觉”得到最少交换次数。

B3612「求区间和」则是最标准的前缀和。预处理 `prefix[i]` 后，每次询问 `[l,r]` 直接计算 `prefix[r] - prefix[l-1]`，预处理 `O(n)`，每次查询 `O(1)`。这两题没有带来太多新的困难，也就不展开记录了。

## 回溯开篇：先把 DFS 的骨架看清楚

今天开始进入回溯算法。回溯的核心依靠 DFS，也就是深度优先搜索，不是广度优先搜索。它先把问题抽象成一棵状态树：每走到一层就做一个选择，沿着选择继续向下；如果当前状态已经不可能产生合法答案，就提前剪枝，不再搜索这棵子树。

老师讲的第一题是经典的 N 皇后。位运算版本把列、两条对角线的可用状态压进 `t1`、`t2`、`t3` 三个二进制数，再用 `-t & t` 依次取出可选位置，并借助哈希表把位权映射回列号。这种写法紧凑得有些吓人。对现在的我来说，最基础的 DFS 流程还没有完全形成直觉，一上来再叠加状态压缩、异或和位移，理解难度一下高了很多。

所以我后来又去力扣找了一种更常规的写法，先只保留“逐行放置、检查冲突、递归下一行”这条主线：

```cpp
void dfs2(int n,int r){
    if(r >= n){
        addRes(n);
        return;
    }
    for(int i=0;i<n;i++){
        arr[r] = i;
        if(check(r)) dfs2(n,r+1);
    }
}

bool check(int r){
    for(int i=0;i<r;i++){
        if(arr[i] == arr[r] or abs(i-r) == abs(arr[i]-arr[r])){
            return false;
        }
    }
    return true;
}
```

`r` 表示当前正在安排哪一行，`arr[r]` 表示这一行的皇后放在哪一列。`check` 只检查前面已经确定的行：列号相同代表同列冲突，行差绝对值等于列差绝对值代表处在同一条对角线上。当前列不合法就不再向下递归，这就是最直观的剪枝。这里也不需要专门“撤销” `arr[r]`，因为下一次循环会直接覆盖当前位置，后续检查只读取已经确定的前 `r` 行。

这版代码让我先看清了回溯的骨架：做选择，检查，向下搜索，走到叶子时记录答案。位运算版本做的事情没有变，只是把“哪些列和对角线还能用”压缩成了几个整数，从逐个比较变成了批量维护状态。

明天我准备重新看一遍老师讲八皇后的那段视频，不过这次不打算直接盯着完整代码硬啃。我想先拿 `n=4` 手动走几层，把每一步的可用列、两条对角线以及三个掩码分别写出来，再对照 lowbit 和异或操作。只要能把位掩码版和今天这套普通 DFS 一步步对应上，它就不会再只是“一段很巧但看不懂的代码”了。
