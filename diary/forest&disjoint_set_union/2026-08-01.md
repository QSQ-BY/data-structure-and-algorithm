# 2026-08-01：把并查集从现场手搓变成两套模板

今天又是一天学完一章，从森林一路学到并查集。我先从最底层的 `quick_find` 和 `quick_union` 写起，再补上路径压缩、按集合大小合并，最后把普通并查集和带权并查集分别整理成了可复用模板。七道练习做下来，这一章的知识基本收尾了。

今天真正让我满意的是把并查集整理成了以后可以直接拿来用的工具。C++ 标准库里没有现成的完整并查集，每次遇到相关题目都要自己实现；如果只记住几行 `find` 和 `merge`，题目稍微多一种操作，代码就又要从头改。现在我手里有两套模板，下一次可以先判断题目属于普通连通关系还是带权关系，再选择对应版本。

## 从颜色数组到一片森林

`quick_find` 的思路很直白：给同一集合里的节点涂上相同颜色。查找时直接读取颜色，复杂度是 `O(1)`；合并时却要扫描整个数组，把一种颜色全部换成另一种颜色，复杂度是 `O(n)`。它让我第一次看清，并查集真正要维护的其实是“每个节点属于哪个集合”。

`quick_union` 把颜色数组换成了父节点数组。每个集合是一棵树，根节点代表整个集合，合并两个集合只需要连接两棵树的根。继续加上路径压缩和按集合大小合并以后，普通并查集的核心就变成了下面这段：

```cpp
int find(int x){
    if(father[x] == x) return x;
    return father[x] = find(father[x]);
}

int merge(int a,int b){
    int set_a = find(a);
    int set_b = find(b);
    if(set_a == set_b) return 0;
    if(size[set_a] < size[set_b]){
        father[set_a] = set_b;
        size[set_b] += size[set_a];
    }else{
        father[set_b] = set_a;
        size[set_a] += size[set_b];
    }
    collection_num--;
    return 1;
}
```

路径压缩让查找过的节点直接指向根，按大小合并则尽量把小树接到大树下面。两个优化一起使用后，单次操作的均摊复杂度接近常数。基础代码里所谓的 weighted quick union，权重指的是集合大小；它和后面“边上带有关系值”的带权并查集不是同一种权重。把这两个概念分清以后，整章的结构顺了很多。

## 普通并查集不再只有 `find` 和 `merge`

以前想到并查集模板，我脑中大概只有初始化、查找和合并。今天真正整理时，我把平时可能反复用到的操作都补了进去：维护元素数量 `element_num` 和集合数量 `collection_num`，合并一个数组中的全部节点，插入新节点，判断两个或多个节点是否连通，以及查询集合大小。

我还加入了 `restore(index)`，用于把一个节点从原集合中单独抽离。并查集天然擅长合并，不擅长拆分，所以这个操作不能只改一条父指针。模板会扫描原集合的成员、重新建立剩余集合，再让被抽离的节点回到独立状态。它的复杂度是 `O(nα(n))`，实际接近 `O(n)`。这个操作也让我更清楚并查集能力的边界：路径压缩带来了很快的查询，同时也丢掉了适合随意拆分的树结构信息。

普通版本随后用在了最长连续序列、被围绕的区域、岛屿数量和省份数量等题目里。这些题表面上分别是数组、二维网格和图，最后问的却都是同一件事：哪些元素能够通过某种规则归到同一个连通块。

## 带权并查集：连通以后还要知道关系

普通并查集只回答“是否属于同一个集合”。带权并查集还要回答：如果已经连通，两个节点之间到底是什么关系。

我在模板里约定：

```text
val[x] = weight(x) - weight(father[x])
```

路径压缩时，父节点改变了，`val[x]` 也必须同步累加。合并时给定 `weight(a) - weight(b) = t`，需要先把这个条件换算成两个根节点之间的权值差：

```cpp
int find(int x){
    if(father[x] == x) return x;
    int parent = father[x];
    int root = find(parent);
    val[x] += val[parent];
    father[x] = root;
    return root;
}

int merge(int a,int b,long long t){
    int set_a = find(a);
    int set_b = find(b);
    if(set_a == set_b) return 0;

    long long root_difference = t - val[a] + val[b];
    // ...
}
```

这一版同样加入了集合数量、数组合并、插入、抽离、集合大小和权值差查询。`restore(index)` 比普通版本更麻烦：如果抽离的是根节点，剩余元素要选择新根，并把每个成员的权值从“相对旧根”改成“相对新根”。重新计算后，剩余元素之间的两两权值差保持不变。

实际题目需要取模时，我没有把模数写死在模板内部。模板只保存普通加法意义下的权值差，石头剪刀布在外部对 `3` 取模，两座监狱的关系在外部对 `2` 取模。这样同一套代码不用绑定某一道题。

## 从模板回到题目

“程序自动分析”这道题让我又看到了并查集之外的一层处理。变量编号可能很大，不能直接拿来当数组下标，于是先用哈希表把实际编号映射成 `0` 开始的连续编号，再建立并查集：

```cpp
unordered_map<int,int> id;
id.max_load_factor(0.7f);
id.reserve(a.size() * 2);

int index = 0;
for(int i = 0; i < a.size(); i++){
    if(id.find(a[i]) == id.end()){
        id[a[i]] = index;
        index++;
    }

    if(id.find(b[i]) == id.end()){
        id[b[i]] = index;
        index++;
    }
}

UnionSet u(index);
```

映射完成后，先合并全部相等关系，再检查每一条不等关系。如果一对要求不相等的变量已经落在同一集合中，整组约束就无法同时成立。这里真正重要的是把“变量编号”和“并查集内部下标”分开，而不是简单把数组开得更大。

石头剪刀布和关押罪犯则让我把带权关系落到了具体问题里。前者用模 `3` 的差值表示胜、负、平，后者用模 `2` 的差值表示两个人是否应该被分到同一侧。至此，两套模板各自适合什么题，已经比刚开始时清楚得多。

今天写下的模板以后大概会被复制很多次。比复制本身更值得记住的是几个判断：题目只问分组，还是还要求组内关系；权值差的方向怎样定义；取模应该放在模板里，还是留给具体问题。下一次再遇到连通性题，我想先把这三个问题想明白，再决定拿出哪一套模板。
