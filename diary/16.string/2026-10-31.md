## Sunday 和 Shift-And，确实有意思

这几天接触了不少单模匹配和多模匹配算法。有些算法读起来很舒服，尤其是 Sunday 和 Shift-And，代码不长，想法却很巧。

Sunday 最吸引我的地方，是它决定窗口移动距离时，看的竟然是当前窗口后面的那个字符。原来匹配失败后，不一定非得围着失配的位置做文章，还能利用下一步将要遇到的信息。

下面摘的是我在 [Sunday 实现](../../source/improved_part/16.string/1.single_mode_matching_algorithm/2.sunday.cpp)中写的搜索循环，省略了前面的移动距离表预处理：

```cpp
    for(int i=0;i+m <= n;i += len[s[i+m]]){
        int flag = 1;
        for(int j=0;t[j];j++){
            if(s[i+j] == t[j]) continue;
            flag = 0;
            break;
        }
        if(flag == 1) return i;
    }
```

`i` 是窗口起点，`m` 是模式串长度，`s[i+m]` 就是窗口后面的字符。如果这个字符没在模式串里出现，窗口直接移动 `m+1`；如果出现过，就让模式串中最右边的那个同字符与它对齐，对应的移动距离是 `m-j`。前面依次赋值 `len[t[j]]`，后面的出现位置会覆盖前面的，正好留下最右位置对应的距离。

这个移动规则很好理解，预处理也简单。不过窗口内部仍然要逐个比较字符，最坏情况下依然可能达到 `O(nm)`。我喜欢的是它用很少的代码就能利用额外信息跳过一些位置。

Shift-And 则换了一个方向：把当前所有可能匹配的前缀状态，放进一个整数里一起更新。

[当前实现](../../source/improved_part/16.string/2.multiple_mode_matching_algorithm/2.shift_and_or.cpp)中，预处理后的 `code[c]` 记录字符 `c` 在模式串中的位置。搜索部分只有几行：

```cpp
    int p = 0;
    for(int i=0;s[i];i++){
        p = (p<<1|1)&code[s[i]];
        if(p&(1<<(n-1))){
            return i-n+1;
        }
    }
```

这里 `n` 是模式串长度，`p` 的第 `j` 位为 1，表示截至当前母串字符，模式串长度为 `j+1` 的前缀已经匹配上了。

1. `p<<1` 把原来的匹配状态向后推进一位。
2. `|1` 允许从当前字符重新开始一次匹配。
3. 再与字符掩码相与，留下当前字符能够接上的状态。
4. 第 `n-1` 位为 1，就说明整个模式串匹配成功。

一次位运算就能同时推进这么多状态，这一点很漂亮。当前版本用一个 `int` 保存状态，限制模式串长度不超过 32 字节。在这个范围内，预处理和扫描加起来是 `O(n+m+256)`，字符表之外只需要一个状态变量。

Shift-Or 用 0 表示有效状态。这样一来，字符掩码、初始状态和成功条件都要跟着反过来。我想记住的是两种状态定义之间的对应关系，尤其是为什么 Shift-And 需要补上最低位的 1，而 Shift-Or 可以在反向编码下省掉这一步。

## 有些算法了解过就先放下

Rabin–Karp 这次也写了单模和多模两个版本。它用滚动哈希维护窗口，把多数不可能匹配的位置先筛掉；哈希值相同时，再比较原字符串。多模版本里，同一个哈希值对应一个模式串下标列表，这样发生碰撞时也不会把候选模式串覆盖掉。我现在写的版本要求模式串等长，便于用同一个窗口扫描。

BM 给我的感觉就没这么轻松了。坏字符、好后缀，再加上相应的预处理，实现又臭又长，细节也多。花不少时间把这些数组的含义理顺之后，我还是觉得，以我现在做题的需要，不太值得继续在它上面投入很多时间。

这些算法各自都能提供一种看待字符串匹配的角度。Sunday 的跳跃、Rabin–Karp 的哈希筛选、Shift-And 的位状态压缩，我都愿意了解。但字符串算法的名字太多，如果每一种都要求自己练熟，这一章还会拖很久。

## 重点还是 KMP 和后面的字典树

KMP 是我准备多花时间的部分。目前已经写了一版实现，接下来要把 `next` 数组和失配回退真正用熟。

我现在的 [KMP 实现](../../source/improved_part/16.string/1.single_mode_matching_algorithm/4.KMP.cpp)用末尾下标表示已匹配前缀，`j == -1` 表示还没有匹配上字符。下面是搜索部分，省略了前面的 `next` 数组构造：

```cpp
    for(int i=0;i<n;i++){
        //失配，保留较短的已匹配前缀，主串的指针保持不变,
        //只对模式串的指针进行回退操作
        while(j != -1 and s[i] != t[j+1]){
            j = next[j];
        }

        if(s[i] == t[j+1]){
            j++;
        }
        if(j == m-1){
            return i - m + 1;
        }
    }
```

匹配失败时，`j = next[j]` 会保留一段仍然有用的匹配结果：已经匹配部分的后缀，同时也是模式串的前缀。当前母串字符继续与这个更短前缀的下一位尝试匹配。这样就能复用已经知道的信息，主串指针不用回退。

这份实现里的 `next[j]` 是下标，表示对应前缀的最长相同真前后缀末尾位置，长度要再加 1。这个约定需要一直保持一致。预处理和匹配都通过回退链复用信息，总时间复杂度是 `O(n+m)`。
