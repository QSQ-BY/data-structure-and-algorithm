## 普通字典树：路径表示前缀，标记区分完整单词

普通 Trie 最容易理解的地方，是每条边对应一个字符，从根出发的一条路径就对应一个前缀。插入时顺着字符往下走，没有对应的孩子就创建；查询时沿同样的路径查找，最后再检查节点是否成词。

我需要分清的是，路径存在不代表这个单词插入过。只插入 `apple` 时，`app` 的路径也存在，但 `app` 对应节点的 `flag` 仍然是 `0`。只有另外插入过 `app`，它才算一个完整单词。

在[普通字典树实现](../../source/improved_part/16.string/2.multiple_mode_matching_algorithm/3.Trie.cpp)里，我还补上了按字典序输出单词的 DFS：

```cpp
void dfs_output(Node* root,int k,char* buffer){
    if(root == nullptr) return;
    if(root->flag){
        buffer[k] = '\0';
        printf("%s\n",buffer);
    }
    for(int i=0;i<BASE;i++){
        if(root->next[i] == nullptr) continue;
        buffer[k] = 'a' + i;
        dfs_output(root->next[i],k+1,buffer);
    }
}
```

这里的 `k` 是当前路径的长度，`buffer` 保存路径上的字符。走到成词节点时，在 `buffer[k]` 放上字符串结束符，就能输出当前单词；随后继续向下搜索，因为一个单词也可能是另一个单词的前缀。

孩子按照 `a` 到 `z` 的顺序访问，成词时先输出当前路径，再访问更长的单词，得到的就是字典序。递归返回时也不需要额外清空缓冲区，下一条分支会覆盖对应位置，输出时的结束符会截断后面残留的内容。这部分能和我已经学过的树遍历、回溯联系起来，读起来比较顺。

普通 Trie 对长度为 `L` 的单词做插入和查询，时间都是 `O(L)`。

## 可持久化字典树：新版本只复制本次插入的路径

普通字典树只维护当前状态，可持久化字典树还要保留每次插入后的历史状态。在[这份实现](../../source/improved_part/16.string/2.multiple_mode_matching_algorithm/4.sustainable_Trie,.cpp)里，`rt[i]` 保存第 `i` 个版本的根节点编号，也就是前 `i` 次插入后的状态。

我一开始最难理解的地方，是不同版本并没有各自保存一棵完全独立的树。它们会共享没有变化的子树，只有本次插入经过的路径需要重新创建节点。要修改的节点属于新版本，已经被旧版本使用的节点不能再改。

例如先插入 `abc`，再插入 `a`。第二个版本里的 `a` 要增加一次计数，第一个版本中的 `a` 仍然没有作为完整单词出现过，所以两个版本必须使用不同的 `a` 节点。但后面的 `b → c` 没有变化，可以继续共享。

核心插入代码如下：

```cpp
void insert(int o,int lst,const char* s){
    for(int i=0;s[i];i++){
        int index = s[i] - 'a';
        ch[o][index] = ++ch_cnt;
        for(int j=0;j<26;j++){
            if(ch[o][j]) continue;
            ch[o][j] = ch[lst][j];
        }
        o = ch[o][index];
        lst = ch[lst][index];
        val[o] = val[lst];
    }
    //终点节点也要继承旧版本的子树，避免插入前缀时丢失已有单词
    for(int j=0;j<26;j++){
        ch[o][j] = ch[lst][j];
    }
    val[o] += 1;
}
```

我现在需要对着新旧节点的关系，才能顺着这段代码读下去：

1. `o` 指向正在构造的新版本节点，`lst` 指向旧版本中相同前缀对应的节点。它们沿着同一个单词一起向下走。
2. 当前字符对应的孩子重新分配节点，其他分支复制旧节点的孩子编号，因此这些分支仍然指向原来的子树。这里 `o` 是新建节点，孩子原本全零，只有刚分配的那条边非零，所以可以用 `if(ch[o][j]) continue` 跳过它。
3. 向下移动后，用 `val[o] = val[lst]` 继承旧计数。中间节点可能已经是某个较短单词的终点，这些计数也需要保留。
4. 循环结束后，终点节点还要复制旧节点的全部孩子，再把当前完整单词的计数增加一次。

终点的孩子复制，是今天检查实现时最值得记住的一处。处理最后一个字符后，循环刚好移动到终点，还没有处理它的孩子。如果漏掉最后这次复制，先插入 `abc`、再插入 `a`，新版本的 `a` 虽然能查到，后面的 `b → c` 却会断掉，连已经存在的 `abc` 都丢了。

这个例子让我能具体看到，复制一个节点时需要保留什么。计数和孩子关系都属于旧状态，只复制计数还不够。

每次插入长度为 `L` 的单词，会创建一个新根和 `L` 个字符节点。每一层还要复制 26 个孩子编号，固定小写字母表下，插入时间仍可记为 `O(L)`。节点池的容量也要把每次新建的根算进去。

## 区间查询：把两个版本的累计次数相减

这份实现里的 `val` 记录完整单词的累计出现次数。`find_once(i,s)` 从 `rt[i]` 出发，返回前 `i` 次插入中单词 `s` 出现了多少次。因此区间 `[a,b]` 的查询可以直接相减：

```cpp
int find(int a,int b,const char* s){
    //使用前缀和的思想，首先统计到b版本，a-1版本之前一共被插入了多少次最后直接相减就是从a版本到b版本之间一共被插入了多少次
    int x1 = find_once(b,s);
    int x2 = find_once(a-1,s);
    return x1 - x2;
}
```

假设依次插入 `abc`、`a`、`abd`、`abc`，第四个版本中 `abc` 的累计次数为 `2`，第一个版本中为 `1`。查询第 2 到第 4 次插入，就用 `2 - 1`，得到这段区间内出现过一次。

这里减去的是第 `a-1` 个版本，排除第 `a` 次之前的插入。每次查询沿字符串走两遍，时间仍然是 `O(L)`。

前缀和的公式本身不难，真正让我费劲的还是前面的版本构造：为什么这些子树可以共享，哪些节点必须复制，两个下标移动以后分别代表什么。我现在能跟着具体例子解释一部分，离自己熟练写出来还有很大距离。

今天修正实现后，前缀插入、重复插入和历史版本的区间查询都核对过，也做了随机对照和最大节点容量的测试。代码行为有了验证，我对这套结构的理解还需要以后继续消化。
