## 前缀和：把重复查询提前算掉

一维前缀和最直接。令 `prefix[i]` 表示前 `i` 个数的和，那么区间 `[l,r]` 的答案就是 `prefix[r]-prefix[l-1]`。多留出的 `prefix[0]=0` 很重要，它让左端点等于 `1` 时仍然能使用同一个公式，不需要另外分类。

二维前缀和是在两个方向上做同样的积累。构造 `prefix[i][j]` 时，上方和左侧的矩形都要加进来，而左上角被计算了两次，所以还要减掉一次：

```cpp
prefix[j][k] = number
            + prefix[j-1][k]
            + prefix[j][k-1]
            - prefix[j-1][k-1];
```

查询一个矩形时再把这个容斥过程反过来。以前我容易把四项的位置记混，今天重新画了一遍矩形后才发现，与其死记正负号，不如一直盯着“哪些区域被重复计算”。行号和列号前面都补一层 `0`，也能把贴着边界的矩形统一处理。

今天做的题不只是在套区间和公式。P3131 要观察两个前缀和模 `7` 后余数相同的位置；CF 816B 则连续做了两层前缀：先用差分统计每个温度被多少份配方覆盖，再把满足要求的温度记成 `0/1`，对它们继续做前缀和。第二层算到 `200000`，查询右端点落在最大温度上时才能直接取值。

## 差分：只记录变化发生的位置

差分数组和前缀和正好是相反的方向。原数组通过相邻两项作差得到差分；对差分重新求前缀和，又能还原原数组。如果要给闭区间 `[l,r]` 统一增加一个值，只需要修改 `diff[l]` 和 `diff[r+1]`，中间每个位置都不用单独访问。

“借教室”让我对这个关系更清楚了一些。检查前 `x` 份订单时，我先把每天可用的教室数转成差分，再把每份订单对一段日期的消耗落在两个端点上：

```cpp
for(long long i=1;i<=x;i++){
    long long day = orders[i].d;
    long long start = orders[i].s;
    long long end = orders[i].t;
    diff[start] -= day;
    diff[end+1] += day;
}
```

之后求一次前缀和，就能得到每天剩余的教室数。只要有一天小于 `0`，说明前 `x` 份订单不能全部满足。再利用“能满足的订单前缀一定连续”这个单调性二分第一份失败订单，差分和二分就接到了一起。

最高的奶牛、校门外的树也用了同一套模型。题目的说法不同，真正落到数组上，都是一段区间统一增减。今天做完这些练习后，我对 `right+1` 的理解也不再只是“数组开大一点就不会越界”：它表示影响从这个位置开始结束，因此差分数组本来就应该为这个边界多留一个位置。

## 补上昨天的蓝桥杯 E

昨天停在蓝桥杯 E 时，我知道它和连续区间、整数和有关，但没有继续推出答案范围。今天补完以后，最重要的结论其实只有两个：目标为 `0` 时答案为 `0`；只要目标可行，最多使用两段连续区间。

先把目标 `W` 除以常数 `C`，记为 `S`。如果 `W` 不能被 `C` 整除，或者 `S` 超过 `1+2+...+n`，答案就是 `-1`。否则，取最小的 `r` 使三角数 `1+2+...+r` 不小于 `S`，再令差值为 `d`。因为 `d<r`，当 `d>0` 时，从 `[1,r]` 中去掉数字 `d`，剩下的部分最多只会分裂成 `[1,d-1]` 和 `[d+1,r]` 两段；`d=0` 时则一整段就够了。

于是代码只需要再检查答案能不能从 `2` 降到 `1`。所有数都是正数，可以用滑动窗口寻找和恰好为目标的连续区间：右端点逐步向右移动，区间和超过目标时再收缩左端点。整个检查只需要线性扫描一次。

这道题和昨天那道 CF B 给我的感觉很像：没有明确的数据结构考点，代码也不长，真正挡住我的是能不能从数字中看出那个范围很小的答案。只要抓住“最多为 `2`”以及答案为 `0` 的条件，后面就顺了。

### C：`k` 很大，但最优得分只需要看一轮

C 是今天最有意思的一题。题目给出的轮数 `k` 可以非常大，看起来像是要模拟每一轮土豆的位置变化，甚至分析两个队伍长期博弈。但真正的突破口是：在双方都采取最优策略时，进行多少轮得到的最终得分，与只进行一轮是等价的。

关键不在于每颗土豆最终停在哪个具体位置，而在于开局时每颗土豆的下一位是否为空。若下一位已经有土豆，这颗土豆第一轮根本不能移动；若下一位为空，它就拥有一次改变最终持有者阵营的机会。之后的移动不会再创造额外的净收益，双方也都不会主动接受让自己得分变差的交换，因此最终只需要按照初始局面判断一次。

我的实现最后只扫描了一遍字符串，`k` 甚至不需要参与计算：

```cpp
if(i%2==0){
    if(s[next] == '0') red_score++;
}else if(i%2 == 1){
    if(s[next] == '1') red_score++;
}
```

这里偶数下标对应编号为奇数的红队成员。红队土豆后面为空时，可以把土豆交给蓝队，为红队增加一分；蓝队成员手里有土豆且后面仍有土豆时，这颗土豆无法转移给红队，最后同样算作红队得分。其余土豆则计入蓝队得分。

这道题最难的地方不是代码，而是相信一个看似包含 `k` 轮动态博弈的问题，最后真的可以压缩成对初始字符串的一次扫描。能否察觉这种不变量，确实很依赖数学直觉。
