## 8 月 7 日：一场只做出 A 的 Div. 2

昨天继续推进回溯算法，也参加了 Codeforces Educational Round 193（Div. 2）。比赛结果不算好，最后只做出了一道题，分数涨到了 381。这个分数当然谈不上理想，但比结果更让我在意的是，比赛中的两道题都很难归进某个熟悉的数据结构或算法模板。

以前做章节练习时，题目通常已经替我缩小了思考范围。学二分时找单调性，学单调栈时观察谁在什么时候出栈，学回溯时画状态树。CF 不会给这种提示。A、B 更依赖数学直觉和对规律的敏感程度，尤其是 B，第一眼看上去条件很多，数组合并之后的变化也有些乱，我在比赛里没有把它拆开。

赛后重新看 B，我先把连续相同的数字压成 `(数值, 出现次数)`，原数组的细节一下少了很多。后面的判断最终只剩下几类局部结构：基础答案是合并后的段数 `m`，满足某些重复段关系时才会增加到 `m+1` 或 `m+2`。

```cpp
int f(const vector<PII>& arr) {
    int m = static_cast<int>(arr.size());

    //m+2的情况
    for (int i = 0; i<m-1; i++) {
        if (arr[i].second >= 2 && arr[i + 1].second >= 2) {
            return m + 2;
        }
    }

    //m+1的情况
    // ... 省略 left 与 right 的边界判断

    return m;
}
```

这道题真正难的地方不在实现，而在于如何从原数组走到“段”这一层，再从合并后的结构继续拆情况。代码写出来只有几段判断，前面的观察过程却不能省。现在我已经把 B 弄懂了，但离比赛中稳定做出这种题还有距离。它没有明确模板可套，只能依靠看过的题、写过的代码和一次次赛后补题，慢慢积累对结构的感觉。

## 回溯最后七题：题型结束了，抽象感还在

今天的主线任务是回溯算法收尾。我连续做完了最后七道题：迷宫路径、吃奶酪、单词接龙、字串变换、自然数拆分、单词方阵，以及把每科习题分给左右脑的搜索问题。题面差别很大，但不断重复出现的骨架还是那几个部分：当前状态是什么，这一层能做哪些选择，什么时候停止，哪些状态可以提前剪掉，以及递归回来后要不要撤销选择。

比较直观的题里，我已经能主动写出“选择—递归—恢复”。例如自然数拆分用下一项的最小值保证序列非递减，左右脑分配则把每道题看成两个分支。字串变换又多了一层深度限制，需要用迭代加深控制十步边界，并记录同一字符串曾经以多少步到达。这些题让我看到，回溯不是某一份固定模板，真正需要设计的是状态。

最让我没底的仍然是状态掩码和位运算。吃奶酪时，`t` 表示还没有访问的点，`k` 只是这一层枚举剩余二进制位的临时变量。只有把这两个含义分开，才能理解为什么下一状态必须从完整状态 `t` 中删除当前位：

```cpp
void dfs(int t,int pos,double s){
    if(t == 0){
        if(s < ans) ans = s;
        return;
    }
    for(int k= t;k!=0;k -= (k&-k)){
        int bit = k&-k;
        int cur_index = index[bit];//当前枚举的点的编号
        int next_t = bit^t;//下一个状态码
        double new_dis = dis[pos][cur_index] + s;
        if(new_dis>=ans) continue;
        if(new_dis >= dp[next_t][cur_index]) continue;
        dp[next_t][cur_index] = new_dis;
        dfs(next_t,cur_index,new_dis);
    }
}
```

`bit = k & -k` 取出当前最低位，`next_t = t ^ bit` 删除真正选择的点。写到这里时，我能逐句解释代码，却还没有形成看到状态压缩就自然想到位运算的直觉。这也是做完十一道题后心里依然没底的原因：普通回溯的路径数组、访问标记和恢复操作已经比较具体，掩码却把一整组布尔状态塞进了一个整数，每次异或、左移和 lowbit 都同时改变了很多信息。代码变短了，脑子里要维护的东西反而更多。

## 两天真正连起来的地方

CF B 和回溯看似没什么关系，一个偏规律，一个属于搜索，但这两天做下来，我感受到的困难很接近。CF B 要先把原数组压成段，再对段之间的关系分类；回溯要先决定哪些信息足以描述一个状态，再决定如何转移。题目最难的部分往往发生在代码之前。

这也解释了为什么只完成章节题目还不够。模板题能让我练熟 DFS 的外形，比赛和综合题则会追问：为什么是这个状态，为什么只需要这些分支，为什么这一步可以剪掉。要稳定处理没有明确考点的题，我还需要更多代码积累，也需要在做完以后回头追问建模过程，而不是只确认答案通过。

明天我先不往前推主线。回溯的十一道题要重新过一遍，我准备给每道题只写五项：状态、选择、终点、恢复和剪枝，再把八皇后与吃奶酪的掩码拿小数据手推。蓝桥杯 E 也留到这轮复习之后看题解。现在最需要的不是再开一个新章节，而是让这十一棵状态树在脑子里真正长出区别。
